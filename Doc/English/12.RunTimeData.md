# Runtime Data System Guide

## 📖 Introduction

`RuntimeDataManager` is the UFlowFramework module used to manage game runtime data. It is suitable for data that only needs to exist during runtime, such as bag items, temporary character state, and in-level statistics.

The current runtime data system is based on `IRuntimeData` data containers and `IRuntimeDataHandler<T>` data handlers. Data containers are responsible for storing data, while data handlers encapsulate initialization, add, remove, query, and listener logic for a specific data type.

When the game starts, the system automatically finds instantiable `IRuntimeDataHandler<T>` implementations, creates handler instances, and calls `InitData()`. Therefore, normal gameplay code usually only needs to access data through `RuntimeDataManager.instance` or the corresponding utility class.

## ⚙️ Features

1. **Runtime data storage**
   - Supports single-value container `RuntimeData<T>`.
   - Supports dictionary container `RuntimeDataDic<K, T>`.
   - Supports normal storage and `doNotClear` storage.

2. **Unified data access entry points**
   - Get data through `GetData<T>(int key)`.
   - Add or modify data through `AddData<T>(T data)`.
   - Remove data through `RemoveData<T>(T data)`.
   - Listen for data changes through `AddChangeListener<T>()` / `RemoveChangeListener<T>()`.

3. **Data handler extension**
   - Supports encapsulating business logic for different data types through `IRuntimeDataHandler<T>`.
   - Instantiable handlers are automatically reflected and created when the game starts.
   - The built-in `BagDataHandler` is provided as an example.

4. **Data change listening**
   - `OnRuntimeDataChange<T>` is triggered when data is replaced by `ReplaceData()`.
   - The callback parameters contain both old data and new data.

5. **Runtime lifecycle management**
   - Initializes handlers and runtime data on `onStartGame`.
   - Clears normal runtime storage on `onResetGame`.
   - `doNotClear` storage is not cleared by game reset.

## 📂 File Structure

- `RuntimeDataManager.cs`  
  Main entry point of the runtime data system. Defines data containers, storage areas, lifecycle, and common data access APIs.

- `IRuntimeData.cs`  
  Base interface required by all runtime data containers. Provides `dataType` to identify the data type stored by the container.

- `IRuntimeDataHandler.cs`  
  Defines runtime data handler interfaces and the common base class `RuntimeDataHandlerBase<T, KT>`.

- `BagDataHandler.cs`  
  Bag runtime data example. Defines the `RItem` data structure and the `BagDataHandler` handler.

- `BagUtils.cs`  
  Static access utility for bag data. Wraps add, remove, count query, and listener APIs.

## 🧩 Core Concepts

### 1. Data Change Delegate

```csharp
public delegate void OnRuntimeDataChange<T>(T oldData, T newData);
```

When data is replaced, listeners receive both old data and new data:

- `oldData`: data before replacement.
- `newData`: data after replacement.
- If the key did not exist in a dictionary container, `oldData` is `default(T)`.
- `RuntimeDataDic<K, T>.Remove(K key)` only removes data and does not trigger this delegate.

### 2. Single-Value Container `RuntimeData<T>`

`RuntimeData<T>` stores one value of type `T`.

```csharp
public class RuntimeData<T> : IRuntimeData
    where T : struct
```

| Method / Property | Description |
|---|---|
| `RuntimeData(T data)` | Creates the container with initial data. |
| `dataType` | Returns the data type stored by the container. |
| `GetData()` | Gets the internal data value. |
| `ReplaceData(T newData)` | Replaces the internal data and triggers change listeners. |
| `AddListener(...)` | Adds a change listener. |
| `RemoveListener(...)` | Removes a change listener. |

### 3. Dictionary Container `RuntimeDataDic<K, T>`

`RuntimeDataDic<K, T>` stores multiple values of type `T` by key.

```csharp
public class RuntimeDataDic<K, T> : IRuntimeData, IEnumerable<T>
    where T : struct
```

| Method / Property | Description |
|---|---|
| `RuntimeDataDic()` | Creates an empty dictionary container. |
| `RuntimeDataDic(IEnumerable<KeyValuePair<K, T>> initDatas)` | Creates a container from initial key-value pairs. |
| `dataType` | Returns the value type stored by the container. |
| `GetData(K key)` | Gets data by key. Returns `default(T)` when the key does not exist. |
| `ReplaceData(K key, T newData)` | Adds or replaces data for the specified key and triggers change listeners. |
| `Remove(K key)` | Removes data by key and does not trigger change listeners. |
| `AddListener(...)` | Adds a change listener. |
| `RemoveListener(...)` | Removes a change listener. |
| `Clear()` | Clears the dictionary. |

### 4. Data Handler `IRuntimeDataHandler<T>`

`IRuntimeDataHandler<T>` centralizes business rules for a specific data type.

```csharp
public interface IRuntimeDataHandler<T> : IRuntimeDataHandler
    where T : struct
{
    void AddData(T rData);
    void RemoveData(T rData);
    int GetKey(T rData);
    T GetData(int key);
    void AddListener(OnRuntimeDataChange<T> action);
    void RemoveListener(OnRuntimeDataChange<T> action);
    List<T> GetAllData();
}
```

Use it in these cases:

- Adding data is not a simple overwrite and requires accumulation, subtraction, merging, or validation.
- The underlying container type should be hidden, exposing only unified access methods.
- A data type should be initialized automatically when the game starts.

## 🛠️ Usage

### 🚀 1. Initialization Flow

`RuntimeDataManager` implements `IEventModule` and `IOnGameStartModule`. Under normal conditions, the module system completes initialization automatically.

The initialization flow is:

1. `OnInit()` initializes `_storage` and `_doNotClearStorage`.
2. `RegisterEvent()` registers `onStartGame` and `onResetGame` events.
3. After `onStartGame` is triggered:
   - Creates `_handlers`;
   - Reflects all instantiable `IRuntimeDataHandler<T>` implementations;
   - Creates handler instances;
   - Calls `InitData()` for each handler;
   - Calls the partial method `InitRuntimeData()`.
4. After `onResetGame` is triggered, normal `_storage` is cleared.

### 🔧 2. Extend Initialization with `InitRuntimeData`

`RuntimeDataManager` provides a partial extension point:

```csharp
partial void InitRuntimeData();
```

If you need to initialize data that does not depend on `IRuntimeDataHandler<T>`, create a `RuntimeDataManager_InitRuntimeData.cs` file:

```csharp
namespace PowerCellStudio
{
    public sealed partial class RuntimeDataManager
    {
        partial void InitRuntimeData()
        {
            var score = new RuntimeData<PlayerScore>(new PlayerScore { value = 0 });
            AddRuntimeStorage(score);
        }
    }

    public struct PlayerScore
    {
        public int value;
    }
}
```

### 📦 3. Add a Runtime Data Container

You can add a runtime data container directly:

```csharp
var score = new RuntimeDataManager.RuntimeData<PlayerScore>(new PlayerScore { value = 100 });
RuntimeDataManager.instance.AddRuntimeStorage(score);
```

If the data should not be cleared on game reset, pass `doNotClear`:

```csharp
RuntimeDataManager.instance.AddRuntimeStorage(score, true);
```

> `doNotClear` only means the data will not be cleared by `onResetGame`. It is still in-memory data and is not the same as a disk save.

### 🔍 4. Get a Runtime Data Container

```csharp
var scoreStorage = RuntimeDataManager.instance.GetRuntimeStorage<RuntimeDataManager.RuntimeData<PlayerScore>>();
var score = scoreStorage.GetData();
```

### 📊 5. Use Common Data APIs

If the data type has a corresponding `IRuntimeDataHandler<T>`, use the common APIs to access it:

```csharp
// Add or modify data
RuntimeDataManager.instance.AddData(new RItem { id = 1, num = 10 });

// Get data
RItem item = RuntimeDataManager.instance.GetData<RItem>(1);

// Remove data
RuntimeDataManager.instance.RemoveData(new RItem { id = 1, num = 5 });

// Listen for changes
RuntimeDataManager.instance.AddChangeListener<RItem>((oldItem, newItem) =>
{
    ModuleLogger.Log<RuntimeDataManager>($"item = {newItem.id}, num = {newItem.num}");
});
```

`GetData<T>(int key)`, `AddData<T>()`, and `RemoveData<T>()` are processed by the corresponding `IRuntimeDataHandler<T>` first.

### 🎒 6. Use Bag Utility `BagUtils`

The project includes a built-in runtime bag data example.

`RItem` is defined as follows:

```csharp
[Serializable]
public struct RItem
{
    public int id;
    public int num;

    public RItem Clone()
    {
        return new RItem
        {
            id = this.id,
            num = this.num
        };
    }
}
```

`BagDataHandler` automatically initializes the bag container when the game starts. Gameplay code can directly use `BagUtils`.

#### Add Items

```csharp
BagUtils.AddItem(new RItem { id = 1, num = 10 });
BagUtils.AddItem(2, 5);
```

You can also add multiple items at once:

```csharp
BagUtils.AddItem(
    new RItem { id = 1, num = 10 },
    new RItem { id = 2, num = 5 },
    new RItem { id = 3, num = 1 }
);
```

#### Remove Items

```csharp
BagUtils.RemoveItem(new RItem { id = 1, num = 3 });
BagUtils.RemoveItem(2, 1);
```

`BagDataHandler` subtracts item count by `id`, clamps the minimum count to `0`, and removes the item from the dictionary when the count becomes `0`.

#### Get Item Count

```csharp
int itemNum = BagUtils.GetItemNum(1);
```

If the bag does not contain this id, the underlying query returns `default(RItem)`, so the count is `0`.

#### Check Item Sufficiency

```csharp
bool enough = BagUtils.IsItemEnough(1, 10);

bool allEnough = BagUtils.IsItemEnough(
    new RItem { id = 1, num = 10 },
    new RItem { id = 2, num = 3 }
);
```

#### Listen for Bag Changes

```csharp
private void OnEnable()
{
    BagUtils.AddBagListener(OnBagItemChanged);
}

private void OnDisable()
{
    BagUtils.RemoveBagListener(OnBagItemChanged);
}

private void OnBagItemChanged(RItem oldItem, RItem newItem)
{
    ModuleLogger.Log<BagUtils>($"item id = {newItem.id}, old = {oldItem.num}, new = {newItem.num}");
}
```

### 🔧 7. Extend Custom Runtime Data

Custom runtime data usually requires:

1. Define a `struct`.
2. Define a handler that implements `IRuntimeDataHandler<T>`.
3. Create and register the corresponding container in `InitData()`.
4. Implement business rules in `AddData()`, `RemoveData()`, and `GetData()`.

The following example uses currency data:

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

namespace PowerCellStudio
{
    [Serializable]
    public struct RCurrency
    {
        public int id;
        public int amount;
    }

    public sealed class CurrencyDataHandler : IRuntimeDataHandler<RCurrency>
    {
        private sealed class CurrencyData : RuntimeDataManager.RuntimeDataDic<int, RCurrency> { }

        public void InitData()
        {
            if (RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>() != null) return;
            RuntimeDataManager.instance.AddRuntimeStorage(new CurrencyData());
        }

        public void AddData(RCurrency data)
        {
            var storage = RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>();
            if (storage == null) return;

            var current = storage.GetData(data.id);
            data.amount += current.amount;
            storage.ReplaceData(data.id, data);
        }

        public void RemoveData(RCurrency data)
        {
            var storage = RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>();
            if (storage == null) return;

            var current = storage.GetData(data.id);
            current.amount = Math.Max(0, current.amount - data.amount);
            storage.ReplaceData(data.id, current);
        }

        public int GetKey(RCurrency data)
        {
            return data.id;
        }

        public RCurrency GetData(int key)
        {
            var storage = RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>();
            return storage == null ? default : storage.GetData(key);
        }

        public void AddListener(OnRuntimeDataChange<RCurrency> action)
        {
            RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>()?.AddListener(action);
        }

        public void RemoveListener(OnRuntimeDataChange<RCurrency> action)
        {
            RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>()?.RemoveListener(action);
        }

        public List<RCurrency> GetAllData()
        {
            var storage = RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>();
            return storage?.ToList() ?? new List<RCurrency>();
        }
    }
}
```

After integration, use the common APIs:

```csharp
RuntimeDataManager.instance.AddData(new RCurrency { id = 1001, amount = 50 });

var gold = RuntimeDataManager.instance.GetData<RCurrency>(1001);

RuntimeDataManager.instance.AddChangeListener<RCurrency>((oldData, newData) =>
{
    ModuleLogger.Log<RuntimeDataManager>($"currency = {newData.id}, amount = {newData.amount}");
});
```

## ⚠️ Notes

1. `RuntimeData<T>` and `RuntimeDataDic<K, T>` require `T` to be a `struct`.
2. Data types used by `IRuntimeDataHandler<T>` are also recommended to be `struct`.
3. `RItem` is a `struct`, so it cannot be checked with `null`; missing data usually returns `default(T)`.
4. `RuntimeDataDic<K, T>.Remove(K key)` does not trigger data change listeners. Only `ReplaceData()` triggers listeners.
5. After using `AddChangeListener()` or `BagUtils.AddBagListener()`, call the corresponding remove method when the owner is destroyed or disabled.
6. Normal `_storage` is cleared on `onResetGame`, while `_doNotClearStorage` is not cleared by `ClearRuntimeStorage()`.
7. `doNotClear` is not persistent save data. It is only in-memory data that is not cleared by game reset.
8. The current implementation does not use locks. Access it from the Unity main thread.
9. Without a handler, the system tries to find a container by element type. Dictionary containers use `data.GetHashCode()` as the key for add and remove operations by default, which is only suitable for simple cases.
10. For complex business logic, explicitly implement `IRuntimeDataHandler<T>`.

## 📦 Dependencies

- UFlowFramework module system.
- `EventManager` game start and game reset events.
- `ReflectionUtils` reflection utility, used to find and create runtime data handlers.

## ❓ FAQ

1. **Cannot get runtime data**  
   Check whether the corresponding handler is instantiable, whether `onStartGame` has been triggered, and whether `InitData()` successfully created and registered the container.
   
2. **Data is lost after game reset**  
   Normal `_storage` is cleared on `onResetGame`. If data should remain after reset, register it into `doNotClear` storage through `AddRuntimeStorage(data, true)`.

3. **Bag item count is not as expected**  
   `BagDataHandler.AddData()` accumulates item count for the same id, while `RemoveData()` subtracts count and clamps the minimum value to `0`. Check whether the input `id` and `num` are correct.

4. **Calling `AddData<T>()` directly has no effect**  
   Check whether the corresponding container or handler has been registered. Without a handler, the system only tries to find an existing container and does not create a new one automatically.
