# Configuration Sheet Tool Guide

## 📖 Introduction

The configuration system has now been upgraded to a DataChunk-based binary loading pipeline.

The tool generates the following from Excel sheets:

- C# data classes and collection classes for each configuration table
- `ConfigManager` accessors
- one chunked data file per table: `ConfNameData.bytes`
- one index file per table: `ConfNameIndex.bytes`

At runtime, configuration tables are no longer expected to be loaded entirely into memory up front. Instead, they are accessed through `ChunkDataQueryer<TKey, TData>`, which resolves chunk offsets by key and loads data on demand.

## ⚙️ Features

1. **Configuration Sheet Generation**
   - Generate configuration data from Excel files.
   - Supports primitive types, arrays, asset references, and localization reference types.
   - Extendable through custom `TypeRef` implementations.

2. **DataChunk Binary Output**
   - Each configuration table is exported as `Data.bytes + Index.bytes`.
   - Uses chunk indexes for fast key-based lookup and on-demand data loading.
   - Runtime access has been standardized around `Get`, `GetByKey`, `GetAll`, and `Find`.

3. **Synchronous and Asynchronous Loading**
   - Supports synchronous `Prepare()` and asynchronous `PrepareAsync()` collection loading.
   - Supports loading multiple configuration collections together through `ConfigGroup`.
   - On first launch, config binaries can be copied from packaged resources into the persistent data directory.

4. **Localization and Asset References**
   - Supports `LocalizationStringRef`, `LocalizationAssetRef`, and similar types.
   - Supports asset reference fields such as `AudioRef`, `SpriteRef`, and `GameObjectRef`.
   - Supports exporting localization CSV data.

5. **Automatic Code Generation**
   - Generates configuration data classes, collection classes, creators, and `ConfigManager` accessors automatically.

## 📂 File Structure

- `ConfigSettingWindow.cs`
  Provides the settings window for Excel paths, generated script paths, and exported configuration file paths.

- `ConfigWriter.cs`
  Generates the C# code for configuration tables.

- `WriteConfCreatorHandler.cs`
  Generates the export logic for configuration assets. It now writes DataChunk files through `ChunkMaker.StreamWriteSync(...)`.

- `ConfBase.cs` / `ConfBaseCollections.cs`
  Define base configuration classes and collection-level loading/query APIs.

- `ConfigGroup.cs`
  Manages asynchronous loading state for multiple configuration collections.

- `ConfigManager.cs`
  Provides the unified runtime entry point and handles first-time config copy initialization.

- `AssetRef` folder
  Contains supported extensible field types such as `AudioRef`, `SpriteRef`, and `LocalizationStringRef`.

## 🛠️ Usage

### 📁 1. Configure Paths

Open the Unity menu `Tools > Config > Config Setting Window` and configure the following paths:

![Open Config Setting Window](../img/ConfigToolMenuItem.png "Magic Gardens")

- **Excel Path**: Folder containing the Excel configuration sheets.
- **Script Path**: Output path for generated C# scripts, relative to `Assets`.
- **Asset Path**: Output path for generated binary config files, relative to `Assets`.

### 📜 2. Generate Configuration Tables

![Config Setting Window](../img/ConfigSettingWindow.png "Magic Gardens")

In the `Config Setting Window`:

- **Save Settings**: Save the current settings.
- **Create Cs Files**: Generate the C# classes and manager code from Excel files.
- **Create Config Assets**: Export configuration binaries.
- **Delete Config Assets**: Delete generated configuration binaries.

Each configuration table typically generates two files:

- `ConfNameData.bytes`: chunked data file
- `ConfNameIndex.bytes`: chunk index file

### 🌐 3. Localization Support

- **Create Localization CSV**: Extract localized strings and assets from configuration tables and export them as CSV files.

### 🚀 4. Initialize Runtime Config Files

At runtime, you can call `ConfigManager.Init(...)` first. The current logic copies packaged config binaries into `Application.persistentDataPath/ConfigAsset/` on the first launch, then later collections load from the persistent directory.

```csharp
IEnumerator Start()
{
    yield return ConfigManager.instance.Init(status =>
    {
        Debug.Log($"Config init status: {status}");
    });
}
```

### 📥 5. Load Multiple Configurations

Use `ConfigGroup` to load multiple config collections together:

```csharp
private ConfigGroup _configGroup;

IEnumerator LoadConfig()
{
    _configGroup = new ConfigGroup(
        ConfigManager.instance.guidanceConf,
        ConfigManager.instance.rolePropConf);

    _configGroup.onLoadCompleted += OnInitConfLoadCompleted;
    yield return _configGroup.LoadAll();
}

private void OnInitConfLoadCompleted(AssetLoadStatus status)
{
    if (status == AssetLoadStatus.Loaded)
    {
        Debug.Log("Config loaded successfully");
        return;
    }

    Debug.LogError("Config loading failed");
    string[] failed = _configGroup.failLoadConfigs;
    foreach (var configName in failed)
    {
        Debug.LogError($"{configName} failed to load");
    }
}

void ReleaseConfig()
{
    _configGroup?.ReleaseAll();
}
```

### 📦 6. Load a Single Table Synchronously

If you only need one table, you can call `Prepare()` directly on the generated collection:

```csharp
ConfigManager.instance.rolePropConf.Prepare();

RolePropConf roleConfig = ConfigManager.instance.rolePropConf.Get(roleId);

ConfigManager.instance.rolePropConf.Release(false);
```

### 📊 7. Access Configuration Data

The recommended access patterns are now:

```csharp
// Get a single record by key
RolePropConf roleConfig = ConfigManager.instance.rolePropConf.Get(roleId);
Debug.Log($"Role Name: {roleConfig.name}");

// Filter by key predicate
foreach (var conf in ConfigManager.instance.rolePropConf.GetByKey(id => id > 1000))
{
    Debug.Log($"Matched By Key: {conf.name}");
}

// Enumerate the full table
foreach (var conf in ConfigManager.instance.rolePropConf.GetAll())
{
    Debug.Log($"All: {conf.name}");
}

// Filter by data predicate
foreach (var conf in ConfigManager.instance.rolePropConf.Find(o => o.atk > 10 && o.atk < 20))
{
    Debug.Log($"Matched By Predicate: {conf.name}");
}
```

Interfaces such as `rawData` from the old full-table caching workflow are no longer the primary recommended access pattern in the current DataChunk design.

### 🔧 8. Extend Custom Types

Custom field types must inherit from `TypeRef` and provide at least:

- `isMatch(string lowerRawType)`
- `TypeName()`
- static `Parse(...)`
- static `WriteItemData(...)`
- static `ReadItemData(...)`

Example: `TimeDateRef`

```csharp
using System;
using System.IO;
using System.Text;

[Serializable]
public sealed class TimeDateRef : TypeRef
{
    public override bool isMatch(string lowerRawType)
    {
        return lowerRawType.Equals("timedate");
    }

    public override string TypeName()
    {
        return "TimeDate";
    }

    public static TimeDate Parse(string stringValue, string confName, int rowIndex, int colIndex)
    {
        if (string.IsNullOrEmpty(stringValue))
            return default;

        string[] splitString = stringValue.Split('-');
        int year = int.Parse(splitString[0]);
        int month = int.Parse(splitString[1]);
        int day = int.Parse(splitString[2]);
        return new TimeDate(year, month, day);
    }

    public static void WriteItemData(TimeDate item, BinaryWriter writer, Encoding encoding)
    {
        writer.Write(item.Year);
        writer.Write(item.Month);
        writer.Write(item.Day);
    }

    public static TimeDate ReadItemData(BinaryReader reader, Encoding encoding)
    {
        int year = reader.ReadInt32();
        int month = reader.ReadInt32();
        int day = reader.ReadInt32();
        return new TimeDate(year, month, day);
    }
}
```

Then use `TimeDate` as the field type in Excel and provide data in the expected format.

### 🔧 9. Read Configuration Tables in the Editor

```csharp
var configInstance = new ConfigManager();

var guidanceConfig = configInstance.guidanceConf.Get(1);

configInstance.guidanceConf.Release(false);
```

## 📑 Excel File Format

1. **Row 1**: Field descriptions/comments.
2. **Row 2**: Field names. Use `:key` to mark primary keys, and multiple keys are supported.
3. **Row 3**: Field types such as `int`, `string`, `float[]`, `LocalizationStringRef`, and so on.
4. **Rows 4+**: Data rows.

Example:

| Description | id | Name | Values |
|---|---|---|---|
| Field Name | id:key | name | value |
| Field Type | int | string | float[] |
| Data | 1 | Hero | 10,20,30 |
| Data | 2 | Monster | 5,15,25 |

## ⚠️ Notes

1. Excel files must be saved as `.xlsx`.
2. Primary keys must be marked with `:key`, and multiple keys are supported.
3. The current config pipeline exports DataChunk binary files rather than the old multi-format config asset workflow.
4. Use `LocalizationStringRef` or `LocalizationAssetRef` for localized fields.
5. Duplicate field names are allowed only when the field types are identical. They will be generated as `List<T>` fields.
6. Custom `TypeRef` implementations now need `WriteItemData` and `ReadItemData` in addition to `Parse`, otherwise generated config classes cannot serialize/deserialize those fields.
7. If your runtime relies on first-launch file copy, make sure the generated config assets have actually been packaged into a runtime-loadable resource set.

## 📦 Dependencies

- Unity 2020.3 or later.
- [EPPlus](https://github.com/EPPlusSoftware/EPPlus) for Excel parsing.
- The DataChunk binary loading system for runtime config access.
- Unity Addressables or an equivalent delivery workflow if you distribute generated config binaries through packaged resources.

## ❓ FAQ

1. **Config loading fails**
   Check the export path, runtime persistent data path, and whether both `Data.bytes` and `Index.bytes` files exist.

2. **First launch does not copy config files**
   Check whether the generated config files were actually included in runtime-loadable resources and make sure `ConfigManager.Init(...)` has been executed.

3. **Generated config class fields are missing or incorrect**
   Verify Excel field names, field types, and key markers.

4. **Changes to export scripts are not reflected in generated config files**
   The tool skips unchanged Excel files based on MD5. Use **Delete Config Assets** or manually remove generated config files before exporting again.

## ❓ FAQ

1. **Config loading fails**
   Check the Excel path, asset output path, and whether both `Data.bytes` and `Index.bytes` exist in the runtime directory.

2. **The first launch cannot read configuration data**
   Check whether `ConfigManager.Init()` has been executed and whether the generated config files are available from the Addressables label `configasset`.

3. **Localized strings are not exported correctly**
   Make sure fields use `LocString` / `LocAsset` or the mapped `LocalizationStringRef` / `LocalizationAssetRef` types.

4. **Generated config fields are missing or have incorrect types**
   Check the Excel field names, field types, and duplicate-field definitions.

5. **Changes to generator scripts are not reflected in exported config assets**
   The tool compares Excel MD5 values to skip unchanged sheets. If only the scripts changed, delete the old `.bytes` files or use **Delete Config Assets** before exporting again.
