# Audio Management Tool Documentation

## 🎵 **Tool Features**

1. **Tree-like Pipeline Structure Design**
   - The audio management tool adopts a tree-like structure design, facilitating the management and extension of different audio types.
   - Uses a message routing mechanism to distribute and handle audio playback requests.

2. **Object Pool Optimization**
   - Uses an object pool to manage audio sources (`AudioSource`), reducing performance overhead caused by frequent creation and destruction of audio objects.

3. **Flexible Audio Control**
   - Supports volume adjustment, mute, fade-in/fade-out, pause, audio group switching, and more.
   - Supports spatialization processing (`spatialBlend`) for 3D audio effects.
   - Supports applying different mixer groups (`AudioMixerGroup`) to different pipelines.

4. **Asynchronous Loading Support**
   - Audio resources are loaded asynchronously to avoid blocking the main thread.
   - Automatically loads audio files using file paths, supporting dynamic loading and unloading of audio resources.

5. **Event-Triggered Playback**
   - Provides trigger components (`AudioTrigger`) and setter components (`AudioSetter`) to trigger audio playback via physics collisions or UI events.

6. **Extensibility**
   - Uses interface designs (e.g., `IAudioPipelineBehavior`) for easy extension and customization of audio playback logic.

7. **Background Music Management by Group**
   - Supports grouping background music for unified control and switching between audio groups.
   - Allows switching to a new audio group while preserving the current audio state.
   - Supports fade-in/fade-out during group switching to avoid abrupt audio transitions.

## 🛠️ **Usage Instructions**

### 1. **Initializing the Audio Manager**

The audio manager initializes automatically when the game starts; no manual calls are required.

```csharp  
  protected override void Awake()  
  {  
      base.Awake();  
      DontDestroyOnLoad(gameObject);  
      _assetLoader = AssetUtils.SpawnLoader("AudioManager");  
      BuildPipeLine();  
  }  
```  
Note the `BuildPipeLine()` method, which is responsible for constructing the audio pipeline.  
The default audio pipeline structure is as follows:
- Master
   - Music (BGM)
   - Dialog
   - SFX
      - SFXUI
      - SFX3D
      - Ambience
   - System

Among these, the *Master*, *Music*, and *SFX* pipelines have no playback behavior. The *Dialog*, *SFXUI*, *SFX3D*, *Ambience*, and *System* pipelines use different playback behaviors.  
The tool implements corresponding interfaces (`IAudioPipelineBehavior`) for each audio type, which can be extended or replaced as needed.

Pipelines have parent-child relationships. Adjusting the maximum volume, pausing/resuming, or muting a parent pipeline will propagate to its child pipelines.  
Dynamic addition/removal of pipelines is supported at runtime, but ensure they are reachable from the *Master* node; otherwise, audio requests cannot be routed to the target pipeline.

Pipeline construction method:
- Create an `AudioPipeline` instance.
- Call the `Init` method of the `AudioPipeline` instance, passing the pipeline ID and a playback behavior instance.
- The playback behavior is a class inheriting the `IAudioPipelineBehavior` interface, defining how to handle audio requests.
- Set the parent pipeline for the pipeline.

```csharp  
private void BuildPipeLine()  
{  
   _masterPipeline = new AudioPipeline();  
   _masterPipeline.Init((int)AudioSourceType.Master, null);  

   var bgmPipeline = new AudioPipeline();  
   bgmPipeline.Init((int)AudioSourceType.Music, null); //new CycleBGMAudioPipelineBehavior(bgmPipeline));  
   bgmPipeline.parent = _masterPipeline;  

   var dialogPipeline = new AudioPipeline();  
   dialogPipeline.Init((int)AudioSourceType.Dialog, new CutoffAudioPipelineBehavior(dialogPipeline));  
   dialogPipeline.parent = _masterPipeline;  
   
   var SFXPipeline = new AudioPipeline();  
   SFXPipeline.Init((int)AudioSourceType.SFX, null);  
   SFXPipeline.parent = _masterPipeline;  

   var SFXUiPipeline = new AudioPipeline();  
   SFXUiPipeline.Init((int)AudioSourceType.SFXUI, new PoolSFXAudioPipelineBehavior(SFXUiPipeline));  
   SFXUiPipeline.parent = SFXPipeline;  
   _updatePipelineBehaviors.Add(SFXUiPipeline.updateBehavior);  

   var SFX3DPipeline = new AudioPipeline();  
   SFX3DPipeline.Init((int)AudioSourceType.SFX3D, new PoolSFXAudioPipelineBehavior(SFX3DPipeline));  
   SFX3DPipeline.parent = SFXPipeline;  
   _updatePipelineBehaviors.Add(SFX3DPipeline.updateBehavior);  

   var ambiencePipeline = new AudioPipeline();  
   ambiencePipeline.Init((int)AudioSourceType.Ambience, new SampleAudioPipelineBehavior(ambiencePipeline));  
   ambiencePipeline.parent = SFXPipeline;  

   var systemPipeline = new AudioPipeline();  
   systemPipeline.Init((int)AudioSourceType.System, new SampleAudioPipelineBehavior(systemPipeline));  
   systemPipeline.parent = _masterPipeline;  
}  
```  

You can use `AddAudioMixerGroupToPipeline` and `RemoveAudioMixerGroupFromPipeline` to add or remove mixer groups from a pipeline.  
Use `GetPipelineMixerCtrl` to retrieve the mixer group controls for a specific pipeline, making it easier to manipulate audio effects.

### 2. **Playing Audio**

#### a. **Playing Background Music (BGM)**
Background music playback involves the concept of groups, and background music is switched based on groups.

```csharp  
AudioManager.instance.PlayMusic("MusicClipPath", MusicGroup.Default, fadeoutTime: 0.5f, intervalTime: 0.3f, fadeinTime: 0.5f);  
```  
Use the `SwitchMusicGroup` method to switch background music groups. Use `DisposeMusicGroup` to release resources for a specific background music group.  
When calling `PlayMusic`, it automatically switches to the given background music group but does not release resources from the previous group.

#### b. **Playing Ambience Audio**

```csharp  
PlayAmbience(clipRef:"clipPath", isLoop:true, fadeoutTime:1f, intervalTime:1f, fadeinTime:1f)  
```  

#### c. **Playing Dialogue Audio**

```csharp  
AudioManager.instance.PlayDialog("DialogClipPath", () => Debug.Log("Dialog Finished"));  
```  

#### d. **Playing 3D Sound Effects (Effect3D)**

Sound effect playback uses a queue mechanism to avoid stuttering during playback.

Simultaneous playback of the same sound effect is limited to prevent audio chaos caused by excessive sound effects.

- **Attach to an object**:

```csharp  
AudioManager.instance.RequestPlayEffect(clipRef:"EffectClipPath", onUI:false, attached:attachedGameObject, position:Vector3.zero, full3D:true)  
```  

- **Play at a specific position**:

```csharp  
AudioManager.instance.RequestPlayEffect(clipRef:"EffectClipPath", onUI:false, attached:null, position:Vector3.zero, full3D:true)  
```  

#### e. **Playing UI Sound Effects (UIEffect)**

```csharp  
AudioManager.instance.RequestPlayEffect(clipRef:"EffectClipPath", onUI:true, attached:null, position:Vector3.zero, full3D:false)  
```

### 5. **Triggers and Setters**

#### a. **Using `AudioTrigger`**

- Add the `AudioTrigger` component to objects that need to trigger sound effects.
- Automatically plays sound effects upon collision triggers.

#### b. **Using `AudioSetter`**

- Add the `AudioSetter` component to UI elements or objects that need to play sound effects.
- Set the audio path and trigger conditions (e.g., `playOnEnable`, `playOnUp`).
- AudioClips configured in `AudioSetter` are not directly assigned assets but are referenced by paths.
- This approach allows dynamic loading of audio resources at runtime, avoiding limitations of directly referencing audio files in the editor.

#### c. **Button Components and Sound Effects**

- `ButtonAddAudioEditor` can quickly add sound effect triggers to `Button` components.
- In the Button's Inspector panel, click the `Add Up AudioTrigger` button to add a sound effect trigger for the button's `PointerUp` event.
- Click the `Add Down AudioTrigger` button to add a sound effect trigger for the button's `PointerDown` event.
- After adding, the sound effect trigger automatically mounts the `AudioSetter` component and sets the corresponding trigger conditions (e.g., `playOnUp` or `playOnDown`).

## ⚠️ **Notes**

1. **Audio Resource Paths**
   - Ensure audio resource paths are correct and loaded into the project.

2. **Object Pool Management**
   - The audio manager uses an object pool to manage `AudioSource`. Ensure the object pool capacity is sufficient to avoid audio playback failures.

3. **Audio Type Differentiation**
   - Different audio types have independent volume and mute settings and must be managed separately.
   - Child pipeline volumes are affected by parent pipelines: actual volume = parent volume setting × child volume setting.
   - Parent pipeline pause/resume and mute/unmute actions propagate to child pipelines, with parent actions taking priority over child actions.

4. **Fade-in/Fade-out Timing**
   - When setting fade-in/fade-out times, ensure values are reasonable to avoid abrupt audio transitions.

5. **Performance Optimization**
   - Avoid frequent creation and destruction of audio objects; prefer using the object pool for audio playback management.

6. **Extensibility**
   - To customize audio playback logic, implement relevant interfaces (e.g., `IAudioPipelineBehavior`) and replace the default implementations.
