# 🔴 RedPoint System

## 1. System Overview

The RedPoint system manages UI red-point visibility, notification counts, and custom notification values. Notification nodes are grouped by **enum type**. Each enum group has its own node array, index translator, and parent-child tree.

### Features

1. **Multiple enum groups**: Different notification enum types are isolated and can represent different business modules.
2. **Tree aggregation**: Child states are aggregated by their parents; parent counts and values are recalculated from active children.
3. **Event-driven updates**: Only listeners registered on a changed node are notified.
4. **Indexed access**: `EnumNotifyIndexTranslator<T>` maps enum values to their positions in `Enum.GetValues()`.
5. **Editor support**: `NotifyGraphWindow`, `NotifyTreeViewWindow`, and `NotifierEditor` support configuration, debugging, and UI binding.

### Main Components / Interfaces

- `NotifyManager`: Manages enum groups, node state, hierarchy, and callbacks.
- `EnumNotifyIndexTranslator<T>`: Converts between enum values and `Enum.GetValues()` array indices.
- `INotifyBindPreset`: Extension contract for registering groups and binding node relationships.
- `Notifier`: A UI component that displays a red point using a serialized enum type name and node index.
- `NotifyGraphWindow`: Edits enum nodes and relationships and generates binding code.
- `NotifyTreeViewWindow`: Displays registered enum groups and live node state during Play Mode.
- `NotifierEditor`: Provides type search and enum-value selection for `Notifier`.

## 2. Operation and Optimizations

### Initialization and Groups

`NotifyManager.OnInit()` initializes the node and translator dictionaries, then uses reflection to find instantiable `INotifyBindPreset` implementations and calls `BindNodes` on them.

A group can be registered through either overload:

- `SetNotifyGroup<T>()`: For code that directly references an enum type.
- `SetNotifyGroup(Type)`: For reflection-, configuration-, or editor-driven registration.

Registering the same enum type more than once does not create a second node table. Nodes initially have no parent, are inactive, and have a count and value of `0`.

### Indexes and Relationships

Each enum group owns a `NotifyNode[]`. An array index is not necessarily the enum's underlying numeric value; it is the position of that value in `Enum.GetValues(enumType)`. `EnumNotifyIndexTranslator<T>` performs this conversion, so non-contiguous enum values are supported.

Each node stores one parent index and a set of child indices. A node can have at most one parent and can have multiple children. Reparenting removes the child from its previous parent's child set. Parent assignment also checks for cycles.

### State Calculation

- Leaf nodes can be changed with `SetNotify`.
- Nodes with children cannot be directly changed with `SetNotify`; their state is calculated from their children.
- A parent count is the number of active child nodes, and its value is the sum of active child values.
- A node is on when its calculated count is greater than `0`.
- `ForceNotify` can override any node temporarily. A forced parent with children may differ from its children until the next recalculation.

### Notifier Binding

`Notifier` no longer depends on a fixed `NotifyType` field. It serializes:

- `typeName`: The notification enum type name. `NotifierEditor` stores the assembly-qualified name, which is resolved at runtime by `ReflectionUtils.GetTypeByName`.
- `notifyTypeIndex`: The selected enum value's index in `Enum.GetValues(enumType)`.

`Notifier.Awake()` resolves the type and registers the callback. `OnEnable()` reads the current state, and `OnDestroy()` unregisters the callback.

## 3. Usage

### 3.1 Define an Enum Group

Use a separate enum for each business group. A value named `Root` is recommended as the group root. The order returned by `Enum.GetValues()` determines the serialized index mapping.

```csharp
namespace Game.UI
{
    public enum MailNotifyType
    {
        Root = 0,
        Mail,
        MailUnread,
        MailReward
    }
}
```

### 3.2 Register the Group and Bind Relationships

Implement `INotifyBindPreset` to register the group and its relationships. Presets are discovered and executed during `NotifyManager.OnInit()`.

```csharp
using PowerCellStudio;

public sealed class MailNotifyPreset : INotifyBindPreset
{
    public void BindNodes(NotifyManager manager)
    {
        manager.SetNotifyGroup<MailNotifyType>();
        manager.SetNodeParent(MailNotifyType.MailUnread, MailNotifyType.Mail);
        manager.SetNodeParent(MailNotifyType.MailReward, MailNotifyType.Mail);
        manager.SetNodeParent(MailNotifyType.Mail, MailNotifyType.Root);
    }
}
```

If an enum type is obtained dynamically, use `manager.SetNotifyGroup(enumType)`. The supplied `Type` must be non-null and must represent an enum.

### 3.3 Set a Leaf Node State

```csharp
NotifyManager.instance.SetNotify(MailNotifyType.MailUnread, true, 1);

var isOn = NotifyManager.instance.IsNotifyOn(
    MailNotifyType.Mail,
    out var notifyNumber);
```

Because `Mail` has children, its state and count are aggregated from `MailUnread`, `MailReward`, and other child nodes.

### 3.4 Register a Listener

```csharp
private void Awake()
{
    NotifyManager.instance.Register(MailNotifyType.Mail, OnNotifyChanged);
}

private void OnDestroy()
{
    NotifyManager.instance.UnRegister(MailNotifyType.Mail, OnNotifyChanged);
}

private void OnNotifyChanged(bool isOn, int notifyNumber, int notifyValue)
{
    // Update the UI.
}
```

### 3.5 Use the Notifier Component

Attach `Notifier` to a UI object, then use the Inspector:

1. Enter an enum name or part of its namespace in the `typeName` search box.
2. Select an enum type from the search results.
3. Select a node from the enum-value popup.
4. `NotifierEditor` stores the type in `typeName` and the value's `Enum.GetValues()` index in `notifyTypeIndex`.
5. Configure `redPoint`, `numberTxt`, and `valueTxt` as needed.

### 3.6 Inspect the Notification Tree

Open:

`Tools > UFlow > Notify > TreeView Window`

During Play Mode, the top of the window displays a button for each registered enum group. Select a group to inspect its tree, `IsOn` state, notification count, and notification value. Use the search field to locate nodes.

## 4. Extension

### Extend with `INotifyBindPreset`

`INotifyBindPreset` is the main public extension point. An implementation must be instantiable by the project's reflection utility and should register its enum group and relationships inside `BindNodes`.

```csharp
public sealed class RoleNotifyPreset : INotifyBindPreset
{
    public void BindNodes(NotifyManager manager)
    {
        manager.SetNotifyGroup<RoleNotifyType>();
        manager.SetNodeParent(RoleNotifyType.LevelUp, RoleNotifyType.Role);
        manager.SetNodeParent(RoleNotifyType.Role, RoleNotifyType.Root);
    }
}
```

The current system does not expose a public extension point for custom node data or custom aggregation algorithms. Changing count or value aggregation requires modifying `NotifyManager`.

## 5. Notes and Constraints

1. **The type must be resolvable**: `Notifier.typeName` must resolve through `ReflectionUtils.GetTypeByName`, and the result must be an enum. Reconfigure `Notifier` after renaming or moving an enum type.
2. **Do not enter an arbitrary index**: `notifyTypeIndex` is the enum value's position in `Enum.GetValues(enumType)`, not its underlying numeric value. Recheck `Notifier` components after changing enum declaration order.
3. **Register groups before use**: The corresponding group must exist before using state, relationship, or type/index callback APIs. Generic `Register` attempts to register its group automatically, but explicit registration in a preset is recommended.
4. **Set only leaf nodes**: `SetNotify` logs an error and ignores the request for nodes with children.
5. **Use `ForceNotify` carefully**: A forced state can temporarily disagree with child states and is best reserved for debugging or deliberate overrides.
6. **Avoid cycles**: Do not connect a node to itself or to one of its ancestors. The manager checks and rejects cyclic relationships.
7. **Unregister listeners**: Manually registered callbacks must be removed with `UnRegister` when no longer needed. `Notifier` unregisters itself in `OnDestroy`.
8. **Respect initialization order**: The manager's module initialization creates groups and executes presets. Do not query notification state before initialization is complete.
9. **Use the tree window in Play Mode**: `NotifyTreeViewWindow` displays runtime state and is intended for Play Mode.
10. **`ClearAll()` is destructive**: It clears state, parent-child relationships, and callbacks for every group. Relationships and listeners must be registered again afterward.

## 6. Recommended Scenarios

- **Mail, task, and reward modules**: Separate enum groups prevent unrelated business states from mixing.
- **Multi-level menu red points**: Leaf nodes represent concrete conditions while parent nodes aggregate them automatically.
- **Dynamic UI lists**: Use `Notifier` or `NotifyManager.AddNotifer` to reuse red-point UI for enum nodes.
- **Runtime debugging**: Use `NotifyTreeViewWindow` to inspect groups, relationships, and live state.
- **Code generation and team workflows**: Use `NotifyGraphWindow` to maintain enum nodes and preset relationships.

The system is suitable for stable, enum-identified notification trees that require parent aggregation. It is not intended to replace a general-purpose rule engine; complex conditions should be evaluated by the business layer and exposed through leaf-node `SetNotify` calls.
