# Data Chunk System

## 😀 Overview

The Data Chunk system is used to store large data files in chunks and load them on demand. It is suitable for scenarios such as configuration tables, resource data, offline data, and similar use cases.

This system splits data into multiple chunks and maintains an index and key set for each chunk. At runtime, only the accessed chunks are loaded, reducing memory usage and load time.

Main components are listed below:

| Component | Purpose |
|---|---|
| `ChunkMaker` | Writes a sequence of records into chunked data files and generates the chunk index file. |
| `ChunkReader` | Reads chunk records and index metadata from the data file and index file. |
| `ChunkIndexer<TKey>` | Parses the index file and builds mappings from key to chunk index and from chunk index to file offset. |
| `ChunkCustomIndexer<TKey>` | Suitable when the chunk index can be derived directly from the key, avoiding a full key-to-chunk map. |
| `ChunkDataMap<TKey, TData>` | Caches loaded chunk data and maintains chunk reference counts. |
| `ChunkDataQueryer<TKey, TData>` | Provides external APIs for lookup by key, conditional queries, and iterating all data. |
| `ChunkInfo` | Chunk metadata structure containing the chunk index, file offset, and serialized key array bytes. |
| `ChunkDataOptions` | Defines chunk encryption/decryption and serialization behavior. |

Component dependencies
```
ChunkDataQueryer<TKey, TData>
        |
        |──> ChunkIndexer<TKey>-----------------> ChunkReader
        |
        └──> ChunkDataMap<TKey, TData>----------> ChunkReader

ChunkMaker -----> ChunkDataOptions -----> IChunkEncryptor / IChunkSerializer -----> ChunkInfo

ChunkReader -----> ChunkDataOptions -----> IChunkEncryptor / IChunkSerializer -----> ChunkInfo
```

## 🛠️ Usage

### 1.✨ **Generate chunk data files**

Use `ChunkMaker.StreamWriteSync<TData, TKey>` to write data to disk and generate both the data file and the index file.

```csharp
var dataDirectory = "Assets/Res/DataChunk";
var fileName = "MyConfig";
var records = myDataList; // IEnumerable<MyData>
ChunkMaker.StreamWriteSync<MyData, int>(
    fileDirectory: dataDirectory,
    fileName: fileName,
    data: records,
    keySelector: item => item.id,
    chunkSize: 256,
    options: new ChunkDataOptions { EnableEncryption = true });
```

This generates two files:

- `MyConfigData.bytes`: the actual data file, with records written chunk by chunk.
- `MyConfigIndex.bytes`: the chunk index file, containing chunk offsets and the corresponding key sets.

If you want the chunking rule to be based on a custom `key => chunkId` mapping instead of "input order + fixed chunkSize", you can use this overload:

```csharp
ChunkMaker.StreamWriteSync<MyData, int>(
    fileDirectory: dataDirectory,
    fileName: fileName,
    data: records,
    keySelector: item => item.id,
    keyToChunkIndex: key => key / 100,
    options: new ChunkDataOptions { EnableEncryption = true });
```

In this mode:

- Records with the same `chunkId` are written into the same chunk.
- `ChunkInfo.index` stores that `chunkId` directly.
- The original input order is still preserved inside each chunk.

### 2.🔍 **Prepare the queryer**

At runtime, use `ChunkDataQueryer<TKey, TData>` to load the index and initialize the cache structures.

```csharp
var queryer = new ChunkDataQueryer<int, MyData>();
var options = new ChunkDataOptions { EnableEncryption = true };
queryer.Prepare(
    indexFilePath: "Assets/Res/DataChunk/MyConfigIndex.bytes",
    dataFilePath: "Assets/Res/DataChunk/MyConfigData.bytes",
    keySelector: data => data.id,
    options: options);
```

If you need to initialize the index asynchronously in a coroutine, use:

```csharp
yield return queryer.PrepareYieldInstruction(
    indexFilePath: indexPath,
    dataFilePath: dataPath,
    keySelector: data => data.id,
    options: options);
```

> Note: `Prepare` / `PrepareYieldInstruction` only initialize the index and cache structures. They do not load actual data chunks.

### 2.1.🧩 **Custom serialization and encryption**

`ChunkDataOptions` supports replacing the default serializer and encryptor:

- `Serializer` defaults to `DefaultChunkSerializer`, which uses `BinarySerializer` internally.
- `Encryptor` defaults to `DefaultChunkEncryptor`, which uses `EncryptUtils.AESEncrypt/AESDecrypt` internally.
- When `EnableEncryption = false`, no encryptor is invoked.

The most important constraint is this: writing and reading must use the same `ChunkDataOptions`; otherwise decryption or deserialization will fail.

#### a. Custom serializer

```csharp
public sealed class VersionedChunkSerializer : IChunkSerializer
{
    private const byte CurrentVersion = 1;

    public byte[] Write<T>(T data)
    {
        byte[] payload = BinarySerializer.Serialize(data);
        byte[] result = new byte[payload.Length + 1];
        result[0] = CurrentVersion;
        Buffer.BlockCopy(payload, 0, result, 1, payload.Length);
        return result;
    }

    public T Read<T>(byte[] bytes, int offset, int count)
    {
        if (count <= 0)
            throw new InvalidOperationException("Chunk payload is empty.");

        byte version = bytes[offset];
        if (version != CurrentVersion)
            throw new InvalidOperationException($"Unsupported chunk serializer version: {version}");

        return BinarySerializer.Deserialize<T>(bytes, offset + 1, count - 1);
    }
}
```

Usage:

```csharp
var options = new ChunkDataOptions
{
    EnableEncryption = false,
    Serializer = new VersionedChunkSerializer()
};

ChunkMaker.StreamWriteSync<MyData, int>(
    fileDirectory: dataDirectory,
    fileName: fileName,
    data: records,
    keySelector: item => item.id,
    chunkSize: 256,
    options: options);

var queryer = new ChunkDataQueryer<int, MyData>();
queryer.Prepare(indexPath, dataPath, data => data.id, options);
```

#### b. Custom encryptor

```csharp
public sealed class XorChunkEncryptor : IChunkEncryptor
{
    private readonly byte _key;

    public XorChunkEncryptor(byte key)
    {
        _key = key;
    }

    public byte[] Encrypt(byte[] data)
    {
        var result = new byte[data.Length];
        for (int i = 0; i < data.Length; i++)
        {
            result[i] = (byte)(data[i] ^ _key);
        }
        return result;
    }

    public byte[] Decrypt(byte[] data, int offset, int count)
    {
        var result = new byte[count];
        for (int i = 0; i < count; i++)
        {
            result[i] = (byte)(data[offset + i] ^ _key);
        }
        return result;
    }
}
```

Usage:

```csharp
var options = new ChunkDataOptions
{
    EnableEncryption = true,
    Serializer = DefaultChunkSerializer.Instance,
    Encryptor = new XorChunkEncryptor(0x5A)
};

ChunkMaker.StreamWriteSync<MyData, int>(
    fileDirectory: dataDirectory,
    fileName: fileName,
    data: records,
    keySelector: item => item.id,
    chunkSize: 256,
    options: options);

var queryer = new ChunkDataQueryer<int, MyData>();
queryer.Prepare(indexPath, dataPath, data => data.id, options);
```

#### c. Customize both serialization and encryption

```csharp
var options = new ChunkDataOptions
{
    EnableEncryption = true,
    Serializer = new VersionedChunkSerializer(),
    Encryptor = new XorChunkEncryptor(0x5A)
};
```

This configuration applies to:

- Writing and reading each record in the data file.
- Writing and reading `ChunkInfo` in the index file.
- Serializing and deserializing each chunk's key array `TKey[]`.

#### d. Notes for interface implementations

- `IChunkSerializer.Read` must correctly honor `offset` and `count`; do not assume the whole array is valid data.
- `IChunkEncryptor.Decrypt` must only decrypt the valid range `[offset, offset + count)`.
- A custom `Serializer` must be able to handle `TData`, `ChunkInfo`, and `TKey[]`, because all three go through the same serializer.
- If custom encryption is enabled, the reading side must use the same encryptor configuration; otherwise `ChunkReader` cannot reconstruct the original data.

### 2.2.🧭 **Use ChunkCustomIndexer for derivable keys**

When the target chunk can be derived directly from the key, you can use `ChunkCustomIndexer<TKey>`.

Typical scenarios include:

- Numeric keys split into fixed ranges.
- Keys that contain a partition id, date id, page number, or other information that can be converted directly into a chunk index.
- Cases where you do not want to keep a full key-to-chunk mapping in memory and only need the `chunkIndex -> offset` map.

`ChunkDataQueryer<TKey, TData>` provides a matching `Prepare` overload:

```csharp
var queryer = new ChunkDataQueryer<int, MyData>();
var options = new ChunkDataOptions { EnableEncryption = false };

queryer.Prepare(
    indexFilePath: indexPath,
    dataFilePath: dataPath,
    keySelector: data => data.id,
    keyPredicate: key => key >= 1000 && key < 1000 + 256 * 32,
    keyToChunkIndex: key => (key - 1000) / 256,
    options: options);
```

If you do not need an extra key-range check, you can also use the overload that only takes `keyToChunkIndex`:

```csharp
queryer.Prepare(
    indexFilePath: indexPath,
    dataFilePath: dataPath,
    keySelector: data => data.id,
    keyToChunkIndex: key => key / 100,
    options: options);
```

In this example:

- Only keys in the target range are accepted.
- The target chunk is computed directly with `key => (key - 1000) / 256`.
- The index file is still read during initialization, but only the `chunkIndex -> offset` mapping is retained.

When using this approach, `keyToChunkIndex` must match the chunking rule used when the data was written. Otherwise the lookup will point to the wrong chunk.

Also note that the current implementation of `ChunkDataQueryer.GetByKey(...)` depends on the default `ChunkIndexer<TKey>`. If the queryer is prepared with `ChunkCustomIndexer<TKey>`, it is better suited for exact single-key access via `Get(key, ...)`, or for a custom batch-query implementation of your own.

### 2.3.🧱 **Build custom chunk lookup tools**

If the default `ChunkDataQueryer<TKey, TData>` does not match your needs, you can assemble your own lookup tool from the lower-level components.

The two most common approaches are:

- Use `ChunkDataQueryer<TKey, TData>.CreateChunkTools(...)` to quickly obtain the default `ChunkIndexer<TKey>` and `ChunkDataMap<TKey, TData>`.
- Implement `IChunkIndexer<TKey>` directly, then combine it with `ChunkDataMap<TKey, TData>` and `ChunkReader` in a custom query class.

For example, here is a minimal custom lookup wrapper:

```csharp
public class MyChunkLookup<TKey, TData>
{
    private readonly string _dataFilePath;
    private readonly Func<TData, TKey> _keySelector;
    private readonly ChunkDataOptions _options;
    private readonly IChunkIndexer<TKey> _indexer;
    private readonly ChunkDataMap<TKey, TData> _dataMap;

    public MyChunkLookup(
        string indexFilePath,
        string dataFilePath,
        Func<TData, TKey> keySelector,
        IChunkIndexer<TKey> indexer,
        ChunkDataOptions options = null)
    {
        _dataFilePath = dataFilePath;
        _keySelector = keySelector;
        _options = options;
        _indexer = indexer;
        _dataMap = new ChunkDataMap<TKey, TData>();

        var reader = ChunkReader.ReadIndexFile<TKey>(indexFilePath, options);
        _indexer.Init(reader);
        _dataMap.Init(_indexer.chunkCount);
    }

    public TData Get(TKey key)
    {
        int chunkIndex = _indexer.GerChunkIndex(key);
        if (chunkIndex < 0)
            return default;

        if (!_dataMap.IsChunkLoaded(chunkIndex))
        {
            long offset = _indexer.GetChunkOffset(chunkIndex);
            var chunkData = ChunkReader.ReadChunkData<TData>(_dataFilePath, offset, _options);
            _dataMap.AddChunk(chunkIndex, chunkData, _keySelector, null);
        }

        return _dataMap.GetData(chunkIndex, key);
    }
}
```

This approach is useful when you want to extend:

- chunk selection strategies.
- batch query strategies.
- cache eviction strategies.
- statistics, warm-up, or monitoring logic.

### 3.📦 **Load on demand and query**

#### a. Get a single record

```csharp
var data = queryer.Get(key, onAdd: item => {
    // Optional callback: triggered when a new record is loaded
});
```

`Get` finds the corresponding chunk index by key. If the chunk has not been loaded yet, it loads that chunk automatically, then searches the chunk cache for the requested record.

#### b. Query multiple records by key condition

```csharp
foreach (var item in queryer.GetByKey(k => k > 100, onAdd: item => {
    // Chunk load callback
}))
{
    // Process item
}
```

This method finds matching chunk indexes based on the key predicate, loads the relevant chunks, and then yields matching results one by one.

#### c. Iterate all data

```csharp
foreach (var item in queryer.GetAll())
{
    // Process item
}
```

`GetAll` traverses all chunks. If a chunk is already loaded, data is read directly from the cache; otherwise the chunk is loaded from the data file on demand.

#### d. General predicate query

```csharp
foreach (var item in queryer.Find(data => data.name.Contains("test")))
{
    // Process item
}
```

`Find` iterates over all data via `GetAll()` and applies the provided predicate.

## 🌟 Internal mechanisms and optimizations

### 1. Chunk index and offsets

The index file created by `ChunkMaker` records the following for each chunk:

- `index`: the chunk number.
- `offset`: the starting byte offset of the chunk in the data file.
- `keys`: all keys contained in the chunk.

`ChunkIndexer<TKey>` reads this information and builds:

- `_keyMap`: mapping from key to chunk number.
- `_offsetMap`: mapping from chunk number to file offset.

### 2. Chunked data layout

The data file structure inside each chunk is:

- a 4-byte length prefix
- the actual payload bytes
- repeated entries in the same format
- a trailing 4-byte `0` marking the end of the chunk

`ChunkReader.ReadChunkData<TData>` reads each entry in this format and deserializes it into `TData`.

### 3. Reference-count-based cache management

`ChunkDataMap<TKey, TData>` tracks chunk access frequency through `_loadedChunkRefCount`.

- `AddChunk` increments the reference count when a chunk is loaded.
- `GetData` / `GetAllData` also increment the reference count when data is accessed.
- `TryClearUnused` retains the top one-third most frequently accessed chunks and releases the rest.

This prevents frequently accessed chunks from being released too early while reclaiming memory from cold chunks.

## ⚙️ Key interfaces

### `ChunkMaker` common method

- `StreamWriteSync<TData, TKey>(string fileDirectory, string fileName, IEnumerable<TData> data, Func<TData, TKey> keySelector, int chunkSize, ChunkDataOptions options = null)`
  - Generates the data file and the index file.
  - `chunkSize` is the maximum number of records in each chunk.
  - `options` controls serialization and encryption/decryption behavior.
- `StreamWriteSync<TData, TKey>(string fileDirectory, string fileName, IEnumerable<TData> data, Func<TData, TKey> keySelector, Func<TKey, int> keyToChunkIndex, ChunkDataOptions options = null)`
    - Generates the data file and index file by grouping records with a custom `chunkId`.
    - Suitable when the target chunk can be derived directly from the key.

### `ChunkDataQueryer<TKey, TData>` common methods

- `Prepare(string indexFilePath, string dataFilePath, Func<TData, TKey> keySelector, Func<TKey, bool> keyPredicate, Func<TKey, int> keyToChunkIndex, ChunkDataOptions options = null)`
- `Prepare(string indexFilePath, string dataFilePath, Func<TData, TKey> keySelector, Func<TKey, int> keyToChunkIndex, ChunkDataOptions options = null)`
- `Prepare(string indexFilePath, string dataFilePath, Func<TData, TKey> keySelector, ChunkDataOptions options = null)`
- `PrepareYieldInstruction(string indexFilePath, string dataFilePath, Func<TData, TKey> keySelector, int operationUnit = 512, ChunkDataOptions options = null)`
- `Get(TKey key, Action<TData> onAdd)`
- `GetByKey(Func<TKey, bool> keyPredicate, Action<TData> onAdd)`
- `GetAll()`
- `Find(Func<TData, bool> predicate)`
- `TryClearUnused()`
- `Clear()`
- `CreateChunkTools(string indexFilePath, ChunkDataOptions options = null)`

### `ChunkIndexer<TKey>` common methods

- `Init(IEnumerable<(int index, long offset, TKey[] keys)> chunks)`
- `InitAsync(IEnumerable<(int index, long offset, TKey[] keys)> chunks, int operationUnit = 512)`
- `Clear()`
- `GerChunkIndex(TKey key)`
- `GetChunkIndexByKey(Func<TKey, bool> keyPredicate)`
- `GetChunkOffset(int chunkIndex)`

### `ChunkReader` common methods

- `ReadChunkData<TData>(string filePath, long offset, ChunkDataOptions options = null)`
- `ReadIndexFile<TKey>(string filePath, ChunkDataOptions options = null)`

## ℹ️ Notes

1. `Prepare` must be executed first; otherwise the queryer does not know the chunk index or data offsets.
2. If you use a custom `Serializer`, it must handle not only `TData`, but also `ChunkInfo` and `TKey[]`.
3. Default encryption is controlled by `ConstSetting.FileEncryptionKey` and `EncryptUtils`; if encryption is not needed, pass `new ChunkDataOptions { EnableEncryption = false }` or `ChunkDataOptions.WithoutEncryption`.
4. Writing and reading must use the same `ChunkDataOptions`, especially when using custom `Serializer` or `Encryptor`.
5. `IChunkEncryptor.Decrypt(byte[] data, int offset, int count)` receives the valid payload range through `offset` and `count`, and these values must not be ignored.
6. `ChunkDataMap` increments access counts in `GetData`, preventing frequently accessed chunks from being released too aggressively.
7. `Clear()` clears all loaded chunks and releases the index cache.
8. When using `ChunkCustomIndexer<TKey>`, `keyToChunkIndex` must stay consistent with the chunking rule used when writing the data.
9. The current `ChunkDataQueryer.GetByKey(...)` implementation depends on the default `ChunkIndexer<TKey>`; when using `ChunkCustomIndexer<TKey>`, prefer `Get(...)` or wrap your own batch query flow.
10. When writing with custom `chunkId` grouping, `chunkId` must be a non-negative integer; negative values are treated as invalid configuration.

## ✅ Recommended scenarios

- Chunked loading of large configuration tables
- Chunked storage and fast access for game data
- Runtime workflows that only read part of the data instead of loading everything at once
- Scenarios requiring quick chunk lookup by key and on-demand loading
