# Async System

## 😀 Overview

The async system is used to manage coroutines, delayed scheduling, fixed-interval tasks, thread pool tasks, and Unity Jobs in a unified way at runtime, so that gameplay code does not need to depend on scattered entry points or maintain lifecycles on its own.

The system uses `AsyncManager` as its unified entry. It automatically creates a host object on first use and drives each executor in `Update` and `FixedUpdate`. It is suitable for the following scenarios:

- Starting and canceling coroutine flows
- Delaying main-thread logic by seconds or frames
- Registering fixed-interval polling tasks
- Sending heavy computations to the thread pool and switching back to the main thread on completion
- Scheduling `IJob` and `IJobFor` tasks

Main components are listed below:

| Component | Purpose |
|---|---|
| `AsyncManager` | Unified entry of the async system. Responsible for creating, holding, and exposing all executors. |
| `CoroutineRunner` | Runs `IEnumerator` through Unity coroutines, with exception logging wrappers in the editor. |
| `SchedulerRunner` | Executes one-shot tasks after a delay by time or by frame count. |
| `IntervalCallRunner` | Executes repeated tasks at fixed intervals and supports auto-release conditions. |
| `ThreadedTasksRunner` | Submits tasks to the thread pool and dispatches callbacks back to the main thread. |
| `JobRunner` | Executes `IJob` and `IJobFor`, supporting both synchronous and asynchronous modes. |
| `AsyncHandlerBase` | Base class for async handles, providing `Cancel` and completion callbacks. |
| `YieldInstructionsQueue` | Executes multiple coroutines sequentially and supports progress observation, pause, resume, and cancel. |

Component dependencies
```
AsyncManager
    |
    |──> CoroutineRunner
    |       |
    |       └──> CoroutineHandler / YieldInstructionsQueue
    |
    |──> SchedulerRunner
    |       |
    |       └──> SchedulerTask
    |
    |──> IntervalCallRunner
    |
    |──> ThreadedTasksRunner
    |
    └──> JobRunner
            |
            └──> CoroutineRunner (used to simulate async parallel jobs on WebGL)
```

## 🛠️ Usage

### 1.✨ Start a coroutine

Use `AsyncManager.Run` to start a coroutine task. The return value is `AsyncHandlerBase`, which can be used to wait for completion or cancel manually.

```csharp
private IEnumerator LoadFlow()
{
    yield return new WaitForSeconds(1f);
    Debug.Log("Load complete");
}

AsyncHandlerBase handler = AsyncManager.Run(LoadFlow());
handler?.OnComplete(() => Debug.Log("Coroutine finished"));
```

If you already have the manager instance, you can also use the instance method:

```csharp
AsyncManager.EnsureInstance().RunCoroutine(LoadFlow());
```

### 2.⏱️ Delay main-thread tasks

Use `Schedule` to delay by seconds and `ScheduleByFrame` to delay by frame count.

```csharp
AsyncManager.Schedule(() => Debug.Log("Delay by seconds"), 0.5f);
AsyncManager.ScheduleByFrame(() => Debug.Log("Delay by frames"), 3);
```

If the delay is less than or equal to `0`, the task is executed immediately and `null` is returned.

### 3.🔁 Register fixed-interval tasks

Use `RegisterIntervalTask` to register a repeatedly triggered task. The task is driven by `FixedUpdate`.

```csharp
int taskId = AsyncManager.EnsureInstance().RegisterIntervalTask(
    1f,
    () => Debug.Log("Tick every second"),
    () => false);

// Unregister later
AsyncManager.EnsureInstance().UnregisterIntervalTask(taskId);
```

If you want the task to release automatically when a condition is met, pass `autoReleaseCondition`:

```csharp
bool finished = false;
AsyncManager.EnsureInstance().RegisterIntervalTask(
    0.2f,
    () => Debug.Log("Polling"),
    () => finished);
```

### 4.📚 Execute a coroutine queue sequentially

Use `CreateYieldInstructionsQueue` to create a coroutine queue that runs items one by one, with an optional fixed interval between adjacent coroutines.

```csharp
IEnumerator StepA()
{
    Debug.Log("Step A");
    yield return new WaitForSeconds(0.5f);
}

IEnumerator StepB()
{
    Debug.Log("Step B");
    yield return null;
}

YieldInstructionsQueue queue = AsyncManager.EnsureInstance()
    .CreateYieldInstructionsQueue(0.1f, StepA(), StepB());

queue.OnComplete(() => Debug.Log("Queue completed"));
```

The queue supports:

- `Pause()`: pause execution
- `Resume()`: resume execution
- `Cancel()`: stop the queue and clear remaining tasks
- `process`: execution progress from $0$ to $1$

### 5.🧵 Submit thread-pool tasks

Use `RunTaskAsync` to send a background task to the thread pool and finish up on the main thread afterward.

```csharp
AsyncManager.EnsureInstance().RunTaskAsync(
    () =>
    {
        // Heavy work on a background thread
        System.Threading.Thread.Sleep(100);
    },
    () =>
    {
        // Back on the main thread
        Debug.Log("Background task completed");
    });
```

There is also a parameterized overload:

```csharp
AsyncManager.EnsureInstance().RunTaskAsync<int>(
    value => Debug.Log($"Background value: {value}"),
    10,
    () => Debug.Log("Callback on main thread"));
```

### 6.⚙️ Run Unity Jobs

Synchronous mode is suitable when you need the result immediately:

```csharp
public struct AddJob : IJob
{
    public NativeArray<int> values;

    public void Execute()
    {
        values[0] += 1;
    }
}

var values = new NativeArray<int>(1, Allocator.TempJob);
AsyncManager.EnsureInstance().SyncRunJob(new AddJob { values = values });
values.Dispose();
```

Asynchronous mode returns the result through a callback when the task is finished:

```csharp
public struct MultiplyJob : IJobFor
{
    public NativeArray<int> values;

    public void Execute(int index)
    {
        values[index] *= 2;
    }
}

var values = new NativeArray<int>(16, Allocator.TempJob);
AsyncManager.EnsureInstance().AsyncRunParallelJob(
    new MultiplyJob { values = values },
    values,
    values.Length,
    result =>
    {
        Debug.Log($"Job finished, length = {result.Length}");
        result.Dispose();
    });
```

## 🌟 Design Features

### 1. Single unified entry

The gameplay layer only needs to depend on `AsyncManager`, instead of separately holding a coroutine host, scheduler, thread-pool utility, or job polling runner.

### 2. Centralized lifecycle management

`AsyncManager` initializes all executors in `Awake` and releases resources uniformly in `Deinit`:

- The coroutine runner stops and clears its handler pool
- Delayed tasks and interval tasks release cached objects
- The thread-pool callback queue is cleared
- Async jobs are checked and completed

### 3. Safe main-thread callback dispatch

Thread-pool tasks do not directly invoke Unity APIs. Instead, callbacks are first queued to the main thread and then executed by `AsyncManager.Update`.

### 4. Platform-compatible fallback

Under `UNITY_WEBGL`:

- Thread-pool tasks degrade to immediate synchronous execution
- `IJob` calls `Execute` directly
- Parallel jobs simulate asynchronous execution across frames through coroutines

## 📦 Public Capabilities Overview

Based on the current implementation, the core capabilities exposed by `AsyncManager` include:

### 1. Coroutine capabilities

- `Run(IEnumerator routine)`
- `RunCoroutine(IEnumerator routine)`
- `CreateYieldInstructionsQueue(float interval, params IEnumerator[] enumerators)`
- `Host` property for getting the current host `MonoBehaviour`

### 2. Scheduling capabilities

- `Schedule(Action action, float delayTime = 0f, bool ignoreTimeScale = false)`
- `ScheduleByFrame(Action action, int delayFrames = 0)`
- Corresponding instance methods `ScheduleTask` and `ScheduleTaskByFrame`

### 3. Interval task capabilities

- `RegisterIntervalTask(float interval, Action action, Func<bool> autoReleaseCondition = null)`
- `UnregisterIntervalTask(int taskIndex)`
- `ClearIntervalTasks()`

### 4. Thread task capabilities

- `RunTaskAsync(Action backgroundTask, Action mainThreadCallback = null)`
- `RunTaskAsync<T>(Action<T> backgroundTask, T parameter, Action mainThreadCallback = null)`

### 5. Job capabilities

- `SyncRunJob<TJob>(TJob job)`
- `AsyncRunJob<TJob, T>(TJob job, NativeArray<T> resultArray, Action<NativeArray<T>> onComplete)`
- `SyncRunParallelJob<TJob>(TJob job, int length, int batchCount = 64)`
- `AsyncRunParallelJob<TJob, T>(TJob job, NativeArray<T> resultArray, int length, Action<NativeArray<T>> onComplete, int batchCount = 64)`

## ⚙️ Internal Mechanisms And Driving Model

### 1. Automatically creating the host object

`AsyncManager.EnsureInstance()` dynamically creates a GameObject named `AsyncManager` on first call and attaches the component itself.

### 2. `Update()` drives one-shot tasks and callbacks

`Update()` drives:

- `SchedulerRunner.Tick(time, unscaledTime, frameCount)`
- `ThreadedTasksRunner.Tick()`
- `JobRunner.Tick()`

This means second-based scheduling, frame-based scheduling, thread callback dispatching, and async job completion checks are all advanced frame by frame on the main thread.

### 3. `FixedUpdate()` drives interval tasks

`FixedUpdate()` calls `IntervalCallRunner.Tick(Time.fixedDeltaTime)`, so fixed-interval tasks are advanced by fixed-step timing rather than normal `Update` timing.

### 4. Coroutine exception wrapping in the editor

Under `UNITY_EDITOR`, `CoroutineRunner` uses a wrapper to catch coroutine exceptions and log them, so exceptions inside coroutines are not silently swallowed.

## 🔍 Example Scenarios

### 1. Delayed refresh after opening a UI

```csharp
AsyncManager.Schedule(() => RefreshUI(), 0.2f);
```

### 2. Sequential resource loading flow

```csharp
var queue = AsyncManager.EnsureInstance().CreateYieldInstructionsQueue(
    0f,
    LoadConfig(),
    LoadAtlas(),
    EnterScene());

yield return queue;
```

### 3. Background computation followed by main-thread presentation update

```csharp
AsyncManager.EnsureInstance().RunTaskAsync(
    () => BuildCache(),
    () => ShowReadyState());
```

### 4. Batch-processing data with Jobs

```csharp
AsyncManager.EnsureInstance().AsyncRunParallelJob(
    new MultiplyJob { values = values },
    values,
    values.Length,
    result => ApplyResult(result));
```

## ℹ️ Notes

1. `Schedule` and `ScheduleByFrame` execute immediately and return `null` when the delay parameter is less than or equal to zero, so the return value cannot be canceled afterward.
2. `ThreadedTasksRunner.backgroundTask` runs on a thread-pool thread and must not directly access most Unity APIs.
3. The main-thread callback of `RunTaskAsync` depends on `AsyncManager.Update()` being driven. If the host is no longer alive, the callback will not be dispatched normally.
4. `RegisterIntervalTask` advances intervals by accumulating `FixedUpdate` delta time, so actual trigger timing is affected by the physics step size.
5. The lifetime of `NativeArray` passed into `AsyncRunJob` and `AsyncRunParallelJob` is managed by the caller and should usually be released in the completion callback.
6. Under WebGL, the thread pool and Job System use fallback branches. The behavior remains close in meaning, but it is not fully equivalent to native concurrent execution.
7. `YieldInstructionsQueue.Cancel()` clears remaining tasks and releases the internal coroutine, and it will not trigger the completion callback afterward.

## ✅ Recommended Scenarios

- Coroutine-based sequence control such as UI animation, panel switching, and guidance flow
- Logic orchestration that needs delayed execution by seconds or frames
- Fixed-interval tasks such as polling checks, timeout checks, and cooldown refreshes
- CPU work such as text parsing, path building, and cache preprocessing that can be moved to the thread pool
- Data-heavy tasks suited to the Job System, such as bulk array processing, path sampling, and numeric preprocessing
