# Event System

## 😀 Overview

UFlow's event system provides three complementary event models to cover different communication scenarios:

- `LinkEvent`: an immediately-invoked strongly typed event, suitable for direct notifications between modules.
- `LaterEvent`: an event deferred to the `LaterExecute` stage, suitable for avoiding reentrancy and chained refreshes in the current call stack.
- `ScopedEventBus`: a local event bus based on `eventId`, suitable for maintaining a temporary set of events inside a specific system, page, or module.

In addition, `EventManager` provides a set of framework-level public events, such as loading, resolution changes, UI open/close, language switching, and network connection changes, which can be subscribed to directly by gameplay code.

---

## 🧱 Main Components

| Component | Purpose |
|---|---|
| `LineEventBase` | Base class for events, providing the `enable` switch and a unified `RemoveAllListeners` entry point. |
| `LinkEvent` / `LinkEvent<T...>` | Immediate events supporting 0 to 3 parameters. |
| `LaterEvent` / `LaterEvent<T...>` | Deferred events whose trigger requests first enter `EventManager` and are executed later in a unified stage. |
| `ScopedEventBus` | Manages a group of strongly typed events through `int eventId`, and supports delayed collection and deduplicated release. |
| `EventManager` | Framework-level event center that also drives the unified execution of `LaterEvent`. |

Supported parameter counts:

- No parameter
- 1 parameter
- 2 parameters
- 3 parameters

The corresponding delegate types are:

```csharp
BaseLinkAction
BaseLinkAction<T>
BaseLinkAction<T, TK>
BaseLinkAction<T, TK, TL>
```

## 1. Immediate Events: `LinkEvent`

`LinkEvent` is the most basic event type. When `Invoke` is called, listeners are executed immediately in the current call stack.

### Suitable Scenarios

- A state change has been confirmed and listeners should be notified immediately.
- The event handling logic is simple and does not risk reentrancy issues.
- You want strong typing for event parameters.

### Common API

- `AddListener(...)`
- `RemoveListener(...)`
- `AddListenerOnce(...)`
- `Invoke(...)`
- `RemoveAllListeners()`
- `GetEventListenerCount()`
- `enable`

### Example

```csharp
public class CurrencyModule
{
    public readonly LinkEvent<int> onCoinChanged = new LinkEvent<int>();

    private int _coin;

    public void AddCoin(int delta)
    {
        _coin += delta;
        onCoinChanged.Invoke(_coin);
    }
}

public class CurrencyPanel : MonoBehaviour
{
    [SerializeField] private TMPro.TextMeshProUGUI _coinText;
    private CurrencyModule _currencyModule;

    private void OnEnable()
    {
        _currencyModule.onCoinChanged.AddListener(OnCoinChanged);
    }

    private void OnDisable()
    {
        _currencyModule.onCoinChanged.RemoveListener(OnCoinChanged);
    }

    private void OnCoinChanged(int value)
    {
        _coinText.text = value.ToString();
    }
}
```

### One-shot Listener

```csharp
EventManager.instance.onNetConnect.AddListenerOnce(() =>
{
    Debug.Log("Only runs once after connect");
});
```

### Temporarily Disabling Event Dispatch

All events inherit from `LineEventBase`, so dispatching can be temporarily disabled through `enable`:

```csharp
var gameEvent = new LinkEvent();
gameEvent.enable = false;
gameEvent.Invoke(); // No listener will be called
```

## 2. Deferred Events: `LaterEvent`

`LaterEvent.Invoke` does not execute listeners immediately. Instead, it first registers the event in `EventManager`, and the listeners are executed later when the module system drives `EventManager.LaterExecute`.

### Suitable Scenarios

- Avoid refreshing UI or mutating state immediately in the current execution flow.
- Multiple trigger requests may occur in the same frame, but you want to handle them in a later stage.
- You want event execution to happen in the module's deferred execution phase.

### Key Behavior

- Once the event has entered the pending queue, repeated `Invoke` calls do not enqueue it again.
- For `LaterEvent<T...>`, a later `Invoke` overwrites previously cached parameter data.
- Actual listener execution depends on `EventManager.LaterExecute` being driven normally.

### Example

```csharp
public class InventoryModule
{
    public readonly LaterEvent onInventoryDirty = new LaterEvent();

    public void MarkDirty()
    {
        onInventoryDirty.Invoke();
    }
}

public class InventoryPanel : MonoBehaviour
{
    [SerializeField] private InventoryModule _inventoryModule;

    private void OnEnable()
    {
        _inventoryModule.onInventoryDirty.AddListener(RefreshView);
    }

    private void OnDisable()
    {
        _inventoryModule.onInventoryDirty.RemoveListener(RefreshView);
    }

    private void RefreshView()
    {
        Debug.Log("Refresh inventory once in later execution stage");
    }
}
```

### Parameterized Example

```csharp
public class ChatModule
{
    public readonly LaterEvent<string> onLatestMessageChanged = new LaterEvent<string>();

    public void SetLatestMessage(string message)
    {
        onLatestMessageChanged.Invoke(message);
    }
}
```

If the following code runs in the same frame:

```csharp
chatModule.SetLatestMessage("A");
chatModule.SetLatestMessage("B");
chatModule.SetLatestMessage("C");
```

Then the listener will receive only the last cached value, `"C"`, when execution happens later.

## 3. Scoped Event Bus: `ScopedEventBus`

`ScopedEventBus` uses `int eventId` to manage a group of event instances. It is suitable for modules, features, or pages that want to maintain their own event collection without exposing those events to a global manager.

### Suitable Scenarios

- Page-level, module-level, or session-level events.
- A dynamic group of events created and destroyed together.
- Cases where you do not want to declare a dedicated field for every event.

### Common API

Listener management:

- `AddListener(...)`
- `RemoveListener(...)`
- `RemoveAllListeners(eventId)`
- `Clear()`

Dispatching:

- `Invoke(...)`
- `CollectInvoke(...)`
- `TriggerInvoke()`
- `HoldInvoke(...)`
- `ReleaseInvoke()`

### Basic Example

```csharp
public static class BattleEventId
{
    public const int WaveStart = 1001;
    public const int WaveFinished = 1002;
    public const int UnitHpChanged = 1003;
}

public class BattleController
{
    private readonly ScopedEventBus _bus = new ScopedEventBus();

    public void Init()
    {
        _bus.AddListener(BattleEventId.WaveStart, OnWaveStart);
        _bus.AddListener<int>(BattleEventId.UnitHpChanged, OnUnitHpChanged);
    }

    public void Deinit()
    {
        _bus.Clear();
    }

    public void StartWave()
    {
        _bus.Invoke(BattleEventId.WaveStart);
    }

    public void ChangeUnitHp(int hp)
    {
        _bus.Invoke(BattleEventId.UnitHpChanged, hp);
    }

    private void OnWaveStart()
    {
        Debug.Log("Wave started");
    }

    private void OnUnitHpChanged(int hp)
    {
        Debug.Log($"Unit hp = {hp}");
    }
}
```

### Keep the `eventId` Signature Consistent

Once an `eventId` has been bound to a specific parameter signature, it must keep using that same signature. Otherwise, the system logs an error.

For example:

```csharp
bus.AddListener<int>(1001, OnValueChanged);
bus.Invoke(1001); // Type mismatch error
```

Recommended practice:

- Define `eventId` values centrally with constants or enums.
- Ensure each `eventId` has one unique parameter signature.

## 4. `CollectInvoke` and `HoldInvoke`

`ScopedEventBus` provides two additional delayed-dispatch strategies. They are different from `LaterEvent` and serve different goals.

### `CollectInvoke` + `TriggerInvoke`

Used to collect event calls first and then dispatch all of them in collection order.

```csharp
bus.CollectInvoke(BattleEventId.WaveStart);
bus.CollectInvoke(BattleEventId.UnitHpChanged, 90);
bus.CollectInvoke(BattleEventId.UnitHpChanged, 80);

bus.TriggerInvoke();
```

Characteristics:

- Keeps every collected call.
- Dispatches in queue order.
- Does not deduplicate automatically.

Suitable for:

- Dispatching all accumulated events after a process completes.
- Preserving every intermediate event request.

### `HoldInvoke` + `ReleaseInvoke`

Used to push calls onto a stack first, and when released, only one call is dispatched for each `eventId`.

```csharp
bus.HoldInvoke(BattleEventId.UnitHpChanged, 90);
bus.HoldInvoke(BattleEventId.UnitHpChanged, 80);
bus.HoldInvoke(BattleEventId.WaveStart);

bus.ReleaseInvoke();
```

Characteristics:

- Internally uses a stack, so later pushed calls are considered first.
- The same `eventId` is dispatched only once.
- Suitable for scenarios where intermediate changes happen many times, but only the final release matters.

Typical scenarios:

- Deduplicating UI refresh requests.
- Batch-releasing dirty flags.
- Processes where the same category of event may fire many times, but only one final response is needed.

## 5. Framework-level Events: `EventManager`

`EventManager` provides a set of predefined public events suitable for observing framework runtime state changes.

### Common Event Example

```csharp
private void OnEnable()
{
    EventManager.instance.onPause.AddListener(OnPauseChanged);
    EventManager.instance.onLanguageChange.AddListener(OnLanguageChanged);
    EventManager.instance.onNetConnect.AddListener(OnNetConnected);
}

private void OnDisable()
{
    EventManager.instance.onPause.RemoveListener(OnPauseChanged);
    EventManager.instance.onLanguageChange.RemoveListener(OnLanguageChanged);
    EventManager.instance.onNetConnect.RemoveListener(OnNetConnected);
}

private void OnPauseChanged(bool paused)
{
    Debug.Log($"Paused: {paused}");
}

private void OnLanguageChanged(Language language)
{
    Debug.Log($"Language changed: {language}");
}

private void OnNetConnected()
{
    Debug.Log("Network connected");
}
```

The current `EventManager` mainly contains these categories:

- Gameplay logic: loading, pause, quit, start game, reset game, clear unused assets
- UI: page open/close, window open/close, screen orientation changes, input enable state
- Guidance: guidance start/end
- Language: language switching
- Time scale: replace / pause
- Network: connect / disconnect

If an event belongs only to a specific system, it is better to keep that event field inside the owning system instead of continuing to add it to `EventManager`.

## 6. Usage Recommendations

### 1. Choose the Simplest Event Model First

- Immediate notification: use `LinkEvent`
- Deferred execution: use `LaterEvent`
- Local `eventId` bus: use `ScopedEventBus`

### 2. Always Pair Listener Registration and Removal

It is recommended to handle them in `OnEnable` / `OnDisable` or `Init` / `Deinit`:

```csharp
private void OnEnable()
{
    _event.AddListener(OnEvent);
}

private void OnDisable()
{
    _event.RemoveListener(OnEvent);
}
```

### 3. Use `AddListenerOnce` Only When It Truly Fits

`AddListenerOnce` is suitable for one-time callbacks, not long-lived subscriptions.

### 4. Keep `eventId` Definitions Clear in `ScopedEventBus`

It is recommended to place `eventId` values in a dedicated static class or enum to avoid scattered magic numbers:

```csharp
public static class ShopEventId
{
    public const int GoodsChanged = 2001;
    public const int CurrencyChanged = 2002;
}
```

### 5. Be Aware of `LaterEvent` Overwrite Semantics

For `LaterEvent<T...>`, if it is invoked multiple times before the deferred execution round is processed, only the last written data will actually be broadcast.

---

## 7. Notes

- `ScopedEventBus` supports only 0 to 3 parameters.
- `CollectInvoke` and `HoldInvoke` internally store parameters in `object[]` and dispatch them later according to parameter count.
- `ScopedEventBus` logs an error if an `eventId` is invoked before being registered.
- `ScopedEventBus` also logs an error if the same `eventId` is used with conflicting parameter signatures.
- Under `UNITY_EDITOR`, `LinkEvent` and `LaterEvent` check duplicate listener registration and log an error.
- `LaterEvent` execution depends on `EventManager` being driven normally by the module system.

---

## ✅ Recommended Scenarios

- Use `LinkEvent` for direct notifications between modules.
- Use `LaterEvent` for UI refresh, state consolidation, and delayed notifications that avoid reentrancy.
- Use `ScopedEventBus` for page-level, module-level, and local-lifecycle event groups.
- Use `EventManager` to subscribe to framework-level public state changes.
