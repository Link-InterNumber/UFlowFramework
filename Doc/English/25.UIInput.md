# UI User Device Input Response System

## 1. System Overview

This system provides stack-based input response for Unity UI pages. An input adapter reads a specific input source and produces a unified `InputEvent<TKey>`. `InputStack<TKey>` dispatches events only to the page at the top of the stack, so page logic does not need to depend on the legacy `Input` API or the Unity Input System.

The system is suitable for button, scalar-axis, and two-dimensional directional input. It currently does not provide dedicated event models for pointers, text input, scroll wheels, or multi-touch input.

Key features:

- Provides exclusive input handling for the page at the top of the stack. Events do not bubble to lower pages when the top page is empty or has no listener for the action key.
- Decouples input sources from page response logic through `InputEvent<TKey>`.
- Uses `Dictionary<TKey, InputHandler<TKey>>` for action-key lookup and `Stack<InputPage<TKey>>` for page lifetime management.
- Provides `IInputAdapter<TKey>` as a common stack-access contract for external input adapters.

The `Sample/` directory contains example code only. `LegacyInputAdapter`, `ILegacyInputCapturer<TKey>`, and `MoveCapturer` demonstrate how to connect legacy Unity input, but they are not framework core members. They are referenced below only as integration examples.

### Main Components / Interfaces

- `InputEvent<TKey>`: Describes the input key, event type, state, scalar value, and two-dimensional value.
- `InputPage<TKey>`: Stores the input listeners for one page and implements `IInputPage<TKey>`.
- `IInputPage<TKey>`: Defines the public contract for handling input and managing page listeners.
- `InputStack<TKey>`: Creates, pushes, pops, and dispatches input to the page at the top of the stack.
- `IInputAdapter<TKey>`: Exposes the `InputStack<TKey>` owned by an external input adapter.

### Component Dependencies

```text
External input adapter (example: `Sample/LegacyInputAdapter`)
    |
    |──> IInputAdapter<TKey>
    |
    |──> InputStack<TKey>
    |       |
    |       |──> Func<IInputPage<TKey>> page factory
    |       |
    |       └──> InputPage<TKey>
    |               |
    |               |──> IInputPage<TKey>
    |               |
    |               └──> InputHandler<TKey>
    |
    └──> External input capturer (example: `Sample/MoveCapturer`)
            |
            └──> UnityEngine.Input
```

`InputEvent<TKey>` is the data structure shared by capturers, adapters, and pages. It is not tied to a specific input backend. The adapter and capturer shown in the dependency tree are external integration examples, not framework core types.

## 2. Operation and Optimization

### Initialization and Page Creation

For example, `Sample/LegacyInputAdapter.Awake()` creates an `InputStack<TKey>` and supplies a page factory:

```csharp
new InputStack<LegacyInputKey>(() => new InputPage<LegacyInputKey>())
```

When `PushPage()` is called, the stack creates a page through this factory and pushes it onto the top of the stack. Page creation is therefore injected by the adapter instead of being hard-coded inside `InputStack<TKey>`.

### Event Dispatch

Using `Sample/LegacyInputAdapter.Update()` as an example, the per-frame flow is:

1. The adapter checks whether a current page exists and contains listeners.
2. The adapter iterates over its input capturers.
3. A capturer creates an `InputEvent<TKey>`.
4. `InputStack<TKey>.Dispatch()` obtains the page at the top of the stack.
5. The page looks up an `InputHandler<TKey>` by `actionKey` and invokes its listeners.

`Dispatch()` returns immediately when the stack is empty or the current page is `isEmpty`. Events are not propagated to lower pages.

### Listener Management

`InputPage<TKey>` creates one `InputHandler<TKey>` for each action key. Multiple callbacks can be registered for the same key.

- `HasListener()` reports whether the handler has listeners.
- `RemoveListener()` removes a specific callback and removes the handler from the dictionary when no listeners remain.
- `RemoveAllListener()` removes the handler for a specific key.
- `ClearAll()` disposes all handlers owned by the current page.

### Disposal

`PopPage()` removes the page at the top of the stack and calls its `Dispose()` method. `InputStack.Dispose()` pops and disposes every page, then sets its internal stack to `null`. Public operations on a disposed page throw `ObjectDisposedException`.

### Performance and Memory Characteristics

- Pages and handlers are created on demand; key lookup has an average complexity of $O(1)$.
- Stack operations have an average complexity of $O(1)$.
- `InputEvent<TKey>` is a value type, so passing an event does not require a managed heap allocation by itself.
- The sample adapter uses a regular `for` loop to iterate over capturers; this is an implementation detail of the sample, not a framework requirement.
- Removing the last listener also removes its handler, preventing empty handlers from accumulating in dynamic-key scenarios.

These optimizations do not change event semantics. The sample `MoveCapturer` returns and dispatches a `NoInput` event even when there is no movement input. Pages that do not need this state should filter it in their callbacks.

## 3. Usage

The following example uses `Sample/LegacyInputAdapter` and `Sample/LegacyInputKey` to demonstrate the minimum flow for opening a page, registering a listener, receiving input, and closing the page. These types are sample code, not framework core members.

### 3.1 Create an Adapter

Attach the sample `Sample/LegacyInputAdapter` script to a GameObject in the scene. The sample initializes its input stack and `MoveCapturer` in `Awake()`. A production project can replace it with its own adapter.

### 3.2 Open a Page and Register a Listener

```csharp
using UnityEngine;
using UFlowFramework;
using UFlowFramework.Sample;

public sealed class InventoryPage : MonoBehaviour
{
    private InputPage<LegacyInputKey> _inputPage;

    public void Open(LegacyInputAdapter adapter)
    {
        _inputPage = adapter.inputStack.PushPage();
        _inputPage.AddListener(LegacyInputKey.Move, OnMove);
    }

    private void OnMove(InputEvent<LegacyInputKey> inputEvent)
    {
        if (inputEvent.state != InputEventState.PressThisFrame &&
            inputEvent.state != InputEventState.Hold)
        {
            return;
        }

        Vector2 moveDirection = inputEvent.v2;
        Debug.Log($"Move: {moveDirection}");
    }
}
```

`InputStack<TKey>.AddListener()` can also register a listener on the current top page. Calling `AddListener()` on the page instance is more explicit and avoids accidentally registering on a different page after the stack changes.

### 3.3 Close a Page

When a page closes, the corresponding top page must be popped:

```csharp
public void Close(LegacyInputAdapter adapter)
{
    adapter.inputStack.PopPage();
    _inputPage = null;
}
```

`PopPage()` disposes the page's handlers and callbacks. Do not continue using the saved `InputPage<TKey>` reference after the page has been popped.

### 3.4 Clear Listeners but Keep the Page

If the page must remain at the top of the stack but should temporarily stop responding to input, call:

```csharp
adapter.inputStack.ClearPeekPage();
```

This clears the listeners on the top page without popping the page itself.

## 4. Extension Methods

The framework provides one public extension point:

1. Implement `IInputAdapter<TKey>` to connect a new input source.

`ILegacyInputCapturer<TKey>`, `LegacyInputAdapter`, and `MoveCapturer` under `Sample/` are example code only. If a project uses a similar capturer organization, it may define equivalent interfaces and implementations, but they are not framework public extension points.

### 4.1 Add a Legacy Input Capturer as an Example

The following example implements a usable keyboard capturer and demonstrates the sample interface `ILegacyInputCapturer<TKey>`. This code is an integration example and does not extend the framework core types:

```csharp
using UnityEngine;
using UFlowFramework;

namespace UFlowFramework.Sample
{
    public sealed class FireCapturer : ILegacyInputCapturer<LegacyInputKey>
    {
        public bool TryGetEvent(out InputEvent<LegacyInputKey> inputEvent)
        {
            bool pressed = Input.GetKey(KeyCode.Space);
            inputEvent = InputEvent<LegacyInputKey>.CreateButtonEvent(
                LegacyInputKey.Fire,
                Input.GetKeyDown(KeyCode.Space),
                Input.GetKeyUp(KeyCode.Space),
                pressed);
            return true;
        }

        public void Dispose()
        {
        }
    }
}
```

After adding the capturer to `_capturers` in the sample `LegacyInputAdapter.Awake()`, it is polled during subsequent `Update()` calls. A custom capturer must use the same `TKey` and release any resources it owns in `Dispose()`.

### 4.2 Implement a New Input Adapter

A new adapter should implement `IInputAdapter<TKey>`, create its own `InputStack<TKey>`, convert external input into `InputEvent<TKey>`, and call `Dispatch()`. Input System types should remain in the adapter layer; page code should depend only on `InputPage<TKey>` and `InputEvent<TKey>`.

The repository does not currently contain an actual Input System adapter. A project may add one according to this interface contract, but must not treat the adapters under `Sample/` as built-in implementations or stable public APIs.

Extensions must preserve these invariants:

- Pages and events within an adapter use the same `TKey` type and comparison semantics.
- Input collection, dispatch, and page callbacks run on the Unity main thread.
- An external adapter releases its own `InputStack<TKey>` and input-capture resources during destruction.
- A legacy adapter and a new input adapter must not dispatch the same logical action at the same time.

## 5. Notes and Constraints

### Lifetime

- Create a page through `InputStack<TKey>` before registering listeners.
- Calling methods on `InputStack<TKey>` after `Dispose()` throws `ObjectDisposedException`.
- Calling methods on `InputPage<TKey>` after `Dispose()` also throws `ObjectDisposedException`.
- `PopPage()` closes pages in stack order. Closing a non-top page requires the application to manage its own page-closing order.
- An external input adapter should release the `InputStack<TKey>` and input-capture resources it created during destruction. The sample `LegacyInputAdapter` is only a reference implementation.

### Top-of-Stack Behavior

Input is sent only to the page at the top of the stack. Even when that page has no listener for the current action key, the event is not passed to lower pages.

### Input State

`MoveCapturer` in the sample accumulates opposite directions. Pressing `W` and `S` together, or `A` and `D` together, cancels the corresponding component. It also generates a `NoInput` event while there is no movement.

### Null and Runtime Errors

The sample adapter assumes that `Awake()` has completed and `OnDestroy()` runs only once. Do not access `inputStack` before adapter initialization is complete or after destruction. If a page callback changes the page stack, ensure that it does not continue using a page reference that has already been popped.

### Threading

The sample `LegacyInputAdapter` reads Unity input APIs and dispatches events from `Update()`. Input collection and page callbacks should therefore run on the Unity main thread. Do not call `Dispatch()` directly from a background thread.

### API Consistency

The current signature of `CreateButtonEvent()` is:

```text
CreateButtonEvent(TKey actionKey, bool isPressThisFrame,
                  bool isReleaseThisFrame, bool pressed)
```

It does not accept an `InputEventType` argument. The method always creates an event with `InputEventType.Button`. New documentation examples should follow the actual method signature.

## 6. Recommended Scenarios

### Exclusive UI Page Input

Push a new page when opening an inventory, settings, or pause screen so navigation input affects only the current page.

### Layered Dialogs

Push a confirmation dialog on top of an inventory page to prevent the lower page from receiving the same input.

### Input Backend Replacement

Because page code depends only on the unified `InputEvent<TKey>`, the legacy input capturer can be replaced or another adapter can be added without changing page callbacks.

### Temporary Input Blocking

Push a page without listeners to block lower pages temporarily, then pop it to restore the page underneath.

### Not Recommended

This system is not suitable for broadcast input to multiple pages, event bubbling to lower pages, background-thread input handling, or complex gestures and text input. Those requirements need additional propagation rules, thread scheduling, or dedicated input event models.
