# 🔴 RedPoint System

## ✨ Features

1. **Modular design**: The RedPoint system is implemented in a modular way, making it easy to extend and maintain.  
2. **Tree structure**: Supports parent-child relationships; a child node's state affects its parent.  
3. **Real-time updates**: When a node's state changes, related components are automatically notified to update their display.  
4. **Lightweight and efficient**: Uses an event-driven mechanism to reduce unnecessary performance overhead.

## 🛠 Overview

- **Red dot display control**: Dynamically show or hide red dots based on node state.  
- **Notification value management**: Supports showing notification counts and custom values.  
- **Parent-child binding**: Supports setting parent-child relationships where child states influence parents.  
- **Event registration and callbacks**: External components can register callbacks to listen for node state changes.  
- **Visual editor**: `NotifyInspector` provides a visual tree view and real-time debugging for the RedPoint system.

## 📖 Usage

### 1. Define notification types

Define notification types in `NotifyType.cs`.  
You can also configure them in the Editor with the `Notify Grap` visual tool (see section 6).

```csharp
public enum NotifyType
{
    Root = 0,
    A,
    B,
    C,
    // add more types...
}
```

------

### 2. Initialize the RedPoint system

Initialize nodes in `NotifyManager`'s `OnInit` method and bind parent-child relationships via `BindNodes`.  
You can also configure this with the `Notify Grap` visual tool in the Editor (see section 6).

```csharp
private partial void BindNodes()
{
    SetNodeParent(NotifyType.B, NotifyType.A);
    SetNodeParent(NotifyType.C, NotifyType.B);
    // add more bindings...
}
```

------

### 3. Set notification state

By default, only leaf nodes (nodes without children) can be modified directly. Non-leaf nodes are driven by their children.  
Use `NotifyManager`'s `SetNotify` to set a node's state:

```csharp
// Suppose the node chain is Root -> C -> D, where D is the leaf node of this branch

// Directly modifying C will log an error in the console and the update will fail
NotifyManager.instance.SetNotify(NotifyType.C, true, 10);

// Modifying D succeeds and will automatically update C up the branch
NotifyManager.instance.SetNotify(NotifyType.D, true, 10);
```

Developers can also use `ForceNotify` to force-update any node. However, if that node has children, its children will recalculate their states on the next update.

```csharp
// Suppose the node chain is Root -> C -> D, where D is the leaf node of this branch

// Forcibly modify C. Root and C will update, but D will not; D may not match C
NotifyManager.instance.ForceNotify(NotifyType.C, true, 10);
var isOnByForce = NotifyManager.instance.IsNotifyOn(NotifyType.C, out var notifyNumByForce);
Debug.Log($"C is On = {isOnByForce}, notifyNum = {notifyNumByForce}"); // --> C is On = true, notifyNum = 0;

// Now modify the child; C's state will refresh
NotifyManager.instance.SetNotify(NotifyType.D, false, 15);
var isCOn = NotifyManager.instance.IsNotifyOn(NotifyType.C, out var notifyNum);
Debug.Log($"C is On = {isCOn}, notifyNum = {notifyNum}"); // --> C is On = false, notifyNum = 15;
```

------

### 4. Register callbacks

Register callbacks in components that need to listen for red dot changes:

```csharp
private void Awake()
{
    NotifyManager.instance.Register(NotifyType.C, OnNotifyChanged);
}

private void OnDestroy()
{
    NotifyManager.instance.UnRegister(NotifyType.C, OnNotifyChanged);
}

private void OnNotifyChanged(bool isOn, int notifyNum, int notifyValue)
{
    // do something...
}
```

------

### 5. Use the Notifier component

Attach the `Notifier` script to a UI object and set the corresponding `NotifyType`. The system will automatically update the red dot display.

------

### 6. Use the Notify Grap visual editor

`Notify Grap` provides a visual editor for the red dot tree.  
Open the tree view via Tools > Notify > Editor Graph.

![Notify Editor Graph](../img/NotifyEditorGraph.png "Magic Gardens")

`Notify Grap` reads the contents of *NotifyManager_Binding.cs* (default path: Assets/UFlowFramework/Systems/NotifySystem/NotifyManager_Binding.cs) to initialize the tree based on existing configuration.

Features:
- **Visual editing**: Configure parent-child relationships by connecting nodes.  
- **Configurable output paths**: You can set custom output paths for `NotifyManager_Binding.cs` and `NotifyType.cs` using the Enum Cs Path and Binding Cs Path fields at the top of the window.  
- **Auto-generate scripts**: Click Save Graph to convert the graph into C# code and save `NotifyManager_Binding.cs` and `NotifyType.cs`.  
- **Duplicate node check**: The tool checks for duplicate node names when saving.

------

### 7. Use the Notify Inspector debug tool

`Notify Inspector` offers a visual tree and real-time debugging for the RedPoint system.  
Open it via Tools > Notify > TreeView Window in the Unity Editor.

Features:
- **Tree view**: Shows parent-child relationships of nodes.  
- **Real-time state**: Displays each node's IsOn state, notification count, and notification value.  
- **Refresh button**: Manually refresh the view with the Refresh button.  
- **Search**: Quickly locate nodes using the search box.

Use cases:
- Debug parent-child relationships.  
- Inspect real-time states and value changes.  
- Quickly find and analyze problematic nodes.

------

## ⚠ Notes

1. **Avoid cyclic bindings**: Ensure parent-child bindings do not create cycles (the tool includes cycle checks; cycles can result in an incomplete tree).  
2. **Child-driven restriction**: If a node has children, you cannot set its state directly; it must be driven by its children.  
3. **Unregister events**: Be sure to call UnRegister when objects are destroyed to avoid memory leaks.  
4. **Default root node**: `NotifyType.Root` is the default root node and should not be manipulated directly.  

Follow the steps above to integrate and use the RedPoint system to improve your game's user experience.
