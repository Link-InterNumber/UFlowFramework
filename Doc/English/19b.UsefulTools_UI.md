# 🖥️ UI Components

## 1. ButtonEx

### ButtonEx Features

`ButtonEx` is a custom UI component that extends Unity's `Button`, providing additional features such as long-press detection and repeated long-press event triggering. It is suitable for button scenarios that require enhanced interaction capabilities.

1. **Long-Press Detection**:
    - Supports detecting long-press actions on the button.
    - Allows setting the time threshold for long-press triggering.

2. **Long-Press Repeat Trigger**:
    - Supports repeatedly triggering events at fixed intervals during a long-press.

3. **Long-Press Events**:
    - `onLongPress`: Event triggered when long-press is detected.
    - `onLongPressUp`: Event triggered when long-press ends.

4. **Custom Properties**:
    - `enableLongPress`: Whether to enable long-press functionality.
    - `longPressRepeat`: Whether to enable repeated long-press triggering.
    - `longPressStartTime`: Time threshold for starting long-press.
    - `longPressTriggerTime`: Time threshold for triggering long-press.
    - `longPressIntervalTime`: Interval time for repeated long-press triggering.

---

### Usage

#### 1. Add ButtonEx to the Scene

- In the Unity Editor, right-click in the Hierarchy view and select `GameObject > UI > ButtonEx` to add a `ButtonEx` component.

#### 2. Configure Long-Press Functionality

- In the `Inspector` panel, check `Enable Long Press`.
- Configure the following parameters:
    - `Long Press Start Time`: Set the time threshold (in seconds) for starting long-press. After this time, the `onClick` event will not be triggered.
    - `Long Press Trigger Time`: Set the time threshold (in seconds) for triggering the `onLongPress` event.
    - `Long Press Interval Time` (optional): Set the interval (in seconds) for repeated triggering of `onLongPress` after the long-press is triggered.

#### 3. Bind Events

- In the `Inspector` panel, expand `On Long Press` and `On Long Press Up` to bind the desired events.

#### 4. Example Code

```csharp
using UnityEngine;

public class ButtonExExample : MonoBehaviour
{
    public ButtonEx buttonEx;

    private void Start()
    {
        buttonEx.onLongPress.AddListener(OnLongPress);
        buttonEx.onLongPressUp.AddListener(OnLongPressUp);
    }

    private void OnLongPress()
    {
        Debug.Log("Button is being long-pressed!");
    }

    private void OnLongPressUp()
    {
        Debug.Log("Button long-press released!");
    }
}
```

### Notes

- If long-press is enabled, short-press events (such as `OnClick`) will be blocked after the long-press starts.
- You can use `ButtonExEditor` to quickly add sound effect triggers (such as playing sound when pressed or released).

## 4. Pluggable Screen Input Detection

### Introduction

`ScreenInputMinitor` is a MonoBehaviour component provided by UFlow for unified management and dispatching of screen input events (such as tap, drag, pinch, long-press, etc.). It supports registration, unregistration, enabling, disabling, and event listening for multiple input handlers, making it easy for developers to flexibly extend and respond to different types of touch operations in their projects.

### Main Features

- Register/unregister different types of input handlers (such as tap, drag, pinch, etc.).
- Support dynamic addition and removal of input event listeners.
- Automatically enable/disable all input handlers during the lifecycle.
- Provide convenient interfaces to check if an input handler is registered and to get its instance.
- Support Unity's new Input System (EnhancedTouch).
- Built-in test methods for easy debugging of various input events.

### Usage

Attach `ScreenInputMinitor` to any GameObject in the scene.
You can register input handlers using generic methods. For example, to register a tap handler:

```csharp
screenInputMinitor.RegisterInputHandle<ScreenTapHandle>();
```

Or pass in an instance directly:

```csharp
var tapHandle = new ScreenTapHandle();
screenInputMinitor.RegisterInputHandle(tapHandle);
```

Add event listeners for a specific type of input handler:
```csharp
screenInputMinitor.AddListener<ScreenTapHandle>(OnTapEvent);
```

Example event callback method:

```csharp
void OnTapEvent(ScreenInputEvent inputEvent)
{
    Debug.Log($"Tap at: {inputEvent.screenPos}");
}
```

Enable/disable input handlers:

```csharp
screenInputMinitor.EnableInput<ScreenTapHandle>();
screenInputMinitor.DisableInput<ScreenTapHandle>();
```

Unregister input handlers:

```csharp
screenInputMinitor.UnregisterInputHandle<ScreenTapHandle>();
```

Check and get handlers:

```csharp
bool isRegistered = screenInputMinitor.IsInputHandleRegistered<ScreenTapHandle>();

if (screenInputMinitor.TryGetInputHandle<ScreenTapHandle>(out var handle))
{
    // Use handle
}
```

### Notes

- Input handlers must implement the `IScreenInputHandle` interface.
- Event listeners must use the `ScreenInputEventHandler` delegate.
- If you enable Unity's new Input System, make sure the `ENABLE_INPUT_SYSTEM` macro is defined.

**Example: Register and listen for tap events**

```csharp
// Register tap handler
screenInputMinitor.RegisterInputHandle<ScreenTapHandle>();

// Add tap event listener
screenInputMinitor.AddListener<ScreenTapHandle>(OnTapEvent);

void OnTapEvent(ScreenInputEvent inputEvent)
{
    Debug.Log($"Tap Detected: {inputEvent.screenPos}");
}
```

To extend more input types, simply implement a new `IScreenInputHandle` and register it.

## 5. AspectRatioLayout (Proportional Size Adaptation)

`AspectRatioLayout` scales a `RectTransform`'s `sizeDelta` according to the relationship between the design resolution and the current UI display size. It is suitable for backgrounds, decorative images, full-screen overlays, and other UI elements whose width and height need to follow the screen independently.

### How It Works

The component caches the initial `sizeDelta` in `Awake`, uses `ConstSetting.DefaultUISize` as the design size, and uses `UIManager.ScreenSize` as the current size. Given an initial size of `initSize`, a design size of `defaultUISize`, and a current size of `screenSize`:

```text
Adapted width  = screenSize.x * (initSize.x / defaultUISize.x)
Adapted height = screenSize.y * (initSize.y / defaultUISize.y)
```

### Inspector Settings

- `match`: The axes to adapt; flags can be combined.
  - `Width`: Adapts only the width to the current UI width.
  - `Height`: Adapts only the height to the current UI height.
  - `Width | Height`: Adapts both axes independently. This is the default value.

### Usage

1. Add `AspectRatioLayout` to the target UI object, which must have a `RectTransform`.
2. Configure the object's initial `Width` and `Height` at the design resolution.
3. Select the desired axes in `match`:
   - Use `Width` for a horizontally stretching background.
   - Use `Height` for an area that should stretch with screen height.
   - Use `Width | Height` for an overlay that should scale with both screen dimensions.
4. The component applies the adapted size when the object is enabled or when its Canvas hierarchy changes.

### Notes

- The initial size is cached only in `Awake`. Changes made to `sizeDelta` later by other scripts do not become the new design size.
- The current implementation does not continuously refresh in response to screen-resolution changes. For runtime orientation changes, window resizing, or display-area changes, re-enable the object from an external flow or extend the component with a manual refresh method.
- The component writes directly to `RectTransform.sizeDelta`. Do not combine it with other components that control the same size unless their update order is deliberate.

## 6. AspectRatioScaler (Aspect-Ratio Scale Adaptation)

`AspectRatioScaler` adjusts a target `RectTransform`'s `localScale` according to the aspect-ratio difference between the current display area and `ConstSetting.DefaultUISize`. It is useful for UI that should retain its base layout size while becoming visually larger or smaller on ultra-wide or narrow screens, such as character displays, centered dialogs, or special decorations.

### How It Works

The component obtains the display size from `UICamera.instance.currentScreen` when available; otherwise, it falls back to `Screen.width` and `Screen.height`. It caches the initial `localScale` in `Awake` and calculates the scale factor as follows:

```text
Current ratio = displayWidth / displayHeight
Design ratio  = DefaultUISize.x / DefaultUISize.y

adaptMatch = Width:  scale factor = current ratio / design ratio
adaptMatch = Height: scale factor = design ratio / current ratio
```

The factor is clamped between `minScale` and `maxScale`, then multiplied by the initial X and Y scale values.

### Inspector Settings

- `adaptMatch`
  - `Width`: Uses width-based aspect-ratio adaptation; on wider screens the element usually becomes larger.
  - `Height`: Uses the inverse, height-based adaptation; on wider screens the element usually becomes smaller.
- `minScale`: The minimum permitted scale factor. Default: `0.6`.
- `maxScale`: The maximum permitted scale factor. Default: `2`.

### Usage

1. Add `AspectRatioScaler` to the target UI object and set its design-state `localScale` first.
2. Select `adaptMatch` according to the intended visual behavior:
   - Choose `Width` when the element should appear relatively larger on wide screens.
   - Choose `Height` when the element should appear relatively smaller on wide screens or should avoid occupying too much horizontal space.
3. Set sensible `minScale` and `maxScale` values to prevent excessive scaling on extreme aspect ratios.
4. The component refreshes when enabled. If the display area changes at runtime, call:

```csharp
aspectRatioScaler.ForceUpdate();
```

### Notes

- The component checks for display-size changes in `OnRectTransformDimensionsChange`. If an external `UICamera` updates its display-size data without changing the RectTransform, call `ForceUpdate()` explicitly.
- Only `localScale.x` and `localScale.y` are changed; the current `localScale.z` value is preserved.
- The initial scale is cached only in `Awake`. Avoid having multiple runtime components continuously write to `localScale`.

## 7. SafeAreaFitter (Safe-Area Adaptation)

`SafeAreaFitter` keeps UI inside `Screen.safeArea`, avoiding notches, camera cutouts, rounded corners, and bottom gesture areas. It is suitable for page roots, top bars, bottom bars, and containers that must remain inside the safe display region.

### How It Works

The component reads `Screen.safeArea`, calculates offsets using `UIManager.PixelScale` and `UIManager.ScreenSize`, then sets the target `RectTransform` to stretch across its parent:

```csharp
root.anchorMin = Vector2.zero;
root.anchorMax = Vector2.one;
root.offsetMin = offsetMin;
root.offsetMax = offsetMax;
```

This aligns the UI's visible area with the device safe area.

### Inspector Setting and Public Methods

- `runInAutomatic`: Whether to fit automatically. Enabled by default.
  - When enabled, fitting runs in `OnEnable` and whenever the Canvas hierarchy changes.
  - When disabled, refresh it manually from game code.
- `ForceUpdate()`: Immediately reads and applies the current safe area.
- `LogSafeArea()`: Logs the current `Screen.safeArea`, anchors, and offsets for device-side troubleshooting.

### Usage

1. Attach `SafeAreaFitter` to the UI root that requires safe-area fitting.
2. Keep `runInAutomatic` enabled in most cases.
3. If the page changes orientation, resolution, or safe-area state at runtime, refresh it explicitly:

```csharp
safeAreaFitter.ForceUpdate();
```

4. To inspect fitting data on a device, invoke `LogSafeArea()` from the Inspector or call it from code and inspect the log.

### Notes

- This component forces `anchorMin` to `(0, 0)`, `anchorMax` to `(1, 1)`, and overwrites `offsetMin` and `offsetMax`. Do not attach it to an ordinary child UI element that relies on custom anchors or offsets.
- It is recommended to attach it to the outermost safe-area container, then lay out top bars, bottom bars, and content as child objects.
- `Screen.safeArea` may differ between the Editor and actual devices. Validate notch, cutout, and gesture-area handling on target devices.
- The component depends on `UIManager.PixelScale` and `UIManager.ScreenSize` being initialized correctly. Ensure the UI manager is ready before showing the page.
