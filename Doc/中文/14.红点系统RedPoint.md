# 🔴 红点系统（RedPoint System）

## 1. 系统概述

红点系统用于管理 UI 红点的显示状态、通知数量和附加数值。系统以**枚举类型作为通知分组**，每个枚举分组拥有独立的节点数组和父子关系树。

### 系统特点

1. **多枚举分组**：不同的红点枚举类型互相隔离，可以分别管理不同业务模块的红点节点。
2. **树状聚合**：子节点状态向父节点聚合，父节点的数量和值由有效子节点重新计算。
3. **跨分组聚合**：不同枚举分组中的节点可以建立父子关系，跨组子节点的状态、数量和值可以继续向父节点聚合。
4. **事件驱动更新**：节点发生变化时，仅通知注册在该节点上的监听器。
5. **索引访问高效**：枚举值通过 `EnumNotifyIndexTranslator<T>` 转换为 `Enum.GetValues()` 对应的数组索引。
6. **编辑器辅助配置**：`NotifyGraphWindow`、`NotifyTreeViewWindow` 和 `NotifierEditor` 提供配置、调试和组件绑定支持。

### 主要组件 / 接口

- `NotifyManager`：管理所有枚举分组、节点状态、父子关系和回调注册。
- `EnumNotifyIndexTranslator<T>`：将枚举值与 `Enum.GetValues()` 数组索引互相转换。
- `INotifyBindPreset`：用于自动发现并绑定通知分组及节点关系的预设接口。
- `Notifier`：挂载在 UI 对象上，根据序列化的枚举类型名称和节点索引显示红点。
- `NotifyGraphWindow`：可视化编辑枚举节点和父子关系，并生成绑定代码。
- `NotifyTreeViewWindow`：运行时查看已注册枚举分组的节点树和实时状态。
- `NotifierEditor`：为 `Notifier` 提供类型搜索和枚举值选择界面。

### 组件依赖关系

```text
NotifyGraphWindow
    |
    └──> NotifyManager / 生成的 INotifyBindPreset
                    |
                    ├──> INotifyBindPreset
                    |       └──> NotifyManager.SetNotifyGroup / SetNodeParent / SetNodeParentCrossGroup
                    |
                    ├──> EnumNotifyIndexTranslator<T>
                    |       └──> Enum.GetValues()
                    |
                    └──> 按 Type 隔离的 NotifyNode[]

Notifier
    |
    ├──> ReflectionUtils.GetTypeByName
    └──> NotifyManager

NotifierEditor
    |
    └──> ReflectionUtils.GetTypeByName / 反射枚举类型

NotifyTreeViewWindow
    └──> NotifyManager
```

## 2. 工作原理与优化

### 初始化与分组

`NotifyManager.OnInit()` 初始化按 `Type` 分组的节点表和转换器表，然后通过反射查找可实例化的 `INotifyBindPreset` 实例并执行 `BindNodes`。

通知分组可以通过泛型或 `Type` 注册：

- `SetNotifyGroup<T>()`：适合代码中直接使用枚举类型的场景。
- `SetNotifyGroupByType(Type)`：适合通过反射、配置或编辑器绑定的场景。

重复注册同一个枚举类型不会创建第二份节点表。每个节点默认没有父节点、未激活、数量和值均为 `0`。

### 索引和节点关系

每个枚举分组对应一个 `NotifyNode[]`。数组下标不是枚举的底层数值，而是该值在 `Enum.GetValues(enumType)` 返回数组中的位置。`EnumNotifyIndexTranslator<T>` 负责两者之间的转换，因此即使枚举底层数值不连续，也必须使用转换后的索引。

父子关系保存在节点的 `parent` 和 `children` 中。一个节点最多有一个父节点，但可以拥有多个子节点。设置父节点时会移除旧父节点的子节点引用，并检查是否形成循环。

除了同一枚举分组内的父子关系，系统还支持通过 `SetNodeParentCrossGroup<T, K>` 建立跨枚举分组的父子关系。一个跨组子节点只能拥有一个跨组父节点，而一个父节点可以关联多个来自其他分组的子节点。

跨分组关系单独保存在 `otherGroupParent` 和 `otherGroupChildren` 中，不会与同组的 `parent`、`children` 混用。父节点重新计算时会同时统计同组和跨组子节点；子节点状态变化后，也会沿跨组父节点继续向上更新。

### 状态计算

- 叶节点可以通过 `SetNotify` 设置状态。
- 有子节点的节点不能通过 `SetNotify` 直接设置，而是由子节点重新计算。
- 父节点的 `notifyNumber` 是当前有效子节点数量之和，`notifyValue` 是当前有效子节点值之和。
- 跨组父节点使用相同的聚合规则，会将同组和跨组的有效子节点一起计算。
- 节点的 `isOn` 等价于 `notifyNumber > 0`。
- `ForceNotify` 可以临时强制设置任意节点，但有子节点的节点可能与子节点状态不一致；后续重新计算时会恢复为子节点聚合结果。

### Notifier 绑定

`Notifier` 不再依赖固定的 `NotifyType` 字段，而是序列化：

- `typeName`：枚举类型名称。`NotifierEditor` 当前保存的是程序集限定名，运行时由 `ReflectionUtils.GetTypeByName` 解析。
- `notifyTypeIndex`：枚举值在 `Enum.GetValues(enumType)` 中的数组索引。

`Notifier.Awake()` 解析类型并注册回调，`OnEnable()` 读取当前状态，`OnDestroy()` 注销回调。

## 3. 使用方法

### 3.1 定义枚举分组

每个业务分组使用一个独立枚举，并建议保留名为 `Root` 的根节点。枚举声明顺序决定 `Enum.GetValues()` 的索引顺序。

```csharp
namespace Game.UI
{
    public enum MailNotifyType
    {
        Root = 0,
        Mail,
        MailUnread,
        MailReward
    }
}
```

### 3.2 注册分组并绑定关系

可以在实现 `INotifyBindPreset` 的预设中注册分组和父子关系。预设会在 `NotifyManager.OnInit()` 中被自动发现和执行。

```csharp
using PowerCellStudio;

public sealed class MailNotifyPreset : INotifyBindPreset
{
    public void BindNodes(NotifyManager manager)
    {
        manager.SetNotifyGroup<MailNotifyType>();
        manager.SetNodeParent(MailNotifyType.MailUnread, MailNotifyType.Mail);
        manager.SetNodeParent(MailNotifyType.MailReward, MailNotifyType.Mail);
        manager.SetNodeParent(MailNotifyType.Mail, MailNotifyType.Root);
    }
}
```

如果分组只在运行时通过 `Type` 获取，也可以调用 `manager.SetNotifyGroupByType(enumType)`。该方法要求传入的 `Type` 非空且确实是枚举类型。

跨分组绑定使用两个不同的枚举类型。下面示例将任务分组中的节点绑定到邮件分组中的根节点：

```csharp
manager.SetNotifyGroup<MailNotifyType>();
manager.SetNotifyGroup<TaskNotifyType>();

manager.SetNodeParentCrossGroup(
    TaskNotifyType.Reward,
    MailNotifyType.Root);
```

建立关系后，调用 `SetNotify(TaskNotifyType.Reward, true, 1)` 会使 `MailNotifyType.Root` 重新计算，并将跨组子节点计入父节点的通知数量和值。需要更换或解除跨组父节点时，可以调用：

```csharp
manager.RemoveNodeParentCrossGroup(TaskNotifyType.Reward);
```

### 3.3 设置叶节点状态

```csharp
NotifyManager.instance.SetNotify(MailNotifyType.MailUnread, true, 1);

var isOn = NotifyManager.instance.IsNotifyOn(
    MailNotifyType.Mail,
    out var notifyNumber);
```

`Mail` 有子节点，因此它的状态和数量会由 `MailUnread`、`MailReward` 等子节点聚合得到。

### 3.4 注册监听

```csharp
private void Awake()
{
    NotifyManager.instance.Register(MailNotifyType.Mail, OnNotifyChanged);
}

private void OnDestroy()
{
    NotifyManager.instance.UnRegister(MailNotifyType.Mail, OnNotifyChanged);
}

private void OnNotifyChanged(bool isOn, int notifyNumber, int notifyValue)
{
    // 更新 UI
}
```

### 3.5 使用 Notifier

将 `Notifier` 挂载到 UI 对象后，在 Inspector 中：

1. 在 `typeName` 搜索框输入枚举名或命名空间中的部分名称。
2. 从搜索结果中选择枚举类型。
3. 在枚举值下拉框中选择节点。
4. `NotifierEditor` 会将类型保存到 `typeName`，并将节点在 `Enum.GetValues()` 中的索引保存到 `notifyTypeIndex`。
5. 按需设置 `redPoint`、`numberTxt` 和 `valueTxt`。

### 3.6 调试通知树

在 Unity 中打开：

`Tools > UFlow > Notify > TreeView Window`

运行时窗口顶部会列出已注册枚举分组按钮。切换分组后，可以查看对应的树状结构、`IsOn`、通知数量和通知值，并使用搜索框定位节点。

### 3.7 使用红点关系可视化窗口

编辑器下可以使用 `NotifyGraphWindow` 以节点图方式编辑同组红点节点及父子关系，并生成枚举和绑定代码。

打开方式：

`Tools > UFlow > Notify > Graph Window`

基本流程：

1. 填写 `Namespace` 和 `Enum Type`。
2. 设置 `Enum Cs Path` 与 `Binding Cs Path`。
3. 通过图中的右键菜单创建节点；默认会创建 `Root` 节点。
4. 在节点的 `Type Name` 中修改节点名称。
5. 将父节点的 `Children` 输出端连接到子节点的 `Parent` 输入端，建立父子关系。
6. 使用 `Check Node` 检查重复名称，使用 `Auto Layout` 整理布局，使用 `Find Node` 查找节点。
7. 点击 `Save Graph` 保存图关系，并生成枚举文件和绑定脚本。

窗口可以读取已选择的绑定脚本并恢复关系。当前图形编辑器主要用于编辑单个枚举分组内的关系；跨枚举分组关系仍需在绑定预设中手动调用 `SetNodeParentCrossGroup<T, K>` 配置。

在 Unity 中打开：

`Tools > UFlow > Notify > TreeView Window`

运行时窗口顶部会列出已注册的枚举分组按钮。切换分组后，可以查看对应的树状结构、`IsOn`、通知数量和通知值，并使用搜索框定位节点。

## 4. 扩展方法

### 使用 `INotifyBindPreset` 扩展分组

`INotifyBindPreset` 是当前系统提供的主要公共扩展点。实现类必须能够被反射实例化，并在 `BindNodes` 中完成分组注册和关系绑定。

```csharp
public sealed class RoleNotifyPreset : INotifyBindPreset
{
    public void BindNodes(NotifyManager manager)
    {
        manager.SetNotifyGroup<RoleNotifyType>();
        manager.SetNodeParent(RoleNotifyType.LevelUp, RoleNotifyType.Role);
        manager.SetNodeParent(RoleNotifyType.Role, RoleNotifyType.Root);
    }
}
```

当前系统未提供自定义节点数据类型或自定义聚合算法的公共扩展接口。若需要改变数量和值的聚合规则，需要修改 `NotifyManager` 的实现。

## 5. 注意事项

1. **必须保证类型可解析**：`Notifier.typeName` 必须能由 `ReflectionUtils.GetTypeByName` 解析，并且解析结果必须是枚举。类型重命名、移动程序集或删除枚举后，需要重新设置 `Notifier`。
2. **不要手动填写错误索引**：`notifyTypeIndex` 必须是对应枚举值在 `Enum.GetValues(enumType)` 中的索引，不是枚举底层数值。修改枚举声明顺序后，应重新检查 `Notifier` 配置。
3. **分组必须先注册**：调用状态、关系或回调 API 前，应确保对应枚举分组已经注册。泛型 `Register` 会尝试自动注册分组；预设方式仍建议在初始化阶段显式注册。
4. **只设置叶节点**：有子节点的节点由子节点驱动，直接调用 `SetNotify` 会记录错误并忽略更新。
5. **谨慎使用 `ForceNotify`**：强制状态可能与子节点不一致，只适合调试或确实需要覆盖聚合状态的场景。
6. **避免循环关系**：不要形成节点自身指向自身或祖先节点的循环。系统会检查并拒绝产生循环的绑定。
7. **跨组关系方向**：`SetNodeParentCrossGroup(child, parent)` 的第一个参数是子节点，第二个参数是父节点；两个节点必须属于不同的枚举分组。
8. **跨组关系约束**：一个节点只能拥有一个跨组父节点；设置新的跨组父节点时，旧的跨组父关系会被移除。父节点可以同时拥有同组和跨组子节点。
9. **避免跨组循环**：跨组关系也不能形成循环，建议在初始化或绑定预设中集中建立关系。
10. **及时注销回调**：手动注册的回调必须在对象销毁或不再使用时调用 `UnRegister`。`Notifier` 会在 `OnDestroy` 中自动注销。
11. **初始化顺序**：`NotifyManager` 依赖其模块初始化流程建立分组；不要在初始化完成前读取通知状态或建立跨组关系。
12. **编辑器窗口要求运行时状态**：`NotifyTreeViewWindow` 用于查看运行时节点状态，应在 Play Mode 下使用。
13. **清理行为**：`ClearAll()` 会清除所有分组的状态、同组及跨组父子关系和回调监听，调用后需要重新绑定关系并重新注册监听。

## 6. 推荐使用场景

- **邮件、任务、奖励等独立业务模块**：每个模块使用独立枚举分组，避免节点名称和状态互相污染。
- **多层菜单红点聚合**：叶节点表示具体条件，父节点自动汇总数量和值。
- **全局红点与业务红点联动**：将邮件、任务、活动等业务分组的节点聚合到公共导航或主界面分组，避免把所有业务节点放进同一个枚举。
- **动态 UI 列表**：使用 `Notifier` 或 `NotifyManager.AddNotifer` 根据枚举节点复用红点 UI。
- **运行时调试**：使用 `NotifyTreeViewWindow` 检查分组、父子关系和实时状态。
- **代码生成和团队协作**：使用 `NotifyGraphWindow` 维护枚举节点和预设绑定关系。

该系统适合由枚举标识、状态相对稳定且需要父子聚合的通知树。不适合直接作为任意复杂规则引擎；复杂业务条件应先在业务层计算，再通过叶节点调用 `SetNotify`。
