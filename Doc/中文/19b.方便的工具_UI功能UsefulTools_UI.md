# UI组件

## 1. ButtonEx

### ButtonEx 功能

`ButtonEx` 是一个扩展自 Unity `Button` 的自定义 UI 组件，提供了额外的功能，如长按检测和长按重复触发事件。它适用于需要增强交互功能的按钮场景。

1. **长按检测**：
    - 支持检测按钮的长按操作。
    - 可设置长按触发的时间阈值。

2. **长按重复触发**：
    - 支持在长按状态下以固定间隔重复触发事件。

3. **长按事件**：
    - `onLongPress`：长按触发的事件。
    - `onLongPressUp`：长按结束时触发的事件。

4. **自定义属性**：
    - `enableLongPress`：是否启用长按功能。
    - `longPressRepeat`：是否启用长按重复触发。
    - `longPressStartTime`：长按开始的时间阈值。
    - `longPressTriggerTime`：长按触发的时间阈值。
    - `longPressIntervalTime`：长按重复触发的时间间隔。

---

### 使用方法

#### 1. 添加 ButtonEx 到场景

- 在 Unity 编辑器中，右键点击层级视图，选择 `GameObject > UI > ButtonEx`，即可添加一个 `ButtonEx` 组件。

#### 2. 设置长按功能

- 在 `Inspector` 面板中，勾选 `Enable Long Press`。
- 配置以下参数：
    - `Long Press Start Time`：设置判断长按开始的时间阈值（单位：秒），按下达到这个时间后，`onClick` 事件将无法触发。
    - `Long Press Trigger Time`：设置长按触发的时间阈值（单位：秒），达到这个时间后将触发 `onLongPress` 事件。
    - `Long Press Interval Time`（可选）：设置长按重复触发的时间间隔（单位：秒），达到长按触发时间后，每隔X秒重复触发
      `onLongPress` 事件。

#### 3. 绑定事件

- 在 `Inspector` 面板中，展开 `On Long Press` 和 `On Long Press Up`，绑定需要触发的事件。

#### 4. 示例代码

```csharp
using UnityEngine;

public class ButtonExExample : MonoBehaviour
{
    public ButtonEx buttonEx;

    private void Start()
    {
        buttonEx.onLongPress.AddListener(OnLongPress);
        buttonEx.onLongPressUp.AddListener(OnLongPressUp);
    }

    private void OnLongPress()
    {
        Debug.Log("Button is being long-pressed!");
    }

    private void OnLongPressUp()
    {
        Debug.Log("Button long-press released!");
    }
}
```

### 注意事项

- 如果启用了长按功能，短按事件（如 `OnClick`）将在长按开始后被屏蔽。
- 可通过 `ButtonExEditor` 快速添加音效触发器（如按下或释放时播放音效）。

## 4. 可插拔屏幕输入检测

### 简介

`ScreenInputMinitor` 是 UFlow 提供的一个 MonoBehaviour 组件，用于统一管理和分发屏幕输入事件（如点击、拖拽、缩放、长按等）。它支持多种输入处理器的注册、注销、启用、禁用和事件监听，方便开发者在项目中灵活扩展和响应不同类型的触控操作。

### 主要功能

- 注册/注销不同类型的输入处理器（如点击、拖拽、缩放等）。
- 支持动态添加和移除输入事件监听器。
- 自动在生命周期内启用/禁用所有输入处理器。
- 提供便捷的接口判断输入处理器是否已注册，并获取实例。
- 支持 Unity 新输入系统（EnhancedTouch）。
- 内置测试方法，方便调试各类输入事件。

### 使用方法

将 `ScreenInputMinitor` 挂载到场景中的任意 GameObject 上。
可以通过泛型方法注册输入处理器。例如，注册点击处理器：

```csharp
screenInputMinitor.RegisterInputHandle<ScreenTapHandle>();
```

或者直接传入实例：

```csharp
var tapHandle = new ScreenTapHandle();
screenInputMinitor.RegisterInputHandle(tapHandle);
```

为指定类型的输入处理器添加事件监听：
```csharp
screenInputMinitor.AddListener<ScreenTapHandle>(OnTapEvent);
```

事件回调方法示例：

```csharp
void OnTapEvent(ScreenInputEvent inputEvent)
{
    Debug.Log($"Tap at: {inputEvent.screenPos}");
}
```

启用/禁用输入处理器

```csharp
screenInputMinitor.EnableInput<ScreenTapHandle>();
screenInputMinitor.DisableInput<ScreenTapHandle>();
```

注销输入处理器

```csharp
screenInputMinitor.UnregisterInputHandle<ScreenTapHandle>();
```

检查和获取处理器

```csharp
bool isRegistered = screenInputMinitor.IsInputHandleRegistered<ScreenTapHandle>();

if (screenInputMinitor.TryGetInputHandle<ScreenTapHandle>(out var handle))
{
    // 使用 handle
}
```

### 注意事项

- 输入处理器需实现 `IScreenInputHandle` 接口。
- 事件监听需使用 `ScreenInputEventHandler` 委托。
- 若启用 Unity 新输入系统，请确保 `ENABLE_INPUT_SYSTEM` 宏已定义。
- 已注册的输入处理器可并行接收同一输入；系统不会自动在点击、拖拽、长按、缩放等手势之间互斥，业务层应按需要决定监听哪些处理器。

### 内置交互组件

| 组件 | 用途与触发条件 | 主要事件字段 | 桌面映射 |
| --- | --- | --- | --- |
| `ScreenTapHandle` | 单指或左键短按并抬起时触发；移动超过阈值或按压超时不视为点击。 | `inputId`、`screenPos`、`pressTime`、`tapCount`。 | 鼠标左键单击与连击。 |
| `ScreenDragHandle` | 单指或左键移动达到拖拽阈值后开始，持续移动时执行，抬起或指针数量变化时结束。 | `screenPos`、`delta`、`pressTime`、`state`。 | 鼠标左键拖拽。 |
| `ScreenMoveHandle` | 跟踪一个触摸指针或鼠标在屏幕内的移动位置。 | `inputId`、`screenPos`、`delta`、`pressTime`、`state`。 | 鼠标移动；按下时会记录按压时长。 |
| `ScreenPinchHandle` | 两指间距变化超过阈值后触发；手指数不足两根时结束。 | `screenPos` 为两指中点，`pinchDelta` 为间距增量，另含 `pressTime`、`state`。 | 鼠标滚轮模拟缩放。 |
| `ScreenTwoFingerDragHandle` | 两指均移动且方向近似一致时触发；手指数或移动方向不满足条件时结束。 | `screenPos` 为两指中点，`delta` 为平均位移，另含 `pressTime`、`state`。 | 鼠标中键拖拽。 |
| `ScreenLongPressHandle` | 指针保持且未超过移动阈值，到达长按时长后开始；保持期间持续执行，结束时派发结束状态。 | `inputId`、`screenPos`、`pressTime`、`state`。 | 鼠标左键长按。 |

**示例：注册并监听点击事件**

```csharp
// 注册点击处理器
screenInputMinitor.RegisterInputHandle<ScreenTapHandle>();

// 添加点击事件监听
screenInputMinitor.AddListener<ScreenTapHandle>(OnTapEvent);

void OnTapEvent(ScreenInputEvent inputEvent)
{
    Debug.Log($"Tap Detected: {inputEvent.screenPos}");
}
```

如需扩展更多输入类型，只需实现新的 `IScreenInputHandle` 并注册即可。

## 5. AspectRatioLayout（尺寸比例适配）

`AspectRatioLayout` 用于让 `RectTransform` 的 `sizeDelta` 按设计分辨率与当前 UI 显示尺寸的比例变化。适合背景、装饰图、全屏遮罩等需要分别跟随屏幕宽度和高度变化的 UI。

### 工作方式

组件会在 `Awake` 时记录初始 `sizeDelta`，以 `ConstSetting.DefaultUISize` 作为设计尺寸，并使用 `UIManager.ScreenSize` 作为当前尺寸。设初始尺寸为 `initSize`，设计尺寸为 `defaultUISize`，当前尺寸为 `screenSize`：

```text
宽度适配后的尺寸 = screenSize.x * (initSize.x / defaultUISize.x)
高度适配后的尺寸 = screenSize.y * (initSize.y / defaultUISize.y)
```

### Inspector 参数

- `match`：需要适配的方向，支持组合。
  - `Width`：仅使宽度随当前 UI 宽度变化。
  - `Height`：仅使高度随当前 UI 高度变化。
  - `Width | Height`：宽高均按各自比例适配，默认值。

### 使用方法

1. 在目标 UI 对象（必须具有 `RectTransform`）上添加 `AspectRatioLayout`。
2. 先在设计分辨率下设置好对象的初始 `Width`、`Height`。
3. 在 `match` 中选择适配方向：
   - 横向铺满的背景图通常选择 `Width`；
   - 需要随屏幕高度伸缩的区域选择 `Height`；
   - 需要同时按屏幕宽高变化的遮罩选择 `Width | Height`。
4. 启用对象或其 Canvas 层级发生变化时，组件会自动应用适配尺寸。

### 注意事项

- 初始尺寸只在 `Awake` 时缓存；运行期间如果其他脚本修改了 `sizeDelta`，该组件不会将修改后的值作为新的设计尺寸。
- 当前实现不会在分辨率变化事件中持续刷新。如果游戏支持运行时旋转屏幕、调整窗口大小或切换显示区域，建议在外部时机重新启用对象，或扩展组件提供手动刷新接口。
- 该组件直接写入 `RectTransform.sizeDelta`，不要与其他同时控制尺寸的布局组件混用，避免相互覆盖。

## 6. AspectRatioScaler（宽高比缩放适配）

`AspectRatioScaler` 根据当前显示区域与 `ConstSetting.DefaultUISize` 的宽高比差异，缩放目标 `RectTransform` 的 `localScale`。适合需要保持自身原始布局尺寸，但在超宽屏或较窄屏中放大、缩小显示效果的 UI，例如角色展示、中央弹窗或特殊装饰。

### 工作方式

组件优先使用 `UICamera.instance.currentScreen` 获取当前显示区域；若 `UICamera` 不存在，则回退使用 `Screen.width` 与 `Screen.height`。它在 `Awake` 中保存初始 `localScale`，并按以下规则计算缩放系数：

```text
当前宽高比 = displayWidth / displayHeight
设计宽高比 = DefaultUISize.x / DefaultUISize.y

adaptMatch = Width  时：缩放系数 = 当前宽高比 / 设计宽高比
adaptMatch = Height 时：缩放系数 = 设计宽高比 / 当前宽高比
```

最后会将系数限制在 `minScale` 与 `maxScale` 之间，并乘到初始 X、Y 缩放值上。

### Inspector 参数

- `adaptMatch`
  - `Width`：以宽高比的宽度变化作为缩放基准；宽屏时通常会放大。
  - `Height`：以高度方向作为相反基准；宽屏时通常会缩小。
- `minScale`：允许的最小缩放系数，默认 `0.6`。
- `maxScale`：允许的最大缩放系数，默认 `2`。

### 使用方法

1. 在目标 UI 对象上添加 `AspectRatioScaler`，并先设置其设计状态下的 `localScale`。
2. 根据视觉需求选择 `adaptMatch`：
   - 希望宽屏时元素相对更大，可选择 `Width`；
   - 希望宽屏时元素相对更小或避免横向过度占位，可选择 `Height`。
3. 设置合理的 `minScale`、`maxScale`，防止极端比例屏幕导致 UI 过大或过小。
4. 组件启用时会自动刷新；如运行时显示区域发生变化，可调用：

```csharp
aspectRatioScaler.ForceUpdate();
```

### 注意事项

- 组件会在 `OnRectTransformDimensionsChange` 中检测显示尺寸是否变化；如果显示区域信息由外部 `UICamera` 更新但 RectTransform 没有触发尺寸变化，应主动调用 `ForceUpdate()`。
- 组件仅修改 `localScale.x` 与 `localScale.y`，保留当前的 `localScale.z`。
- 初始缩放值仅在 `Awake` 时记录；不要在运行时持续由多个组件同时写入 `localScale`。

## 7. SafeAreaFitter（安全区域适配）

`SafeAreaFitter` 用于将 UI 限制在设备的 `Screen.safeArea` 内，避开刘海、挖孔、圆角和底部手势区域。适合挂在页面根节点、顶部栏、底部栏或需要始终处于安全显示范围内的容器上。

### 工作方式

组件读取 `Screen.safeArea`，并结合 `UIManager.PixelScale` 与 `UIManager.ScreenSize` 计算偏移，然后将目标 `RectTransform` 设置为全屏拉伸锚点：

```csharp
root.anchorMin = Vector2.zero;
root.anchorMax = Vector2.one;
root.offsetMin = offsetMin;
root.offsetMax = offsetMax;
```

这会使 UI 的可视范围与设备安全区域对齐。

### Inspector 参数与公开方法

- `runInAutomatic`：是否自动适配，默认启用。
  - 启用时，会在对象 `OnEnable` 以及 Canvas 层级变化时执行安全区适配。
  - 关闭时，需要由业务代码手动刷新。
- `ForceUpdate()`：立即重新读取并应用当前安全区域。
- `LogSafeArea()`：输出当前 `Screen.safeArea`、锚点和偏移，便于在真机排查适配问题。

### 使用方法

1. 将 `SafeAreaFitter` 挂到需要安全区适配的 UI 根节点上。
2. 保持 `runInAutomatic` 勾选，通常无需额外代码。
3. 若页面在运行时切换横竖屏、切换分辨率或安全区状态发生变化，主动刷新：

```csharp
safeAreaFitter.ForceUpdate();
```

4. 在真机上需要检查适配数据时，可在 Inspector 中调用 `LogSafeArea()`，或在代码中调用该方法查看日志。

### 注意事项

- 此组件会强制将 `anchorMin` 设为 `(0, 0)`、`anchorMax` 设为 `(1, 1)`，并覆盖 `offsetMin`、`offsetMax`。不要挂在依赖自定义锚点或偏移的普通子控件上。
- 推荐挂在页面最外层的安全区容器上，再把顶部栏、底部栏和内容区域作为该容器的子节点布局。
- `Screen.safeArea` 在 Editor 中可能与真机不同；刘海屏、挖孔屏和手势导航区域必须以目标设备实机结果为准。
- 组件依赖 `UIManager.PixelScale` 与 `UIManager.ScreenSize` 的正确初始化，应确保 UI 管理器已完成初始化后再进行页面展示。
