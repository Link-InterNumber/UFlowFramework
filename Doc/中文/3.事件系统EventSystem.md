# 事件系统

## 😀 概述

UFlow 的事件系统提供了三种互补的事件能力，用于覆盖不同的通信场景：

- `LinkEvent`：立即触发的强类型事件，适合模块之间的直接通知。
- `LaterEvent`：延迟到 `LaterExecute` 阶段统一触发的事件，适合规避当前调用栈中的重入和连锁刷新。
- `ScopedEventBus`：基于 `eventId` 的局部事件总线，适合某个系统、页面或模块内部维护一组临时事件。

除此之外，`EventManager` 还提供了一组框架级公共事件，例如加载、分辨率变化、UI 打开关闭、语言切换、网络连接等，业务层可以直接订阅。

---

## 🧱 主要组件

| 组件 | 用途 |
|---|---|
| `LineEventBase` | 事件基类，提供 `enable` 开关和 `RemoveAllListeners` 统一入口。 |
| `LinkEvent` / `LinkEvent<T...>` | 立即触发事件，支持 0 到 3 个参数。 |
| `LaterEvent` / `LaterEvent<T...>` | 延迟触发事件，触发请求会先进入 `EventManager`，稍后统一执行。 |
| `ScopedEventBus` | 通过 `int eventId` 管理一组强类型事件，支持延后收集和去重释放。 |
| `EventManager` | 框架级事件中心，同时负责驱动 `LaterEvent` 的统一执行。 |

支持的参数形式：

- 无参数
- 1 个参数
- 2 个参数
- 3 个参数

对应的委托类型分别是：

```csharp
BaseLinkAction
BaseLinkAction<T>
BaseLinkAction<T, TK>
BaseLinkAction<T, TK, TL>
```

---

## 1. 立即事件 `LinkEvent`

`LinkEvent` 是最基础的事件类型。调用 `Invoke` 时，监听函数会立即在当前调用栈中执行。

### 适用场景

- 某个状态已经确定变化，需要立刻通知监听者。
- 事件处理逻辑简单，不担心重入问题。
- 希望通过泛型约束事件参数类型。

### 常用 API

- `AddListener(...)`
- `RemoveListener(...)`
- `AddListenerOnce(...)`
- `Invoke(...)`
- `RemoveAllListeners()`
- `GetEventListenerCount()`
- `enable`

### 示例

```csharp
public class CurrencyModule
{
    public readonly LinkEvent<int> onCoinChanged = new LinkEvent<int>();

    private int _coin;

    public void AddCoin(int delta)
    {
        _coin += delta;
        onCoinChanged.Invoke(_coin);
    }
}

public class CurrencyPanel : MonoBehaviour
{
    [SerializeField] private TMPro.TextMeshProUGUI _coinText;
    private CurrencyModule _currencyModule;

    private void OnEnable()
    {
        _currencyModule.onCoinChanged.AddListener(OnCoinChanged);
    }

    private void OnDisable()
    {
        _currencyModule.onCoinChanged.RemoveListener(OnCoinChanged);
    }

    private void OnCoinChanged(int value)
    {
        _coinText.text = value.ToString();
    }
}
```

### 一次性监听

```csharp
EventManager.instance.onNetConnect.AddListenerOnce(() =>
{
    Debug.Log("Only runs once after connect");
});
```

### 临时禁用事件触发

所有事件都继承自 `LineEventBase`，可以通过 `enable` 临时关闭触发：

```csharp
var gameEvent = new LinkEvent();
gameEvent.enable = false;
gameEvent.Invoke(); // 不会触发监听
```

## 2. 延迟事件 `LaterEvent`

`LaterEvent` 的 `Invoke` 不会立即执行监听函数，而是先把事件登记到 `EventManager`，等到模块系统驱动 `EventManager.LaterExecute` 时再统一执行。

### 适用场景

- 避免在当前逻辑执行过程中立即刷新 UI 或修改状态。
- 同一帧内会多次请求触发，但希望在稍后统一处理。
- 希望把事件执行时机放到模块的延后阶段。

### 关键行为

- 当事件已进入待执行队列后，重复调用 `Invoke` 不会重复入队。
- 对有参数的 `LaterEvent<T...>`，后一次 `Invoke` 会覆盖前一次缓存的数据。
- 真正执行监听函数依赖 `EventManager` 的 `LaterExecute` 驱动。

### 示例

```csharp
public class InventoryModule
{
    public readonly LaterEvent onInventoryDirty = new LaterEvent();

    public void MarkDirty()
    {
        onInventoryDirty.Invoke();
    }
}

public class InventoryPanel : MonoBehaviour
{
    [SerializeField] private InventoryModule _inventoryModule;

    private void OnEnable()
    {
        _inventoryModule.onInventoryDirty.AddListener(RefreshView);
    }

    private void OnDisable()
    {
        _inventoryModule.onInventoryDirty.RemoveListener(RefreshView);
    }

    private void RefreshView()
    {
        Debug.Log("Refresh inventory once in later execution stage");
    }
}
```

### 带参数示例

```csharp
public class ChatModule
{
    public readonly LaterEvent<string> onLatestMessageChanged = new LaterEvent<string>();

    public void SetLatestMessage(string message)
    {
        onLatestMessageChanged.Invoke(message);
    }
}
```

如果同一帧连续调用：

```csharp
chatModule.SetLatestMessage("A");
chatModule.SetLatestMessage("B");
chatModule.SetLatestMessage("C");
```

那么稍后真正触发时，监听者收到的是最后一次写入的数据 `"C"`。

## 3. 作用域总线 `ScopedEventBus`

`ScopedEventBus` 用 `int eventId` 管理一组事件实例，适合某个模块、功能或页面内部维护自己的事件集合，而不需要把事件字段暴露到全局管理器上。

### 适用场景

- 页面级、模块级、会话级事件。
- 动态创建和销毁的一组事件。
- 不希望为每个事件单独声明字段。

### 常用 API

监听管理：

- `AddListener(...)`
- `RemoveListener(...)`
- `RemoveAllListeners(eventId)`
- `Clear()`

触发：

- `Invoke(...)`
- `CollectInvoke(...)`
- `TriggerInvoke()`
- `HoldInvoke(...)`
- `ReleaseInvoke()`

### 基础示例

```csharp
public static class BattleEventId
{
    public const int WaveStart = 1001;
    public const int WaveFinished = 1002;
    public const int UnitHpChanged = 1003;
}

public class BattleController
{
    private readonly ScopedEventBus _bus = new ScopedEventBus();

    public void Init()
    {
        _bus.AddListener(BattleEventId.WaveStart, OnWaveStart);
        _bus.AddListener<int>(BattleEventId.UnitHpChanged, OnUnitHpChanged);
    }

    public void Deinit()
    {
        _bus.Clear();
    }

    public void StartWave()
    {
        _bus.Invoke(BattleEventId.WaveStart);
    }

    public void ChangeUnitHp(int hp)
    {
        _bus.Invoke(BattleEventId.UnitHpChanged, hp);
    }

    private void OnWaveStart()
    {
        Debug.Log("Wave started");
    }

    private void OnUnitHpChanged(int hp)
    {
        Debug.Log($"Unit hp = {hp}");
    }
}
```

### 类型要和 `eventId` 保持一致

同一个 `eventId` 一旦被绑定为某种参数签名，后续就必须保持一致，否则会输出错误日志。

例如：

```csharp
bus.AddListener<int>(1001, OnValueChanged);
bus.Invoke(1001); // 会报类型不匹配错误
```

建议做法：

- 用常量或枚举集中定义 `eventId`
- 为每个 `eventId` 明确唯一的参数签名

## 4. `CollectInvoke` 与 `HoldInvoke`

`ScopedEventBus` 额外提供了两种“延后触发”策略，它们和 `LaterEvent` 的设计目标不同。

### `CollectInvoke` + `TriggerInvoke`

用于先收集，再按收集顺序依次触发所有事件。

```csharp
bus.CollectInvoke(BattleEventId.WaveStart);
bus.CollectInvoke(BattleEventId.UnitHpChanged, 90);
bus.CollectInvoke(BattleEventId.UnitHpChanged, 80);

bus.TriggerInvoke();
```

特点：

- 会保留所有收集到的调用
- 按入队顺序依次触发
- 不会自动去重

适合场景：

- 一段流程结束后再统一派发所有事件
- 希望完整保留中间每一次事件请求

### `HoldInvoke` + `ReleaseInvoke`

用于先压栈，释放时同一 `eventId` 只触发一次。

```csharp
bus.HoldInvoke(BattleEventId.UnitHpChanged, 90);
bus.HoldInvoke(BattleEventId.UnitHpChanged, 80);
bus.HoldInvoke(BattleEventId.WaveStart);

bus.ReleaseInvoke();
```

特点：

- 内部使用栈，后压入的调用先参与释放
- 同一个 `eventId` 只会触发一次
- 适合“中间可能多次变化，但最终只关心释放时结果”的场景

典型场景：

- UI 刷新请求去重
- 配置脏标记批量释放
- 某段流程中同类事件可能反复触发，但最终只需要响应一次

## 5. 框架级事件 `EventManager`

`EventManager` 提供了一批已经定义好的公共事件，适合订阅框架运行时状态变化。

### 常见事件示例

```csharp
private void OnEnable()
{
    EventManager.instance.onPause.AddListener(OnPauseChanged);
    EventManager.instance.onLanguageChange.AddListener(OnLanguageChanged);
    EventManager.instance.onNetConnect.AddListener(OnNetConnected);
}

private void OnDisable()
{
    EventManager.instance.onPause.RemoveListener(OnPauseChanged);
    EventManager.instance.onLanguageChange.RemoveListener(OnLanguageChanged);
    EventManager.instance.onNetConnect.RemoveListener(OnNetConnected);
}

private void OnPauseChanged(bool paused)
{
    Debug.Log($"Paused: {paused}");
}

private void OnLanguageChanged(Language language)
{
    Debug.Log($"Language changed: {language}");
}

private void OnNetConnected()
{
    Debug.Log("Network connected");
}
```

当前 `EventManager` 中包含的主要类别有：

- 游戏逻辑：加载、暂停、退出、开始游戏、重置游戏、清理资源
- UI：页面打开关闭、窗口打开关闭、屏幕方向变化、输入使能
- 引导：引导开始 / 结束
- 语言：语言切换
- 时间缩放：替换 / 暂停
- 网络：连接 / 断开

如果某个事件只属于某个系统自身，优先把事件字段放在该系统内部，而不是继续堆到 `EventManager` 中。

## 6. 使用建议

### 1. 优先选择最简单的事件模型

- 立即通知：用 `LinkEvent`
- 延后执行：用 `LaterEvent`
- 局部 `eventId` 总线：用 `ScopedEventBus`

### 2. 始终成对注册和注销监听

推荐在 `OnEnable` / `OnDisable` 或 `Init` / `Deinit` 中成对处理：

```csharp
private void OnEnable()
{
    _event.AddListener(OnEvent);
}

private void OnDisable()
{
    _event.RemoveListener(OnEvent);
}
```

### 3. 只有确实需要时才用 `AddListenerOnce`

`AddListenerOnce` 适合一次性回调，不适合长期监听。

### 4. 为 `ScopedEventBus` 维护清晰的 `eventId` 定义

推荐把 `eventId` 放到单独的静态类或枚举中，避免魔法数字散落：

```csharp
public static class ShopEventId
{
    public const int GoodsChanged = 2001;
    public const int CurrencyChanged = 2002;
}
```

### 5. 关注 `LaterEvent` 的覆盖语义

对于 `LaterEvent<T...>`，如果同一轮延后执行前被多次调用，只有最后一次写入的数据会被真正广播。

---

## 7. 注意事项

- `ScopedEventBus` 只支持 0 到 3 个参数。
- `CollectInvoke` / `HoldInvoke` 内部参数使用 `object[]` 保存，释放时再按参数个数分派。
- `ScopedEventBus` 如果调用时 `eventId` 未注册，会输出错误日志。
- `ScopedEventBus` 如果同一个 `eventId` 混用了不同参数签名，也会输出错误日志。
- `LinkEvent` / `LaterEvent` 在 `UNITY_EDITOR` 下会检查重复监听并输出错误日志。
- `LaterEvent` 的执行依赖 `EventManager` 被模块系统正常驱动。

---

## ✅ 场景推荐

- 用 `LinkEvent` 处理模块之间的直接通知。
- 用 `LaterEvent` 处理 UI 刷新、状态整理、避免重入的延迟通知。
- 用 `ScopedEventBus` 处理页面级、模块级、局部生命周期内的事件集合。
- 用 `EventManager` 订阅框架级公共状态变化。
