# 异步系统

## 😀 概述

异步系统用于统一管理运行时中的协程、延时调度、固定间隔任务、线程池任务与 Unity Job，避免业务代码直接依赖分散的入口或自行维护生命周期。

该系统以 `AsyncManager` 为统一入口，在首次使用时自动创建宿主对象，并在 `Update` / `FixedUpdate` 中驱动各类执行器。它适合以下场景：

- 启动和取消协程流程
- 延迟若干秒或若干帧执行主线程逻辑
- 注册固定间隔轮询任务
- 把耗时计算丢到线程池，完成后切回主线程
- 调度 `IJob` / `IJobFor` 类型任务

主要组件如下：

| 组件 | 用途 |
|---|---|
| `AsyncManager` | 异步系统统一入口，负责创建和持有各执行器，并提供对外 API。 |
| `CoroutineRunner` | 基于 Unity 协程执行 `IEnumerator`，在编辑器下附带异常日志包装。 |
| `SchedulerRunner` | 负责按时间或按帧延迟执行一次性任务。 |
| `IntervalCallRunner` | 负责固定间隔重复执行任务，并支持自动释放条件。 |
| `ThreadedTasksRunner` | 负责把任务提交到线程池，并把回调投递回主线程。 |
| `JobRunner` | 负责执行 `IJob` / `IJobFor`，支持同步与异步两种模式。 |
| `AsyncHandlerBase` | 异步句柄基类，提供 `Cancel` 与完成回调能力。 |
| `YieldInstructionsQueue` | 用于串行执行多个协程，并可观察进度、暂停、恢复和取消。 |

组件依赖关系
```
AsyncManager
    |
    |──> CoroutineRunner
    |       |
    |       └──> CoroutineHandler / YieldInstructionsQueue
    |
    |──> SchedulerRunner
    |       |
    |       └──> SchedulerTask
    |
    |──> IntervalCallRunner
    |
    |──> ThreadedTasksRunner
    |
    └──> JobRunner
            |
            └──> CoroutineRunner (WebGL 下用于模拟异步并行 Job)
```

## 🛠️ 使用

### 1.✨ 启动协程

使用 `AsyncManager.Run` 启动一个协程任务。返回值是 `AsyncHandlerBase`，可用于等待完成或手动取消。

```csharp
private IEnumerator LoadFlow()
{
    yield return new WaitForSeconds(1f);
    Debug.Log("Load complete");
}

AsyncHandlerBase handler = AsyncManager.Run(LoadFlow());
handler?.OnComplete(() => Debug.Log("Coroutine finished"));
```

如果你已经拿到了管理器实例，也可以使用实例方法：

```csharp
AsyncManager.EnsureInstance().RunCoroutine(LoadFlow());
```

### 2.⏱️ 延时执行主线程任务

使用 `Schedule` 按秒延迟执行，使用 `ScheduleByFrame` 按帧延迟执行。

```csharp
AsyncManager.Schedule(() => Debug.Log("Delay by seconds"), 0.5f);
AsyncManager.ScheduleByFrame(() => Debug.Log("Delay by frames"), 3);
```

当延迟值小于等于 `0` 时，任务会立即执行，并返回 `null`。

### 3.🔁 注册固定间隔任务

使用 `RegisterIntervalTask` 注册一个会重复触发的任务。该任务由 `FixedUpdate` 驱动。

```csharp
int taskId = AsyncManager.EnsureInstance().RegisterIntervalTask(
    1f,
    () => Debug.Log("Tick every second"),
    () => false);

// 某个时机注销
AsyncManager.EnsureInstance().UnregisterIntervalTask(taskId);
```

如果需要在满足条件时自动回收，可以传入 `autoReleaseCondition`：

```csharp
bool finished = false;
AsyncManager.EnsureInstance().RegisterIntervalTask(
    0.2f,
    () => Debug.Log("Polling"),
    () => finished);
```

### 4.📚 串行执行协程队列

使用 `CreateYieldInstructionsQueue` 创建一个依次执行的协程队列，并可设置相邻协程之间的固定间隔。

```csharp
IEnumerator StepA()
{
    Debug.Log("Step A");
    yield return new WaitForSeconds(0.5f);
}

IEnumerator StepB()
{
    Debug.Log("Step B");
    yield return null;
}

YieldInstructionsQueue queue = AsyncManager.EnsureInstance()
    .CreateYieldInstructionsQueue(0.1f, StepA(), StepB());

queue.OnComplete(() => Debug.Log("Queue completed"));
```

队列支持：

- `Pause()`：暂停执行
- `Resume()`：恢复执行
- `Cancel()`：终止队列并清空剩余任务
- `process`：返回 $0$ 到 $1$ 的执行进度

### 5.🧵 提交线程池任务

使用 `RunTaskAsync` 把后台任务交给线程池执行，并在主线程回调收尾逻辑。

```csharp
AsyncManager.EnsureInstance().RunTaskAsync(
    () =>
    {
        // 后台线程中的耗时逻辑
        System.Threading.Thread.Sleep(100);
    },
    () =>
    {
        // 回到主线程后的逻辑
        Debug.Log("Background task completed");
    });
```

也支持带参数版本：

```csharp
AsyncManager.EnsureInstance().RunTaskAsync<int>(
    value => Debug.Log($"Background value: {value}"),
    10,
    () => Debug.Log("Callback on main thread"));
```

### 6.⚙️ 执行 Unity Job

同步模式适合需要立刻拿到结果的场景：

```csharp
public struct AddJob : IJob
{
    public NativeArray<int> values;

    public void Execute()
    {
        values[0] += 1;
    }
}

var values = new NativeArray<int>(1, Allocator.TempJob);
AsyncManager.EnsureInstance().SyncRunJob(new AddJob { values = values });
values.Dispose();
```

异步模式会在任务完成后通过回调返回结果：

```csharp
public struct MultiplyJob : IJobFor
{
    public NativeArray<int> values;

    public void Execute(int index)
    {
        values[index] *= 2;
    }
}

var values = new NativeArray<int>(16, Allocator.TempJob);
AsyncManager.EnsureInstance().AsyncRunParallelJob(
    new MultiplyJob { values = values },
    values,
    values.Length,
    result =>
    {
        Debug.Log($"Job finished, length = {result.Length}");
        result.Dispose();
    });
```

## 🌟 设计特点

### 1. 单一统一入口

业务层只需要依赖 `AsyncManager`，不需要分别持有协程宿主、调度器、线程池工具或 Job 轮询器。

### 2. 生命周期集中管理

`AsyncManager` 在 `Awake` 中初始化所有执行器，在 `Deinit` 中统一释放资源：

- 协程执行器停止并清空句柄池
- 延时任务和间隔任务释放缓存对象
- 线程池回调队列清空
- 异步 Job 检查并收尾

### 3. 主线程回调安全回收

线程池任务不会直接回调 Unity API，而是先压入主线程队列，再由 `AsyncManager.Update` 驱动执行。

### 4. 平台兼容回退

在 `UNITY_WEBGL` 下：

- 线程池任务会退化为同步直接执行
- `IJob` 直接调用 `Execute`
- 并行 Job 通过协程分帧模拟异步执行

## 📦 对外能力总览

根据当前实现，`AsyncManager` 暴露的核心能力包括：

### 1. 协程能力

- `Run(IEnumerator routine)`
- `RunCoroutine(IEnumerator routine)`
- `CreateYieldInstructionsQueue(float interval, params IEnumerator[] enumerators)`
- `Host` 属性用于获取当前宿主 `MonoBehaviour`

### 2. 调度能力

- `Schedule(Action action, float delayTime = 0f, bool ignoreTimeScale = false)`
- `ScheduleByFrame(Action action, int delayFrames = 0)`
- 对应实例方法 `ScheduleTask` 与 `ScheduleTaskByFrame`

### 3. 间隔任务能力

- `RegisterIntervalTask(float interval, Action action, Func<bool> autoReleaseCondition = null)`
- `UnregisterIntervalTask(int taskIndex)`
- `ClearIntervalTasks()`

### 4. 线程任务能力

- `RunTaskAsync(Action backgroundTask, Action mainThreadCallback = null)`
- `RunTaskAsync<T>(Action<T> backgroundTask, T parameter, Action mainThreadCallback = null)`

### 5. Job 能力

- `SyncRunJob<TJob>(TJob job)`
- `AsyncRunJob<TJob, T>(TJob job, NativeArray<T> resultArray, Action<NativeArray<T>> onComplete)`
- `SyncRunParallelJob<TJob>(TJob job, int length, int batchCount = 64)`
- `AsyncRunParallelJob<TJob, T>(TJob job, NativeArray<T> resultArray, int length, Action<NativeArray<T>> onComplete, int batchCount = 64)`

## ⚙️ 内部机制与驱动方式

### 1. 自动创建宿主对象

`AsyncManager.EnsureInstance()` 会在首次调用时动态创建名为 `AsyncManager` 的 GameObject，并挂载组件本体。

### 2. Update 驱动一次性任务与回调

`Update()` 中会驱动：

- `SchedulerRunner.Tick(time, unscaledTime, frameCount)`
- `ThreadedTasksRunner.Tick()`
- `JobRunner.Tick()`

这意味着按秒调度、按帧调度、线程回调派发和异步 Job 完成检查，都是由主线程逐帧推进的。

### 3. FixedUpdate 驱动间隔任务

`FixedUpdate()` 中调用 `IntervalCallRunner.Tick(Time.fixedDeltaTime)`，因此固定间隔任务是基于固定帧推进，而不是普通 `Update` 时间片。

### 4. 编辑器下协程异常包装

`CoroutineRunner` 在 `UNITY_EDITOR` 下会使用包装器捕获协程异常并输出日志，避免协程内部异常被静默吞掉。

## 🔍 示例场景

### 1. UI 打开后延迟刷新

```csharp
AsyncManager.Schedule(() => RefreshUI(), 0.2f);
```

### 2. 资源加载流程串行执行

```csharp
var queue = AsyncManager.EnsureInstance().CreateYieldInstructionsQueue(
    0f,
    LoadConfig(),
    LoadAtlas(),
    EnterScene());

yield return queue;
```

### 3. 后台计算后回主线程更新表现

```csharp
AsyncManager.EnsureInstance().RunTaskAsync(
    () => BuildCache(),
    () => ShowReadyState());
```

### 4. 使用 Job 批量处理数据

```csharp
AsyncManager.EnsureInstance().AsyncRunParallelJob(
    new MultiplyJob { values = values },
    values,
    values.Length,
    result => ApplyResult(result));
```

## ℹ️ 注意事项

1. `Schedule` 和 `ScheduleByFrame` 在延迟参数小于等于零时会立即执行回调，并返回 `null`，不能再对返回值做取消操作。
2. `ThreadedTasksRunner` 的 `backgroundTask` 运行在线程池线程中，不能直接访问绝大多数 Unity API。
3. `RunTaskAsync` 的主线程回调依赖 `AsyncManager.Update()` 驱动，如果宿主没有存活，回调不会被正常派发。
4. `RegisterIntervalTask` 的间隔推进基于 `FixedUpdate` 的 `deltaTime` 累加，实际触发节奏会受物理步长影响。
5. `AsyncRunJob` / `AsyncRunParallelJob` 传入的 `NativeArray` 生命周期由调用方负责管理，通常应在完成回调后释放。
6. WebGL 下线程池与 Job System 会走降级分支，行为语义保持接近，但不是完全等价的原生并发实现。
7. `YieldInstructionsQueue.Cancel()` 会清空剩余任务并释放内部协程，不会再触发完成回调。

## ✅ 场景推荐

- UI 动画、面板切换、引导流程等基于协程的时序控制
- 需要按秒或按帧延迟执行的逻辑编排
- 轮询式检测、超时检查、冷却刷新等固定间隔任务
- 文本解析、路径构建、缓存预处理等可放入线程池的 CPU 工作
- 大批量数组运算、路径采样、数值预处理等适合 Job System 的数据任务
