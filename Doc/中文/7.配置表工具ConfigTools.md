# 配置表工具使用说明

## 📖 简介

当前配置表系统已经升级为基于 DataChunk 的二进制分块加载方案。

配置工具会从 Excel 生成：

- 配置表对应的 C# 数据类和集合类
- `ConfigManager` 访问入口
- 每张表对应的分块二进制数据文件 `ConfNameData.bytes`
- 每张表对应的索引文件 `ConfNameIndex.bytes`

运行时不再依赖一次性把整张表读入内存，而是通过 `ChunkDataQueryer<TKey, TData>` 按 key 定位 chunk，按需读取数据。这种方式更适合大规模配置表、按需访问和异步初始化场景。

## ⚙️ 功能

1. **配置表生成**
   - 从 Excel 文件生成配置数据。
   - 支持常见基础类型、数组类型、资源引用和本地化类型。
   - 支持通过 `TypeRef` 扩展自定义字段类型。

2. **DataChunk 二进制输出**
   - 每张配置表导出为 `Data.bytes + Index.bytes` 两个文件。
   - 使用 chunk 索引实现按 key 快速定位和按需加载。
   - 配置读取接口已经统一切换到 `Get` / `GetByKey` / `GetAll` / `Find` 这组基于 chunk 的查询方式。

3. **异步与按需加载**
   - 支持同步 `Prepare()` 和异步 `PrepareAsync()`。
   - 支持通过 `ConfigGroup` 批量异步加载多个配置集合。
   - 首次运行时可从打包资源中拷贝配置二进制文件到持久化目录。

4. **本地化与资源引用**
   - 支持 `LocalizationStringRef`、`LocalizationAssetRef` 等类型。
   - 支持 `AudioRef`、`SpriteRef`、`GameObjectRef` 等资源引用类型。
   - 支持导出本地化 CSV。

5. **自动代码生成**
   - 自动生成配置表数据类、集合类、创建器和 `ConfigManager` 管理入口。

## 📂 文件结构

- `ConfigSettingWindow.cs`
  提供配置工具设置窗口，用于设置 Excel 路径、脚本输出路径和配置资源输出路径。

- `ConfigWriter.cs`
  负责从 Excel 生成配置表对应的 C# 代码。

- `WriteConfCreatorHandler.cs`
  负责生成配置表资产导出逻辑，当前内部使用 `ChunkMaker.StreamWriteSync(...)` 输出 DataChunk 文件。

- `ConfBase.cs` / `ConfBaseCollections.cs`
  定义配置数据基础类和集合加载/查询接口。

- `ConfigGroup.cs`
  负责批量管理多个配置集合的异步加载状态。

- `ConfigManager.cs`
  提供统一的配置访问入口，并处理首次配置拷贝初始化逻辑。

- `AssetRef` 文件夹
  定义配置表字段可用的扩展类型，例如 `AudioRef`、`SpriteRef`、`LocalizationStringRef` 等。

## 🛠️ 使用方法

### 📁 1. 设置路径

打开 Unity 菜单 `Tools > Config > Config Setting Window`，设置以下路径：

![打开Config Setting Window](../img/ConfigToolMenuItem.png "Magic Gardens")

- **Excel 文件路径**：存放 Excel 配置表的文件夹路径。
- **脚本文件路径**：生成的 C# 脚本存放路径，为 `Assets` 下的相对路径。
- **资源文件路径**：导出的配置二进制文件目录，为 `Assets` 下的相对路径。

### 📜 2. 生成配置表

![Config Setting Window](../img/ConfigSettingWindow.png "Magic Gardens")

在 `Config Setting Window` 中点击以下按钮：

- **Save Settings**：保存当前设置。
- **Create Cs Files**：根据 Excel 文件生成配置表对应的 C# 类和管理代码。
- **Create Config Assets**：生成配置表二进制文件。
- **Delete Config Assets**：删除已生成的配置二进制文件。

当前每张配置表通常会生成两份文件：

- `ConfNameData.bytes`：分块数据文件
- `ConfNameIndex.bytes`：chunk 索引文件

### 🌐 3. 本地化支持

- **Create Localization csv**：提取配置表中的本地化字符串和资源，生成 CSV 文件。

### 🚀 4. 初始化配置资源

运行时可先调用 `ConfigManager.Init(...)`。当前逻辑会在首次启动时把打包进资源中的配置二进制文件拷贝到 `Application.persistentDataPath/ConfigAsset/`，后续配置集合再从持久化目录加载。

```csharp
IEnumerator Start()
{
    yield return ConfigManager.instance.Init(status =>
    {
        Debug.Log($"Config init status: {status}");
    });
}
```

### 📥 5. 批量加载配置

使用 `ConfigGroup` 批量加载多个配置集合：

```csharp
private ConfigGroup _configGroup;

IEnumerator LoadConfig()
{
    _configGroup = new ConfigGroup(
        ConfigManager.instance.guidanceConf,
        ConfigManager.instance.rolePropConf);

    _configGroup.onLoadCompleted += OnInitConfLoadCompleted;
    yield return _configGroup.LoadAll();
}

private void OnInitConfLoadCompleted(AssetLoadStatus status)
{
    if (status == AssetLoadStatus.Loaded)
    {
        Debug.Log("配置加载成功");
        return;
    }

    Debug.LogError("配置加载失败");
    string[] failed = _configGroup.failLoadConfigs;
    for (int i = 0; i < failed.Length; i++)
    {
        Debug.LogError($"{failed[i]} 加载失败");
    }
}

void ReleaseConfig()
{
    _configGroup?.ReleaseAll();
}
```

### 📦 6. 单张配置同步加载

如果只需要单独使用某张表，也可以直接调用集合类上的 `Prepare()`：

```csharp
ConfigManager.instance.rolePropConf.Prepare();

RolePropConf roleConfig = ConfigManager.instance.rolePropConf.Get(roleId);

ConfigManager.instance.rolePropConf.Release(false);
```

### 📊 7. 获取配置数据

当前推荐的访问方式如下：

```csharp
// 通过 key 获取单条配置
RolePropConf roleConfig = ConfigManager.instance.rolePropConf.Get(roleId);
Debug.Log($"角色名称: {roleConfig.name}");

// 按 key 条件筛选
foreach (var conf in ConfigManager.instance.rolePropConf.GetByKey(id => id > 1000))
{
    Debug.Log($"Matched By Key: {conf.name}");
}

// 遍历整张表
foreach (var conf in ConfigManager.instance.rolePropConf.GetAll())
{
    Debug.Log($"All: {conf.name}");
}

// 按数据条件筛选
foreach (var conf in ConfigManager.instance.rolePropConf.Find(o => o.atk > 10 && o.atk < 20))
{
    Debug.Log($"Matched By Predicate: {conf.name}");
}
```

`rawData` 这类一次性整表缓存接口已经不再是当前 DataChunk 方案的主推荐用法，优先使用上述查询接口。

### 🔧 8. 扩展自定义类型

自定义字段类型需要继承 `TypeRef`，并至少提供：

- `isMatch(string lowerRawType)`
- `TypeName()`
- 静态 `Parse(...)`
- 静态 `WriteItemData(...)`
- 静态 `ReadItemData(...)`

下面以 `TimeDateRef` 为例：

```csharp
using System;
using System.IO;
using System.Text;

[Serializable]
public sealed class TimeDateRef : TypeRef
{
    public override bool isMatch(string lowerRawType)
    {
        return lowerRawType.Equals("timedate");
    }

    public override string TypeName()
    {
        return "TimeDate";
    }

    public static TimeDate Parse(string stringValue, string confName, int rowIndex, int colIndex)
    {
        if (string.IsNullOrEmpty(stringValue))
            return default;

        string[] splitString = stringValue.Split('-');
        int year = int.Parse(splitString[0]);
        int month = int.Parse(splitString[1]);
        int day = int.Parse(splitString[2]);
        return new TimeDate(year, month, day);
    }

    public static void WriteItemData(TimeDate item, BinaryWriter writer, Encoding encoding)
    {
        writer.Write(item.Year);
        writer.Write(item.Month);
        writer.Write(item.Day);
    }

    public static TimeDate ReadItemData(BinaryReader reader, Encoding encoding)
    {
        int year = reader.ReadInt32();
        int month = reader.ReadInt32();
        int day = reader.ReadInt32();
        return new TimeDate(year, month, day);
    }
}
```

之后只需要在 Excel 中使用 `TimeDate` 作为字段类型，并填写正确格式的数据即可。

### 🔧 9. 在 Editor 中读取配置表

在 Editor 工具代码里，如果只是临时读取单张配置表，通常更直接的方式是同步 `Prepare()`：

```csharp
var configInstance = new ConfigManager();
configInstance.guidanceConf.Prepare();

var guidanceConfig = configInstance.guidanceConf.Get(1);

configInstance.guidanceConf.Release(false);
```

## 📑 Excel 文件格式

1. 第一行：字段注释。
2. 第二行：字段名称，可用 `:key` 标记主键，支持多 key。
3. 第三行：字段类型，如 `int`、`string`、`float[]`、`LocalizationStringRef` 等。
4. 第四行及以后：数据内容。

示例：

| 注释 | id | 名称 | 属性值 |
|---|---|---|---|
| 字段名称 | id:key | name | value |
| 字段类型 | int | string | float[] |
| 数据 | 1 | 英雄 | 10,20,30 |
| 数据 | 2 | 怪物 | 5,15,25 |

## ⚠️ 注意事项

1. Excel 文件需保存为 `.xlsx` 格式。
2. 主键字段需使用 `:key` 标记，支持多个键。
3. 当前配置系统导出的是 DataChunk 二进制文件，而不是旧版的多格式配置资源。
4. 本地化字段请使用 `LocalizationStringRef` 或 `LocalizationAssetRef` 类型。
5. 字段名称可以重复，但字段类型必须相同；重复字段会在生成时转为 `List<T>`。
6. 自定义 `TypeRef` 除了 `Parse` 外，还需要提供 `WriteItemData` / `ReadItemData`，否则生成出来的配置类无法完成二进制读写。
7. 如果运行时依赖首次拷贝配置文件，请确保生成的配置资源已经被正确打包进可加载资源中。

## 📦 依赖

- Unity 2020.3 或更高版本。
- [EPPlus](https://github.com/EPPlusSoftware/EPPlus) 用于解析 Excel 文件。
- DataChunk 二进制分块读取系统，用于配置表运行时加载。
- Unity Addressables 或等价资源分发方案，用于首次启动时分发表配置资源时可选使用。

## ❓ 常见问题

1. **配置加载失败**
   检查 Excel 导出路径、运行时持久化目录和生成的 `Data.bytes` / `Index.bytes` 文件是否存在。

2. **首次运行没有拷贝到配置文件**
   检查配置资源是否已经被正确打包进运行时可加载资源，并确认初始化流程已执行 `ConfigManager.Init(...)`。

3. **生成的配置类字段缺失或类型不对**
   检查 Excel 文件的字段名称、字段类型和主键标记是否正确。

4. **修改导出脚本后，生成配置表资产没有更新**
   为了加快生成速度，工具会检查 Excel 的 MD5。如果只修改脚本而 Excel 没有变化，工具会跳过这份 Excel。
   可以使用 **Config Setting Window** 中的 **Delete Config Assets**，或者手动删除已生成的配置文件后重新导出。

## ❓ 常见问题

1. **配置加载失败**
   检查 Excel 路径、资源输出路径，以及持久化目录中的 `Data.bytes` / `Index.bytes` 是否存在。

2. **首次启动读取不到配置**
   检查 `ConfigManager.Init()` 是否已执行，以及 Addressables 中是否正确提供了 `configasset` 标签下的配置资源。

3. **本地化字符串未正确导出**
   确保字段类型为 `LocString` / `LocAsset` 或对应的 `LocalizationStringRef` / `LocalizationAssetRef` 映射类型。

4. **生成的配置类字段缺失或类型不对**
   检查 Excel 文件的字段名称、字段类型和重复字段定义是否正确。

5. **修改导出脚本后，生成配置表资产没有更新**
   为了加快生成速度，工具会检查 Excel 的 MD5。如果只修改脚本而 Excel 未变化，当前表可能会跳过导出。
   可以使用 **Config Setting Window** 的 **Delete Config Assets** 按钮，或者手动删除旧的 `.bytes` 文件后重新导出。
