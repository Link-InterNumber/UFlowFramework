# 数据持久化

## 😀 概述

UFlow 提供一套简洁易用的数据持久化工具，基于 `PersistenceDataProcessor` 架构设计，支持多种数据格式的存储与读取。

目前支持的存储类型 (`PlayerDataType`)：
- **Json**: 文本格式
- **Binary**: 二进制格式（支持 AES 加密）
- **PlayerPrefs**: Unity 原生键值对存储
- **Capture**: 屏幕截图

在原有存读 API 不变的前提下，数据持久化现在新增了版本控制和数据迁移能力：
- 为 `IPersistenceData` 类型声明当前版本号
- 默认使用当前存储类型的标准序列化方案
- `Binary` 存档默认使用 `SerializeUtils` 的 `Safe` 模式
- 在读取旧数据后按版本顺序逐步迁移
- 迁移成功后自动按当前版本重新保存

## 🛠️ 使用方法

### 1.✨ 定义要存储的数据

建议使用 `IPersistenceData` 接口标记持久化数据类：

```csharp
[Serializable]
public class PlayerSave : IPersistenceData
{
    public long Id;
    public string Name;
}
```

如果你暂时不使用版本控制标签，保存和读取仍然可以正常工作，当前版本默认按 `1` 处理

这意味着可以渐进式接入版本控制，而不需要一次性改造全部存档类型。

### 2.💾 数据保存

使用 `PlayerDataUtils` 的泛型接口进行保存。你需要指定 `PlayerDataType` 来决定保存的格式。

**同步保存**

```csharp
public void SaveExample(PlayerSave data)
{
    // 1. 保存为 Json 格式
    // 默认路径: {PersistentDataPath}/Json/PlayerSave.json
    PlayerDataUtils.Save(data, PlayerDataType.Json);

    // 2. 保存为 Binary 格式并加密
    // 默认路径: {PersistentDataPath}/Binary/PlayerSave.bytes
    PlayerDataUtils.Save(data, PlayerDataType.Binary, encrypt: true);

    // 3. 指定自定义文件名
    // 保存路径: {PersistentDataPath}/Binary/MySaveFile.bytes
    PlayerDataUtils.Save("MySaveFile", data, PlayerDataType.Binary, encrypt: true);
}
```

**异步保存**

`PlayerDataUtils` 提供三种异步保存方式：基于回调、协程和 `async/await`。

```csharp
public void SaveAsyncExample(PlayerSave data)
{
    PlayerDataUtils.SaveAsync(data, PlayerDataType.Binary, success =>
    {
        if (success)
        {
            Debug.Log("保存成功");
        }
    }, encrypt: true);
}

public IEnumerator SaveAsyncCoroutineExample(PlayerSave data)
{
    var yieldInstruction = PlayerDataUtils.SaveAsYieldInstruction(data, PlayerDataType.Binary, encrypt: true);
    yield return yieldInstruction;
    bool result = yieldInstruction.Result;
    if (result)
    {
        Debug.Log("保存成功");
    }
}

public async void SaveAsyncAwaitExample(PlayerSave data)
{
    bool result = await PlayerDataUtils.SaveAsTask(data, PlayerDataType.Binary, encrypt: true);
    if (result)
    {
        Debug.Log("保存成功");
    }
}
```

版本号封装由处理器内部自动完成，业务层不需要修改现有保存 API，也不需要手动写版本字段。

可以通过 `HasSave` 方法检查数据是否存在：

```csharp
public void HasSaveExample()
{
    bool exists = PlayerDataUtils.HasSave<PlayerSave>(PlayerDataType.Json);
    Debug.Log("数据是否存在: " + exists);

    bool existsCustom = PlayerDataUtils.HasSave<PlayerSave>("MySaveFile", PlayerDataType.Binary);
    Debug.Log("自定义文件数据是否存在: " + existsCustom);
}
```

### 3.📂 数据读取

**同步读取**

```csharp
public void ReadExample()
{
    PlayerSave save1 = PlayerDataUtils.Read<PlayerSave>(PlayerDataType.Json);
    PlayerSave save2 = PlayerDataUtils.Read<PlayerSave>("MySaveFile", PlayerDataType.Binary, decrypt: true);
}
```

**异步读取**

和保存类似，提供回调、协程和 `async/await` 三种方式。

```csharp
public void ReadAsyncExample()
{
    PlayerDataUtils.ReadAsync<PlayerSave>(PlayerDataType.Json, data =>
    {
        Debug.Log("读取到数据: " + data.Name);
    });
}

public IEnumerator ReadAsyncCoroutineExample()
{
    var yieldInstruction = PlayerDataUtils.ReadAsYieldInstruction<PlayerSave>(PlayerDataType.Json);
    yield return yieldInstruction;
    PlayerSave data = yieldInstruction.Result;
    Debug.Log("读取到数据: " + data.Name);
}

public async void ReadAsyncAwaitExample()
{
    PlayerSave data = await PlayerDataUtils.ReadAsTask<PlayerSave>(PlayerDataType.Json);
    Debug.Log("读取到数据: " + data.Name);
}
```

当读取到旧版本数据时，处理流程如下：
- 先从存档内容中解析版本号
- 先按当前类型直接反序列化出实例
- 如果版本落后，再按迁移方法逐版本补齐初始化和数据修正
- 如果某一步迁移方法返回了当前类型实例，会以返回值继续后续迁移；否则继续使用当前实例
- 升级成功后自动按当前版本重新保存一次

因此业务层通常仍然只需要调用现有 `Read<T>` / `ReadAsync<T>` 接口。

### 4.🆕 版本控制与数据迁移

#### 1. 声明当前版本

使用 `PersistenceDataVersionAttribute` 为类型声明当前版本：

```csharp
[Serializable]
[PersistenceDataVersion(2)]
public class PlayerSave : IPersistenceData
{
    public long Id;
    public string Name;
    public int Level;
}
```

如果不写这个标签，当前版本默认视为 `1`。

#### 2. 默认序列化 / 反序列化策略

这套方案不再为版本声明独立的序列化 / 反序列化方法标签，处理器会始终使用当前存储类型的默认读写方案：

- `Json` / `PlayerPrefs`：使用 `SerializeUtils.SerializeToJson` / `SerializeUtils.DeserializeFromJson`
- `Binary`：使用 `SerializeUtils.SerializeToBinary` / `SerializeUtils.DeserializeFromBinary` 的 `Safe` 模式

`SerializeUtils.Safe` 适合持久化版本演进场景：
- 旧数据中保留的字段会按字段标识读取
- 已删除字段会被跳过
- 新增字段会保留类型默认值

但它仍然不能自动解决字段改名、字段语义改变、同名字段类型变化等问题，这些情况需要依赖迁移方法补齐。

#### 3. 声明逐版本迁移方法

使用 `PersistenceMigrationMethodAttribute` 声明从旧版本到新版本的迁移步骤。

- 方法应定义在数据类自身上
- 方法不接收参数
- 方法会在旧版本数据第一次反序列化为当前实例后执行
- 返回值可以是 `void`，也可以是当前数据类型本身
- 推荐直接修改当前实例；如果需要替换实例，也可以返回新的当前类型实例
- 系统会按版本顺序逐步执行迁移

```csharp
[PersistenceMigrationMethod(1, 2)]
private void UpgradeV1ToV2()
{
    Level = Mathf.Max(1, Level);
}
```

```csharp
[PersistenceMigrationMethod(2, 3)]
private PlayerSave UpgradeV2ToV3()
{
    return new PlayerSave
    {
        Id = Id,
        Name = string.IsNullOrEmpty(Name) ? "Player" : Name,
        Level = Mathf.Max(Level, 1)
    };
}
```

#### 5. 完整示例

```csharp
[Serializable]
[PersistenceDataVersion(2)]
public class PlayerSave : IPersistenceData
{
    public long Id;
    public string Name;
    public int Level;

    [PersistenceMigrationMethod(1, 2)]
    private void UpgradeV1ToV2()
    {
        Level = Mathf.Max(1, Level);
    }
}
```

读取旧版 Json 存档时：
- 存档中的版本号会被读出
- 系统会先把内容直接反序列化为当前 `PlayerSave`
- `UpgradeV1ToV2` 会在这个实例上执行，用来补齐当前版本需要的初始化
- 处理器随后会把升级后的数据重新保存为版本 `2`

#### 6. 编辑器中的迁移配置检查

编辑器工具窗口会根据当前数据类版本检查迁移链是否完整。

检查规则如下：
- 只有实现了 `IPersistenceData` 的可实例化类型会参与检查
- 如果当前版本大于 `1`，系统会检查从 `1` 到 `当前版本 - 1` 的每个起始版本，是否至少存在一个 `PersistenceMigrationMethodAttribute`
- 如果缺少某个起始版本的迁移方法，工具窗口会给出警告

例如：
- 当前版本是 `3`
- 只声明了 `[PersistenceMigrationMethod(2, 3)]`

那么编辑器会提示缺少起始版本 `1` 的迁移方法，因为从版本 `1` 升级到更高版本的链路并不完整。

### 5.⚙️ PlayerPrefs

可以使用 PlayerPrefs 存储简单的数据（`int`、`float`、`string`）。

```csharp
PlayerDataUtils.SavePlayerPrefs("IntKeyName", 114514);
PlayerDataUtils.SavePlayerPrefs("FloatKeyName", 3.14159f);
PlayerDataUtils.SavePlayerPrefs("StringKeyName", "Hello UFlow!");

var intValue = PlayerDataUtils.ReadPlayerInt("IntKeyName", 0);
var floatValue = PlayerDataUtils.ReadPlayerFloat("FloatKeyName", 0f);
var stringValue = PlayerDataUtils.ReadPlayerString("StringKeyName", "DefaultString");
```

对于实现了 `IPersistenceData` 的复杂对象，`PlayerPrefsProcessor` 现在同样支持版本封装和自动迁移。

### 6.📸 保存屏幕截图

截图功能独立于通用数据接口。

```csharp
public IEnumerator CaptureExample()
{
    yield return PlayerDataUtils.TakeCapture("Screenshot");
    yield return PlayerDataUtils.TakeCapture("CameraShot", new Rect(0,0,1920,1080), Camera.main);
}

public void LoadCaptureExample()
{
    Sprite sp = PlayerDataUtils.LoadCapture("Screenshot");

    PlayerDataUtils.LoadCaptureAsync("Screenshot", sprite =>
    {
        // 使用 sprite
    });

    PlayerDataUtils.DeleteCapture("Screenshot");
}

public IEnumerator LoadCaptureAsyncExample()
{
    var yieldInstruction = PlayerDataUtils.LoadCaptureAsYieldInstruction("Screenshot");
    yield return yieldInstruction;
    Sprite sp = yieldInstruction.Result;
}

public async void LoadCaptureAsyncAwaitExample()
{
    Sprite sp = await PlayerDataUtils.LoadCaptureAsTask("Screenshot");
}
```

### 7. 清除保存的数据

可以使用 `Clear` 方法删除指定的数据文件：

```csharp
public void ClearSaveExample()
{
    PlayerDataUtils.Clear<PlayerSave>(PlayerDataType.Json);
    PlayerDataUtils.Clear<PlayerSave>("MySaveFile", PlayerDataType.Binary);
    PlayerDataUtils.DeleteCapture("Screenshot");
    PlayerDataUtils.ClearAll(PlayerDataType.PlayerPrefs);
    PlayerDataUtils.ClearCapture();
}
```

## 🚀 如何自定义数据保存方式

本系统采用反射机制自动注册处理器，扩展新的存储格式非常简单。

### 1. 扩展枚举

在 `PlayerDataType` 枚举中添加新的类型：

```csharp
public enum PlayerDataType
{
    // ... 原有类型
    Xml = 10
}
```

### 2. 创建处理器

创建一个继承自 `PersistenceDataProcessor` 的类，并添加 `[DataProcessor]` 特性。

```csharp
using PowerCellStudio;
using System;

[DataProcessor(PlayerDataType.Xml)]
public class XmlDataProcessor : PersistenceDataProcessor
{
    public override string directoryName => "Xml";
    public override string extension => "xml";

    public override bool Save<T>(string saveKey, T data, bool encrypt)
    {
        return true;
    }

    public override T Read<T>(string saveKey, bool decrypt)
    {
        return default;
    }

    public override void SaveAsync<T>(string saveKey, T data, Action<bool> onComplete, bool encrypt)
    {
    }

    public override void ReadAsync<T>(string saveKey, Action<T> onComplete, bool decrypt)
    {
    }
}
```

### 3. 自动生效

无需手动注册，`PlayerDataUtils.Init()` 会自动扫描带有 `[DataProcessor]` 特性的 `PersistenceDataProcessor` 类并完成映射。之后即可直接调用：

```csharp
PlayerDataUtils.Save(data, PlayerDataType.Xml);
```

如果你的自定义处理器也希望支持版本控制和迁移，建议沿用以下调用链：
- 保存时调用 `SerializeStringPayload` / `SerializeBinaryPayload`
- 将版本信息与实际载荷一起封装
- 读取时调用 `DeserializeStringPayload` / `DeserializeBinaryPayload`
- 反序列化完成后调用 `TryUpgradeData`

## 数据转换

在某些情况下，可能需要将数据从一种存储格式转换为另一种格式；或者历史项目已经存在旧存档结构，需要在版本控制迁移之外做一次格式级转换。UFlow 仍然提供 `DataTranslator` 机制来处理这类问题。

### 1. 什么时候使用 DataTranslator

推荐这样区分两套机制：
- **同一种存储类型内的版本演进**：优先使用前面的版本控制与迁移机制
- **不同存储格式之间的整体转换**：使用 `DataTranslator`

例如：
- `Json v1` 升级到 `Json v2`：优先用 `PersistenceDataVersion` + 迁移方法
- 旧项目整体从 `Json` 存档切到 `Binary` 存档：适合用 `DataTranslator`

### 2. 使用 `DataTranslator`

UFlow 提供了 `IDataTranslator` 接口和 `DataTranslatorBase` 类，用于实现数据格式转换。你可以创建一个继承自 `DataTranslatorBase` 的类，并实现所需的转换逻辑。

```csharp
public class JsonToBinaryTranslator : DataTranslatorBase
{
    protected override string saveKey => GetType().Name;

    public override int version => 0;

    private BinaryDataProcessor _binaryDataProcessor = new BinaryDataProcessor();
    protected override PersistenceDataProcessor targetProcessor => _binaryDataProcessor;

    protected override object ReadOldData(string filePath, bool decrypt)
    {
        var jsonEn = File.ReadAllText(filePath);
        object result = null;
        try
        {
            if (decrypt)
            {
                var json = EncryptUtils.AESDecrypt(jsonEn, ConstSetting.FileEncryptionKey);
                result = JsonConvert.DeserializeObject(json);
            }
            else
            {
                result = JsonConvert.DeserializeObject(jsonEn);
            }
        }
        catch (Exception e)
        {
            LinkLog.LogError($"Failed to read json data: {e.Message}");
        }

        return result;
    }
}
```

### 3. 自动生效

将转换器类添加到项目中后，UFlow 会在初始化时自动检测并执行数据转换。这个过程是自动的，无需手动调用。

## 工具窗口

UFlow 提供一个管理和调试数据持久化的编辑器工具窗口。通过该工具，开发者可以方便地查看、读取、删除和清除持久化数据。

在 Unity 编辑器中，你可以通过以下步骤打开工具窗口：
1. 点击顶部菜单栏中的 `Tool` -> `Editor Setting Window`
2. 选择 `Data Persistence Data` 选项卡

工具窗口支持以下操作：

### 清除数据

- **Clear Player Prefs**: 清除所有存储在 `PlayerPrefs` 中的数据
- **Clear Json**: 清除所有存储为 `Json` 格式的数据
- **Clear Binary**: 清除所有存储为 `Binary` 格式的数据
- **Delete All Capture**: 删除所有截图文件
- **Delete All**: 清除所有持久化数据，包括 `Json`、`Binary`、`PlayerPrefs` 和截图

### 读取数据

1. **搜索数据**
   - 在 `Data Save Key` 文本框中输入要读取的保存键
   - 如果数据是加密存储的，勾选 `Decrypt Data`
   - 如果未指定保存键，默认键为数据类的 `{命名空间名称}_{类型名称}`

2. **读取操作**
   - 点击 `Read` 按钮，工具会根据保存键读取所有类型的数据
   - 读取成功后，数据会以格式化字符串显示在窗口中
   - 每个数据项后有一个 `Delete` 按钮，可删除对应数据

3. **加载截图**
   - 在 `Data Save Key` 文本框中输入要加载的截图保存键
   - 点击 `Load Capture` 按钮，即可加载并显示截图

### 迁移配置警告

如果某个持久化数据类型声明了更高版本号，但没有为必需的起始版本补齐迁移方法，工具窗口顶部会显示警告。

这个检查只验证迁移链覆盖情况，不检查迁移逻辑本身是否正确。

## ✅ 场景推荐

- 继续沿用旧 `PlayerDataUtils` API，同时给存档增加版本控制
- 为 Json / Binary / PlayerPrefs 复杂对象建立可维护的版本升级链
- 读取旧存档后自动迁移并回写，减少运行时兼容分支
- 在必要时使用 `DataTranslator` 完成跨存储格式的整体迁移
