# 运行时数据 RuntimeData 系统使用说明

## 📖 简介

`RuntimeDataManager` 是 UFlowFramework 中用于管理游戏运行期数据的模块，适合保存背包、临时角色状态、关卡内统计值等只在运行期有效的数据。

当前运行时数据系统基于 `IRuntimeData` 数据容器和 `IRuntimeDataHandler<T>` 数据处理器实现。数据容器负责保存数据，数据处理器负责封装某种数据的初始化、添加、删除、查询和监听逻辑。

系统会在游戏开始时自动查找可实例化的 `IRuntimeDataHandler<T>`，创建处理器并调用 `InitData()`，因此普通业务代码通常只需要通过 `RuntimeDataManager.instance` 或对应工具类访问数据即可。

## ⚙️ 功能

1. **运行时数据存储**
   - 支持单值容器 `RuntimeData<T>`。
   - 支持字典容器 `RuntimeDataDic<K, T>`。
   - 支持普通存储和 `doNotClear` 存储。

2. **统一数据访问入口**
   - 通过 `GetData<T>(int key)` 获取数据。
   - 通过 `AddData<T>(T data)` 添加或修改数据。
   - 通过 `RemoveData<T>(T data)` 删除数据。
   - 通过 `AddChangeListener<T>()` / `RemoveChangeListener<T>()` 监听数据变化。

3. **数据处理器扩展**
   - 支持通过 `IRuntimeDataHandler<T>` 为不同数据类型封装业务逻辑。
   - 游戏开始时会自动反射创建可实例化的处理器。
   - 已内置背包数据处理器 `BagDataHandler` 作为示例。

4. **数据变化监听**
   - 数据被 `ReplaceData()` 替换时会触发 `OnRuntimeDataChange<T>`。
   - 回调参数包含旧数据和新数据。

5. **运行期生命周期管理**
   - `onStartGame` 时初始化处理器和运行时数据。
   - `onResetGame` 时清空普通运行时存储。
   - `doNotClear` 存储不会被游戏重置清空。

## 📂 文件结构

- `RuntimeDataManager.cs`  
  运行时数据系统主入口，定义数据容器、存储区、生命周期和通用数据访问 API。

- `IRuntimeData.cs`  
  所有运行时数据容器需要实现的基础接口，提供 `dataType` 用于标识容器保存的数据类型。

- `IRuntimeDataHandler.cs`  
  定义运行时数据处理器接口，以及通用基类 `RuntimeDataHandlerBase<T, KT>`。

- `BagDataHandler.cs`  
  背包运行时数据示例，定义 `RItem` 数据结构和 `BagDataHandler` 处理器。

- `BagUtils.cs`  
  背包数据的静态访问工具，封装添加、移除、数量查询和监听接口。

## 🧩 核心概念

### 1. 数据变化委托

```csharp
public delegate void OnRuntimeDataChange<T>(T oldData, T newData);
```

当数据被替换时，监听器会收到旧数据和新数据：

- `oldData`：替换前的数据。
- `newData`：替换后的数据。
- 如果字典容器中原本不存在该 key，`oldData` 为 `default(T)`。
- `RuntimeDataDic<K, T>.Remove(K key)` 只删除数据，不会触发该委托。

### 2. 单值容器 `RuntimeData<T>`

`RuntimeData<T>` 用于保存一个 `T` 类型数据。

```csharp
public class RuntimeData<T> : IRuntimeData
    where T : struct
```

| 方法 / 属性 | 说明 |
|---|---|
| `RuntimeData(T data)` | 使用初始数据创建容器。 |
| `dataType` | 返回容器中保存的数据类型。 |
| `GetData()` | 获取内部数据的克隆值。 |
| `ReplaceData(T newData)` | 替换内部数据，并触发变化监听。 |
| `AddListener(...)` | 添加变化监听。 |
| `RemoveListener(...)` | 移除变化监听。 |

### 3. 字典容器 `RuntimeDataDic<K, T>`

`RuntimeDataDic<K, T>` 用于按 key 保存多个 `T` 类型数据。

```csharp
public class RuntimeDataDic<K, T> : IRuntimeData, IEnumerable<T>
    where T : struct
```

| 方法 / 属性 | 说明 |
|---|---|
| `RuntimeDataDic()` | 创建空字典容器。 |
| `RuntimeDataDic(IEnumerable<KeyValuePair<K, T>> initDatas)` | 使用初始键值对创建容器。 |
| `dataType` | 返回容器中 value 的类型。 |
| `GetData(K key)` | 根据 key 获取数据克隆值，不存在时返回 `default(T)`。 |
| `ReplaceData(K key, T newData)` | 新增或替换指定 key 的数据，并触发变化监听。 |
| `Remove(K key)` | 删除指定 key 的数据，不触发变化监听。 |
| `AddListener(...)` | 添加变化监听。 |
| `RemoveListener(...)` | 移除变化监听。 |
| `Clear()` | 清空字典。 |

### 4. 数据处理器 `IRuntimeDataHandler<T>`

`IRuntimeDataHandler<T>` 用于集中封装某种数据的业务规则。

```csharp
public interface IRuntimeDataHandler<T> : IRuntimeDataHandler
    where T : struct
{
    void AddData(T rData);
    void RemoveData(T rData);
    int GetKey(T rData);
    T GetData(int key);
    void AddListener(OnRuntimeDataChange<T> action);
    void RemoveListener(OnRuntimeDataChange<T> action);
    List<T> GetAllData();
}
```

适合在以下场景使用：

- 添加数据时不是简单覆盖，而是需要累加、扣减、合并或校验。
- 希望隐藏底层容器类型，只暴露统一访问方式。
- 希望某种数据在游戏开始时自动初始化。

## 🛠️ 使用方法

### 🚀 1. 初始化流程

`RuntimeDataManager` 实现了 `IEventModule` 和 `IOnGameStartModule`。正常情况下模块系统会自动完成初始化。

初始化流程如下：

1. `OnInit()` 初始化 `_storage` 和 `_doNotClearStorage`。
2. `RegisterEvent()` 注册 `onStartGame` 和 `onResetGame` 事件。
3. `onStartGame` 触发后：
   - 创建 `_handlers`；
   - 反射查找所有可实例化的 `IRuntimeDataHandler<T>`；
   - 创建 handler 实例；
   - 调用每个 handler 的 `InitData()`；
   - 调用 partial 方法 `InitRuntimeData()`。
4. `onResetGame` 触发后清空普通 `_storage`。

### 🔧 2. 使用 `InitRuntimeData` 扩展初始化

`RuntimeDataManager` 提供了一个 partial 扩展点：

```csharp
partial void InitRuntimeData();
```

如果需要初始化不依赖 `IRuntimeDataHandler<T>` 的数据，可以新建一个 `RuntimeDataManager_InitRuntimeData.cs`：

```csharp
namespace PowerCellStudio
{
    public sealed partial class RuntimeDataManager
    {
        partial void InitRuntimeData()
        {
            var score = new RuntimeData<PlayerScore>(new PlayerScore { value = 0 });
            AddRuntimeStorage(score);
        }
    }

    public struct PlayerScore
    {
        public int value;
    }
}
```

### 📦 3. 添加运行时数据容器

可以直接添加一个运行时数据容器：

```csharp
var score = new RuntimeDataManager.RuntimeData<PlayerScore>(new PlayerScore { value = 100 });
RuntimeDataManager.instance.AddRuntimeStorage(score);
```

如果希望数据在游戏重置时不被清空，可以传入 `doNotClear`：

```csharp
RuntimeDataManager.instance.AddRuntimeStorage(score, true);
```

> `doNotClear` 只表示不会被 `onResetGame` 清空，它仍然是内存数据，不等同于写入磁盘的存档。

### 🔍 4. 获取运行时数据容器

```csharp
var scoreStorage = RuntimeDataManager.instance.GetRuntimeStorage<RuntimeDataManager.RuntimeData<PlayerScore>>();
var score = scoreStorage.GetData();
```

### 📊 5. 使用通用数据接口

如果数据类型存在对应的 `IRuntimeDataHandler<T>`，推荐使用通用接口访问数据：

```csharp
// 添加或修改数据
RuntimeDataManager.instance.AddData(new RItem { id = 1, num = 10 });

// 获取数据
RItem item = RuntimeDataManager.instance.GetData<RItem>(1);

// 删除数据
RuntimeDataManager.instance.RemoveData(new RItem { id = 1, num = 5 });

// 监听变化
RuntimeDataManager.instance.AddChangeListener<RItem>((oldItem, newItem) =>
{
    ModuleLogger.Log<RuntimeDataManager>($"item = {newItem.id}, num = {newItem.num}");
});
```

`GetData<T>(int key)`、`AddData<T>()`、`RemoveData<T>()` 会优先交给对应的 `IRuntimeDataHandler<T>` 处理。

### 🎒 6. 使用背包工具 `BagUtils`

当前项目内置了背包运行时数据示例。

`RItem` 定义如下：

```csharp
[Serializable]
public struct RItem
{
    public int id;
    public int num;

    public RItem Clone()
    {
        return new RItem
        {
            id = this.id,
            num = this.num
        };
    }
}
```

`BagDataHandler` 会在游戏开始时自动初始化背包容器。业务代码可以直接使用 `BagUtils`。

#### 添加道具

```csharp
BagUtils.AddItem(new RItem { id = 1, num = 10 });
BagUtils.AddItem(2, 5);
```

也可以一次添加多个：

```csharp
BagUtils.AddItem(
    new RItem { id = 1, num = 10 },
    new RItem { id = 2, num = 5 },
    new RItem { id = 3, num = 1 }
);
```

#### 移除道具

```csharp
BagUtils.RemoveItem(new RItem { id = 1, num = 3 });
BagUtils.RemoveItem(2, 1);
```

`BagDataHandler` 会按 `id` 扣减数量，最低扣到 `0`；数量为 `0` 时会从字典中移除该道具。

#### 获取道具数量

```csharp
int itemNum = BagUtils.GetItemNum(1);
```

如果背包中没有该 id，底层会返回 `default(RItem)`，因此数量为 `0`。

#### 判断道具是否足够

```csharp
bool enough = BagUtils.IsItemEnough(1, 10);

bool allEnough = BagUtils.IsItemEnough(
    new RItem { id = 1, num = 10 },
    new RItem { id = 2, num = 3 }
);
```

#### 监听背包变化

```csharp
private void OnEnable()
{
    BagUtils.AddBagListener(OnBagItemChanged);
}

private void OnDisable()
{
    BagUtils.RemoveBagListener(OnBagItemChanged);
}

private void OnBagItemChanged(RItem oldItem, RItem newItem)
{
    ModuleLogger.Log<BagUtils>($"item id = {newItem.id}, old = {oldItem.num}, new = {newItem.num}");
}
```

### 🔧 7. 扩展自定义运行时数据

自定义运行时数据一般需要：

1. 定义一个实现 `struct`。
2. 定义一个继承 `IRuntimeDataHandler<T>` 的处理器。
3. 在 `InitData()` 中创建并注册对应容器。
4. 在 `AddData()`、`RemoveData()`、`GetData()` 中实现业务规则。

下面以货币数据为例：

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

namespace PowerCellStudio
{
    [Serializable]
    public struct RCurrency 
    {
        public int id;
        public int amount;
    }

    public sealed class CurrencyDataHandler : IRuntimeDataHandler<RCurrency>
    {
        private sealed class CurrencyData : RuntimeDataManager.RuntimeDataDic<int, RCurrency> { }

        public void InitData()
        {
            if (RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>() != null) return;
            RuntimeDataManager.instance.AddRuntimeStorage(new CurrencyData());
        }

        public void AddData(RCurrency data)
        {
            var storage = RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>();
            if (storage == null) return;

            var current = storage.GetData(data.id);
            data.amount += current.amount;
            storage.ReplaceData(data.id, data);
        }

        public void RemoveData(RCurrency data)
        {
            var storage = RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>();
            if (storage == null) return;

            var current = storage.GetData(data.id);
            current.amount = Math.Max(0, current.amount - data.amount);
            storage.ReplaceData(data.id, current);
        }

        public int GetKey(RCurrency data)
        {
            return data.id;
        }

        public RCurrency GetData(int key)
        {
            var storage = RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>();
            return storage == null ? default : storage.GetData(key);
        }

        public void AddListener(OnRuntimeDataChange<RCurrency> action)
        {
            RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>()?.AddListener(action);
        }

        public void RemoveListener(OnRuntimeDataChange<RCurrency> action)
        {
            RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>()?.RemoveListener(action);
        }

        public List<RCurrency> GetAllData()
        {
            var storage = RuntimeDataManager.instance.GetRuntimeStorage<CurrencyData>();
            return storage?.ToList() ?? new List<RCurrency>();
        }
    }
}
```

接入后即可通过通用 API 使用：

```csharp
RuntimeDataManager.instance.AddData(new RCurrency { id = 1001, amount = 50 });

var gold = RuntimeDataManager.instance.GetData<RCurrency>(1001);

RuntimeDataManager.instance.AddChangeListener<RCurrency>((oldData, newData) =>
{
    ModuleLogger.Log<RuntimeDataManager>($"currency = {newData.id}, amount = {newData.amount}");
});
```

## ⚠️ 注意事项

1. `RuntimeData<T>` 与 `RuntimeDataDic<K, T>` 要求 `T` 是 `struct`。
2. `IRuntimeDataHandler<T>` 的数据类型也建议使用 `struct`。
3. `RItem` 是 `struct`，不能用 `null` 判断是否存在；查询不到时通常返回 `default(T)`。
4. `RuntimeDataDic<K, T>.Remove(K key)` 不会触发数据变化监听，只有 `ReplaceData()` 会触发监听。
5. 使用 `AddChangeListener()` 或 `BagUtils.AddBagListener()` 后，应在对象销毁或禁用时调用对应的移除方法。
6. 普通 `_storage` 会在 `onResetGame` 时清空，`_doNotClearStorage` 不会被 `ClearRuntimeStorage()` 清空。
7. `doNotClear` 不是持久化存档，只是不会随游戏重置清除的内存数据。
8. 当前实现没有加锁，建议只在 Unity 主线程访问。
9. 没有 handler 时，系统会尝试按元素类型查找容器；字典容器默认使用 `data.GetHashCode()` 作为 key 进行添加和删除，只适合简单场景。
10. 复杂业务建议显式实现 `IRuntimeDataHandler<T>`。

## ❓ 常见问题

1. **获取不到运行时数据**  
   检查对应 handler 是否可实例化，`onStartGame` 是否已经触发，以及 `InitData()` 是否成功创建并注册容器。

2. **游戏重置后数据丢失**  
   普通 `_storage` 会在 `onResetGame` 时清空。如果希望重置时保留数据，需要通过 `AddRuntimeStorage(data, true)` 注册到 `doNotClear` 存储。

3. **背包数量不符合预期**  
   `BagDataHandler.AddData()` 会累加同 id 道具数量，`RemoveData()` 会扣减数量并限制最低为 `0`。检查传入的 `id` 和 `num` 是否正确。

4. **直接调用 `AddData<T>()` 后没有效果**  
   检查是否已经注册对应容器或 handler。没有 handler 时，系统只会尝试查找已经存在的容器，不会自动创建新容器。
